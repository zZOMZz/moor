# 输入区模型、权限与用量面板

状态：已实现。本文记录产品行为、协议与验证范围。审批入口保持独立，包含 Read-only、Agent、Auto review 和 Full access 四种明确权限模式。

当前界面见[工作区界面](workspace-ui.md)，能力读取与执行校验见[运行与恢复](runtime.md)。模型探测的触发时机与交互以本文和当前实现为准。

## 已确认的产品行为

### 合并模型与推理强度

输入框底部工具栏使用一个入口，展示具体模型与推理强度，例如 `GPT-6 Astra · High`；权限入口紧随其后，发送位于最右侧。点击模型入口后打开同一个面板，包含两行：

```text
模型       GPT-6 Astra  ›  模型列表
推理强度   High         ›  当前模型支持的档位
```

- 桌面端参考 Lody/Codex 的两级菜单，当前选择显示勾选标记；选择后更新入口摘要。
- 窄屏在同一个浮层内切换列表并提供返回，避免侧向子菜单溢出。
- 模型列表只包含具体型号，移除“沿用会话模型”以及作为虚拟型号的默认选项。
- 已确认当前模型时显示具体名称；读取中、未选择或尚未确认时显示相应状态，不能把临时探测的新会话默认模型显示成已有会话的当前模型。
- 切换模型优先保留当前推理强度；新模型不支持该档位时，采用它实际声明的默认强度并更新显示。没有可验证默认值时提示选择，不猜测或硬编码档位。
- 审批保持独立入口。合并面板先包含模型与推理强度两项，角色、计划与快速模式不属于本次已确认范围。

### 收敛能力探测时机

- 应用启动后等待执行主机与工作区就绪，再完成一次初始化探测；“启动”与“就绪”是同一次探测的前置条件，不各触发一次。
- 同一执行范围的能力随后复用缓存。进入会话、展开模型面板、切换模型或推理强度，都不再次发起目录探测。
- 手动刷新能力放在设置的 Agent 配置区域；主界面移除常驻刷新按钮。刷新成功后，所有相关界面读取同一份新缓存。
- 初始化与手动刷新使用同一条能力读取链路。并发就绪信号合并为同一请求，迟到结果不能覆盖已经切换的执行目标或用户选择。
- 探测失败显示明确状态，由用户手动重试；不能通过每次打开面板或进入会话隐式反复重试。
- 探测只读取能力，不发送用户指令、不批准权限请求，也不恢复或重发离线草稿。
- 设置显示当前能力目录的最近成功时间、项目作用域和最近一次安全错误；这些状态来自执行主机确认，不从菜单是否能打开反推。

### 分开保存能力与会话选择

能力缓存回答“有哪些模型、各自支持什么档位、默认值是什么”；会话与草稿状态回答“这个会话选择了什么模型和档位”。两者独立更新。

- 一次初始化探测收齐各模型的推理强度及可验证默认值。Codex 锁定补丁在初始目录中提供所有模型的 effort；其他 ACP Agent 的缺失选项在同一次初始化探测中收集，不在用户切换模型时补查。
- 缓存按账号、执行电脑、工作区、Agent 配置和项目的实际执行范围隔离，记录来源、程序与目录指纹、读取时间。同一范围内的会话共享能力目录；会话编号不能成为重复探测的理由。
- 工作目录或有效 Agent 配置存在差异时，先核对是否属于不同能力范围，不能把另一项目或另一电脑的目录冒充为当前能力。
- 已保存缓存可用于展示，但需区分初始化中、已确认、过期和失败；过期数据不能伪装为本次初始化成功。
- 初始化和手动刷新不能覆盖用户已选择的模型、推理强度、草稿或待确认操作。旧型号从目录消失时保留原选择并提示不可用，不自动换模型发送。
- 发送时仍使用实际打开或恢复的 Agent 校验所选模型与档位。这是执行校验，不额外启动一次模型目录探测。

### 持久保存新会话的运行默认值

| 模式        | 沙箱               | 审批策略     | 审批者         |
| ----------- | ------------------ | ------------ | -------------- |
| Read-only   | `readOnly`         | `on-request` | 用户           |
| Agent       | `workspaceWrite`   | `on-request` | 用户           |
| Auto review | `workspaceWrite`   | `on-request` | Codex 自动审查 |
| Full access | `dangerFullAccess` | `never`      | 不请求审批     |

首次使用、尚未保存偏好时，新会话默认采用 **Agent**：允许工作区内操作，需要审批时交给用户，对应 `workspaceWrite`、`on-request` 和用户审批者。

用户手动切换审批模式后，将该选择保存到 **Moor 的持久化配置**，作为后续新会话的默认值。例如，将当前会话切换为 **Auto review** 后，随后创建的新会话都默认采用 Auto review；关闭再打开应用或重启执行主机后仍保留这一选择，不能仅存于组件或进程内存。Auto review 表示需要审批时由 Codex 自动审查，不等于完全访问或跳过审批。

模型与推理强度面板提供“设为新会话默认”。该操作把当前模型和强度按执行电脑上的不可变 Agent 配置版本保存；权限继续使用独立的审批默认配置。创建新会话时，主机把当时的模型、强度和权限冻结到会话元数据，之后修改默认值不会改变已有会话。

- 区分三个状态：配置中的新会话默认值、各会话自身的审批选择、已接受操作携带的审批参数快照。新会话初始化时读取保存的默认值，之后保留自己的选择。
- 只有用户主动更改审批模式才更新默认配置。打开或恢复已有会话、初始化选择器、刷新能力，都不能把该会话的模式反写为新的默认值。
- 当前会话的手动选择用于后续手动发送的操作；更新默认值不会批量修改其他已有会话，也不会改写正在执行或等待审批的操作。待审批请求仍按原有活动轮次和请求标识匹配，切换模式不构成批准。
- 保存结果需要以持久化成功为准。写入失败应显示明确状态，不能把内存中的选择当成已保存默认值，也不能由此自动发送、重发或批准操作。
- 模型默认值保存前必须由当前项目的已确认能力目录验证。目录尚未读取、模型已移除或强度不属于该模型时拒绝保存；不会用名称相近的模型或较低强度替代。
- 模型/强度默认值按 Agent 配置版本隔离，同一版本可跨项目复用；每个新会话仍在自己的项目能力目录下重新校验。失效默认值保留并显示不可用，必须由用户重新选择。
- 模型/强度默认记录使用独立 revision 比较写入。多个页面竞争修改时，迟到页面必须重新读取，不能覆盖较新的默认值。
- 偏好属于 Moor 配置，不通过修改 Codex 自身的全局配置实现。具体配置落点与同步方式沿用 Moor 的类型边界和授权范围，不将会话内状态充当全局默认配置。
- 持久化的模式必须有稳定的产品语义，并显式映射到实际沙箱、审批策略和审批者。当前锁定适配器中的 `agent` 实际使用自动审查，不能直接把该原始 ID 当成上述 Agent 默认值；适配器映射及已有数据迁移必须保持原权限语义。

### 上下文与账号额度面板

输入框「+」菜单提供「上下文与账号额度」入口，百分比始终表示当前会话的上下文已用比例。点击显示上下文已用 token、实际容量、账号额度窗口的剩余比例、重置时间和最近更新时间。已确认的上下文占用达到 85% 时，输入区显示简短提示；未知值不触发推测。模型与审批选择仍使用各自入口。

- 上下文复用 ACP `session/update` 中的 `usage_update`，按 Agent 上报的当前 `used` / `size` 快照显示；补齐会话创建与恢复阶段的接收，不累计历次 token 消耗，不通过消息长度猜测，也不为读取用量发送提示词或创建临时聊天。
- 额度按 Agent 实际登录账号读取，不能由上下文消耗推算。根据返回的额度池名称、窗口长度和模型关联展示，不硬编码五小时、每周窗口或臆造型号归属。剩余比例为 `100 - usedPercent`，展示限制在 0–100%；未知值显示暂无数据，不当成零。
- Codex 原生接口提供 `account/rateLimits/read` 与 `account/rateLimits/updated`。锁定 ACP 适配器暴露版本化的扩展查询 `_moor/account/rate_limits/read` 与通知 `_moor/account/rate_limits/updated`，在初始化 `_meta` 中声明支持；主机确认版本后调用，校验并投影为 Moor 自有类型，不能提供任意原生方法代理。
- 上下文按会话保存；额度按执行主机、Agent 配置与实际登录账号保存主机侧快照，同范围会话复用，账号切换立即失效。请求仍经过账号、设备、工作区、项目与会话的授权边界，额度不写入每个会话的共享正文。
- 主机与账号就绪后读取一次额度，随后优先使用推送。打开面板或应用回到前台时，若快照超过 60 秒则补查一次；短时间反复打开与切换会话复用缓存，并发请求合并。面板收起时不轮询。
- 重置倒计时在本地计算，不为刷新文字发请求；到达重置时间不能自行将额度置为 100%。支持相对时间和具体本地时间。失败保留旧值并标明状态、时间，未登录或 Agent 未提供套餐额度时显示明确的不可用说明。
- 设置中提供手动刷新能力与额度的入口，输入区不另增刷新按钮。查询与推送都不发送用户指令、不批准权限或恢复离线草稿。

协议依据：[ACP 上下文用量](https://agentclientprotocol.com/rfds/session-usage)、[ACP 扩展机制](https://agentclientprotocol.com/protocol/v1/extensibility)、[Codex App Server](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)。扩展方法为 Moor 自有接口，并非 ACP 标准方法。适配器变更锁定版本、保留许可与来源，并用合成原生接口验证。

### 与 Lody 能力探测的关系

Moor 采用与 Lody 相同的核心边界：能力属于 Agent 配置，由一个不发送 prompt 的临时 ACP 会话读取；并发刷新合并，成功结果缓存，配置或运行时变化后由设置显式刷新。Lody 的公开实现与说明见 [ACP capability refresh](https://github.com/lodyai/lody/blob/main/apps/cli/src/agent/acp-capabilities.ts) 和 [Agent Config 刷新说明](https://lody.ai/docs/cli/#agent-config-refresh-capabilities)。

Moor 保留两项本地优先差异：能力缓存继续绑定项目目录及程序指纹，避免工作目录相关 Agent 把另一项目的选项冒充为当前目录；错误只公开固定安全类别，不把本机路径、启动参数或 Agent 原始诊断同步到共享客户端。Codex 锁定适配器直接发布每个模型的 effort 元数据；旧 ACP 才在同一临时会话里逐模型补齐。

Lody 的 Agent Role 可以把 Agent、模型、强度、权限和说明组合成命名预设。Moor 此阶段只实现按 Agent 配置保存的新会话模型/强度默认值，不恢复已经移除的角色系统，也不让默认值携带指令、凭据或 MCP 选择。

## 设置与程序路径

不新增“重新检测 Codex 程序”按钮。首次配置通过现有发现流程识别本机 Codex，包括 `ChatGPT.app` 内的程序。后续路径变化通过现有设置面板重新配置；已有会话继续遵守固定 Agent 版本规则。能力刷新与程序路径重新登记是两个不同操作。

## 实现位置

- 主机能力缓存：`packages/host/src/sessions/workspace.ts`，目录按实际执行范围共享，单次主机生命周期内记录初始化成功或失败，并发刷新合并。
- ACP 能力投影：`packages/host/src/agents/capabilities.ts`、`packages/host/src/agents/acp/driver.ts`，在一次探测中收齐可用档位与默认值；补丁与上游许可、版本保持可追溯。
- 统一工作区控制器：`apps/web/src/features/workspace/workspace-controller.ts`，本机和远程共用就绪触发、缓存读取和手动刷新语义，草稿选项独立保存。
- 共享控件：`apps/web/src/components/ui.tsx`，合并模型与推理强度入口，移除虚拟模型选项和常驻刷新。
- 设置入口：`apps/desktop/src/settings/settings.html`、`apps/desktop/src/settings/settings.js`，接入明确的手动能力刷新；远程访问端的入口沿用目标执行主机的授权边界。
- 运行默认配置：`packages/host/src/agents/run-preferences.ts` 保留全局审批默认记录，并把模型/强度写入按用户与 Agent 配置隔离的 `run-defaults-v1` 记录。两者使用独立递增 revision；新会话冻结 `initialModeId`、`initialModelId` 和 `initialReasoningEffort`，恢复只读，不反写偏好。

## 验收要点

1. 启动与工作区就绪信号重复到达时，同一范围只执行一次初始化探测。
2. 连续切换会话、展开菜单、选择模型和强度，不增加能力查询次数。
3. 设置中一次手动刷新只触发一次查询，更新对应范围的缓存，保留会话选择和草稿。
4. 首次采集包含每个模型的可用档位；切换模型能直接显示正确强度并按已确认默认值处理不兼容档位。
5. 模型菜单只展示具体型号；默认模型与会话当前模型不混淆，未知状态不伪装成具体选择。
6. 本机与远程工作区、桌面与窄屏行为一致，支持键盘操作、焦点返回及可访问名称。
7. 失败、重连、程序或配置变化、迟到响应不会产生循环探测、跨范围缓存污染或自动发送。
8. 没有已保存审批偏好时，新会话采用 Agent，实际执行参数为工作区权限、按需请求审批、用户审批者。
9. 用户手动选择 Auto review 后，创建的新会话默认采用 Auto review；重新打开应用或重启执行主机后仍保持，其他可用模式遵守相同保存规则。
10. 恢复一个使用 Agent 的旧会话或刷新能力，不会覆盖已保存的 Auto review 默认值；修改默认值不会改变其他已有会话、活动轮次和待审批请求。
11. 配置保存失败时明确反馈，重新读取仍以实际保存值为准；旧模式 ID 的迁移不会将用户审批与自动审查互换。
12. 保存模型 B / Medium 为默认后，新会话冻结 B / Medium；已有会话不变，重启主机后默认值仍可读取。
13. 默认模型从目录移除、默认强度与模型不匹配或另一页面先更新 revision 时，保存与发送明确拒绝，不自动回退。
14. 上下文按钮与面板显示当前会话的最近快照；创建、恢复、运行和压缩后的更新均正确处理，未上报时不显示伪造的零值。
15. 额度扩展仅在协商支持后使用，查询不创建会话或发送提示词；多窗口和多额度池正确展示，缺失字段、未登录和不支持状态有明确反馈。
16. 相同范围的初始化、并发打开面板与前台恢复不会重复查询；60 秒缓存、账号切换、迟到响应、重置倒计时及失败保留旧值使用注入时钟和合成事件验证。

使用合成能力数据、可计数的探测替身和确定性就绪信号验证，不使用真实 Agent 账号或 sleeps。真实设备与账号验证另行记录，不能用合成测试声明已完成。

## 验证范围

合成原生 Codex App Server 验证锁定适配器的四种审批参数、旧权限 ID 语义、全部模型档位、额度查询不创建会话与不发送 prompt，以及上下文和额度推送。主机测试覆盖重启后的默认偏好、已有会话不变、目录缓存共享、失败后手动重试、并发刷新、60 秒额度缓存、账号切换与迟到响应。

实际 React 控件在浏览器中检查桌面和 390px 窄屏菜单。上下文、额度、具体重置时间、缺失状态、焦点返回与不触发模型探测使用合成数据验证。未使用真实 Agent 账号，未声明真实套餐数据或所有操作系统上的安装包已验证。
