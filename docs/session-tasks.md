# 受限多 Agent 协作

Moor 可以让一个父回合协调用户事先审查的有限子任务。每项任务使用同一执行电脑、同一项目中的独立 Git worktree，并固定 Agent 版本、首条说明、完成条件和执行预算。父 Agent 通过五个私有工具创建、发送、读取、等待或取消这些子任务。

入口位于 Web 会话输入区的“协作任务”。已有会话和新会话都可以准备计划；主机需要报告 `session-tasks-v1`，项目需要支持[独立工作目录](git-workspaces.md)。本批没有单独的 CLI 任务计划命令；已创建的子会话仍使用既有[会话 CLI](cli.md)与 Web 的范围校验。

## 审查与发送

1. 打开父会话的“协作任务”，点击“读取本地基线分支”。为每项任务填写标题、执行说明和可人工核对的完成条件，选择 Agent 版本及明确的分支与提交。新目录只包含该提交，不包含原目录的未提交改动。
2. 按需要选择模型、effort 和模式。留空沿用该 Agent 版本的默认行为；“刷新选项”会启动临时能力检查，但不发送指令。设置并行数、每项回合数和授权时限。
3. 点击“审查本次任务计划”，核对每项完整说明、Agent 编号、运行选项、分支和 SHA，再点击“启用本次任务计划”。修改草稿会取消原审查，需要重新审查启用。
4. 回到普通输入区，写明父 Agent 要协调和汇总的工作，手动发送。审查、启用、刷新页面或重新连接都不会创建子会话或发送指令；这次普通父指令得到主机确认后，授权才成立。
5. 在面板中点击“读取任务状态”。只有主机已创建会话时才显示“打开子会话”；尚未创建的预留编号或仅准备了目录的任务不能导航成一个已存在的会话。子会话显示父任务来源和完成条件。
6. 分别检查子会话输出、文件与测试结果，再核对完成条件。`success` 只表示该助手回合正常结束，任务状态中的 `goalVerified` 始终为 `false`，不会据此标记用户目标已验收。

任务草稿按服务、账号、执行副本、项目和父会话隔离，并保存在当前访问端。发送前，同一 IndexedDB 事务保存已审查计划与原普通发送请求的关联；存储冲突或保存未确认时不发送。确认只清除这次已发送的审查版本，期间继续编辑的新草稿会保留。新会话刷新后沿用原预留会话编号。

父 Agent 必须在实际 ACP 初始化中报告 HTTP MCP 能力。未报告时会明确提示“此 Agent 不支持 HTTP MCP，无法执行已授权的多 Agent 任务”；不能仅凭 Agent 名称或一次旧能力缓存判断支持。接口能力不保证真实 Agent 一定选择使用工具，因此还需按[设备验收](validation.md#m54-受限多-agent-协作专项步骤)核对实际版本。

## 授权范围与预算

| 项目         | 当前范围                                                                         |
| ------------ | -------------------------------------------------------------------------------- |
| 子任务数量   | 每份计划 1–8 项，编号不能重复；父 Agent 不能临时增加槽位                         |
| 层数与位置   | 仅一层、同一执行电脑与项目；子任务不能再授权下一层任务                           |
| 并行数       | 1–4 项；准备中、执行中和结果未知的任务保守占用额度                               |
| 每项回合数   | 1–3 个发送回合；达到预算后拒绝继续发送                                           |
| 授权时限     | Web 可选 1–60 分钟，默认 10 分钟；协议允许 1 秒至 1 小时，从主机接受授权时计时   |
| 单项正文     | 首条说明及后续单条指令最多 10,000 字符，完成条件最多 2,000 字符                  |
| 执行目录     | 每项从冻结的分支与 SHA 创建新的受管 worktree；分支已前进或目录身份变化时拒绝执行 |
| Agent 与选项 | 使用审查时的固定配置版本和选项，创建、发送及实际 ACP 打开时再次校验适用条件      |
| 结束策略     | 仅支持父回合结束、授权到期或执行授权失效后，请求停止本授权仍在运行的子回合       |

这些预算限制 Moor 任务工具的派发次数和范围，不是模型费用或 token 硬上限。worktree 提供代码目录隔离，不是操作系统沙箱；Agent 的原生能力与权限仍由本机配置和它自身的审批机制决定。审批仍需匹配精确的活动回合与请求，多 Agent 授权不会自动批准子任务的权限请求。

授权有效或任务操作尚未确认时，普通发送、另行创建、Fork 和 Git 目录操作不能绕过任务所有权。查看历史、处理精确审批和手动停止仍走既有接口。授权结束并完成未知结果处理后，可以在保留的子会话中明确手动继续；它仍保留子任务来源，不能重新获得下一层协作权限。

## 父 Agent 的五个工具

| 工具               | 行为与前置条件                                                                                                                                     |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `moor_task_create` | 仅创建授权中指定的槽位。先确认独立 worktree，再原子创建空会话和来源信息；本身不发送 prompt。                                                       |
| `moor_task_send`   | 首次使用已审查的固定说明，调用方不能替换。后续指令需要明确正文、原最新用户回合编号及剩余预算；每次发送保存自己的原操作编号。                       |
| `moor_task_read`   | 只读取当前授权中的子会话状态和有限文本历史。每页最多 20 个回合、每回合最多 16,000 字符，截断会明确标记；附件和完整文件内容仍从子会话原有入口读取。 |
| `moor_task_wait`   | 只等待本授权已发送的精确用户回合，每次最多 20 秒。超时返回当前状态，不取消 Agent，也不改为等待后来的人工回合。                                     |
| `moor_task_cancel` | 只取消本授权发出的精确活动助手回合。旧回合编号或后来手动发送的回合不能被它取消。                                                                   |

普通父 prompt 会附加主机生成的授权清单与槽位编号。工具挂载仅属于这一个活动父回合，首次 `tools/call` 必须发生在真正派发父 prompt 之后；能力检查和原生会话加载不能提前执行子任务。没有任务计划的普通回合不挂载这些工具。

## 结束、未知结果与目录清理

父回合正常结束、失败或停止时，工具授权随之结束，并请求停止本授权仍在运行的子回合。执行主机连接被替换、断开或撤销，以及父项目或目录身份失效，也会使原工具不可用。主机重启将未结束授权收束为中断，不重新创建目录、恢复授权或重放指令。关闭访问页面本身不会停止父任务；页面连接与执行主机的中转连接有不同生命周期。

“工具授权已撤销”只确认不能继续使用该授权，不证明所有子 Agent 已完成停止。面板分别展示授权状态和每个子回合的实际状态；停止未确认或结果未知时继续核查，不能把它显示为全部完成。已产生的代码、分支和会话历史会保留，系统不自动合并或删除它们。

| 页面动作               | 结果的含义                                                                                                                         |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 读取任务状态           | 获取原范围下的最新授权、会话是否存在、回合与操作状态；最多返回最近 20 份授权，字节预算可能使结果更少，并显示不完整。               |
| 核查原操作             | 核对原持久凭据与已记录的 Git/会话操作；不重新派发尚未执行的子任务。没有找到完成凭据仍可能是未知。                                  |
| 封存原操作             | 只有主机能确认尚未执行的原操作才封存，阻止其迟到执行。此前已执行的操作返回原结果；目录仍未知时不能封存后换编号绕过。               |
| 重试原任务操作         | 继续原编号与原参数的人工管理请求；刷新、加载和重连都不自动重试。未知的 Agent 工具操作本身不会因再次调用而重新执行。                |
| 结束此授权并停止子任务 | 明确撤销授权，并尝试停止它发出的精确活动回合。响应丢失时只“重试原撤销”并重新读取状态，不改为封存一个假定未执行的撤销。             |
| 清理此任务工作目录     | 授权已结束且未知操作已处理后，核对任务编号与目录版本，再确认清理。主机再次检查目录干净且未被使用；只移除工作目录，保留分支和历史。 |

每项工具动作先保存意图，以及固定的内部 Git、会话创建或发送请求，再执行对应动作。存在未知操作时，换一个新编号也不能绕过它；可能已派发但回执丢失的任务仍占并行额度。首条发送与后续发送都会消费授权回合预算，不通过重试获得额外预算。

如果 worktree 已创建而空会话保存失败，面板仍展示目录与未知操作。先核查或封存原创建，再结束授权并明确清理干净目录；不能把“没有子会话”当作“没有任何副作用”。有修改、未跟踪文件、被忽略文件或仍被使用的目录受既有 Git 清理保护。

## 协议与私有数据

普通发送的 `inputConfig.taskPlan` 携带版本化清单，`taskToolsEnabled: true` 表示本次启用，外部 `mcpServerIds` 仍为空。主机在接受该用户回合、创建助手回合并保存原发送凭据的同一事务中保存授权和预留槽位；事务失败不会留下独立的可执行授权。授权固定父用户回合、父助手回合、主机用户/电脑/项目/会话范围及原服务、账号与设备身份。

授权身份、操作意图、内部原请求和去重记录保存在执行主机的私有运行数据库中；父计划与子会话来源属于 Moor 会话数据。来源只包含父/子关联与完成条件，不含凭据或启动配置。只有执行主机导入并持久化用户 CRDT 操作，中转不保存会话正文。

Web 人工读取和恢复使用副本范围内的 `tasks-read`、`tasks-action` 类型接口。中转在调用前后核对当前登录、设备、原主机连接与项目副本；主机再次校验执行范围和结果身份。已经获得该项目访问权的其他设备或本机界面可以管理同一授权，不能把原访问端身份字段当成请求参数伪造。

父 ACP 会话通过临时的回环 HTTP MCP 地址接收工具，使用独立随机 bearer 凭据。地址与凭据只传给本次 Agent，不写入共享配置、任务清单或会话历史。传输只开放固定五个工具，限制 origin、Host、认证、请求体与响应大小；每个端点最多同时处理 4 个调用，请求上限 512 KiB、响应上限 1 MiB。当前为 JSON 响应的 Streamable HTTP 子集，不提供 SSE 流、原始 shell、任意 URL 或 socket 代理。关闭立即使凭据对应的工具不可用，不等待挂起的业务回调重新授权。

备份主机数据库会保留授权、来源和原操作记录，但不保存可重新使用的临时工具端点。恢复仍需原项目仓库及独立目录；单独恢复 Moor 数据库不能恢复 worktree 文件或 Agent 自己保存的原生上下文。具体步骤见[运行与恢复](runtime.md)。

## 验证范围

定向合成测试覆盖协议限制与结果归属、事务回滚、真实临时 Git worktree、空会话后首次发送、预算、精确停止、未知结果核查与孤立目录清理。HTTP MCP 和合成 stdio ACP 测试覆盖实际初始化、能力拒绝、prompt 前禁止工具执行、私有凭据脱敏与端点关闭；Web/app 与 IndexedDB 测试覆盖审查不执行、原发送事务、刷新恢复、晚响应和新会话编号。

这些测试使用合成 Agent、临时项目和确定性信号，没有调用真实模型或读取真实账号。最终仓库检查、图形浏览器记录与人工设备结果分别在[设备验收](validation.md)登记。真实 Codex/Claude 或第三方 ACP 的 HTTP MCP 行为、双 Mac、iPhone/Safari/PWA、安装包和系统生命周期仍需专项验收；M5.4 的合成验证不表示条件性 M6 或全部 roadmap 已完成。
