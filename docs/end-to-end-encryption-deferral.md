# 端到端加密延期与退场计划

## 决策

端到端加密不再作为当前产品迭代范围，也不继续以独立“加密工作区”的形态补齐功能。当前阶段优先验证和稳定统一工作区、会话、输入、权限、文件与 Git 等核心体验；端到端加密在产品和协议成熟后作为独立需求重新立项。

这项决定不否定端到端加密的安全价值。普通远程连接仍由 HTTPS/WSS 保护，但 TLS 在中转处终止，中转进程能够看到转发的正文；只有客户端到执行主机之间的端到端加密才能改变这一威胁边界。当前决定是延期交付并清理未成熟的产品实现，不是把现有传输宣称为端到端加密。

现有 M6.2 实现、测试结果和安全边界保留在[端到端加密历史实现](end-to-end-encryption.md)中，仅作为后续设计参考，不再代表当前路线图要求。

## 目标

- 从正式产品和日常开发路径中移除独立“加密工作区”及其双轨实现。
- 消除普通与加密入口之间的界面、控制器、协议适配和测试重复成本。
- 不让失活的安全代码长期留在生产路径中腐化或被误认为正式能力。
- 保留将来引入端到端加密所需的通用安全边界，而不是保留整套不可用功能。
- 保护已有本机数据、主机记录和结果未知的原操作；退场本身不得触发执行、重试或静默删除。

## 非目标

- 本计划不在当前阶段设计新的端到端加密协议。
- 不把 TLS、中转不落盘或自托管等同于端到端加密。
- 不在清理过程中迁移、补齐或重新包装 M6.2 的未完成功能。
- 不借退场改变会话 schema、主机确认、幂等操作和离线草稿的既有语义。
- 不自动删除用户数据、设备材料、主机 journal 或待确认操作。

## 清理范围

### 产品与界面

- 移除菜单、连接设置和工作区导航中的“加密工作区”入口。
- 移除普通／加密视图切换、独立登录配对页面和加密工作区专属状态。
- 移除 `SecureApp` 及只服务于该入口的组件、样式、交互和响应式适配。
- 删除当前产品文案中“已提供完整端到端加密工作区”的承诺。

隐藏入口只允许作为同一清理批次内的过渡步骤，不作为长期完成状态。

### 桌面可信客户端

- 移除仅为加密工作区加载的可信页面、preload、有限 IPC 和窗口生命周期接线。
- 移除仅为该页面使用的独立缓存、IndexedDB 状态和主进程桥接。
- 清理不再可达的权限、CSP、协议加载和页面恢复分支。

若已有预览数据，先完成下文的数据退场保护，再移除读取入口。

### 传输、Host 与 CLI

- 移除产品运行路径中的 v4 Host/Client 端点、加密目录和 secure CLI 命令。
- 移除仅由 v4 使用的能力声明、请求分发、响应适配和恢复入口。
- 删除不再被其他功能使用的设备配对、信任版本、根密钥和恢复命令接线。
- 通过依赖检索确认共享代码的真实消费者，禁止按目录名称整块删除仍被普通流程使用的实现。

### 存储与兼容

- 停止创建新的加密工作区草稿、缓存和原操作记录。
- 不在升级、启动或卸载时自动删除已有记录；如需清理，必须提供明确范围、预览和用户动作。
- 未确认操作不得在退场时自动核查、重试、封存或改投普通连接。
- 已由执行主机保存的会话、附件、journal 和去重记录保持原样，不通过中转或客户端推测结果。
- 只有仍被既有会话读取或升级校验需要的数据格式保留只读兼容；无消费者的 schema、迁移和存储表随实现一起删除。

### 测试与文档

- 删除只验证已移除入口和失活运行路径的交互、图形及端到端测试。
- 保留普通工作区对身份范围、原操作、主机确认和离线不执行的回归测试。
- 删除失效测试后重新核对覆盖率，不能用测试数量下降掩盖共享安全边界的回归。
- 将实现进展文档标为历史资料；当前架构、README 和路线图只描述实际可交付能力。

## 必须保留的基础边界

以下能力服务于普通工作区的正确性和未来演进，不属于需要清除的“加密工作区”功能：

- 每个请求绑定账号、设备、工作区、项目和会话。
- 写操作使用稳定 operation ID、主机去重和明确确认。
- 离线草稿、页面恢复和重新连接不自动执行。
- Relay 不持久化会话正文、项目文件或 Agent 配置。
- 业务协议通过类型化 Host 边界，不暴露原始 shell 或 socket 代理。
- 凭据不进入共享文档、日志、会话正文或分发产物。
- 传输实现与业务请求保持可替换边界，业务组件不直接依赖 Relay 能读取正文。

## 实施顺序

### 1. 冻结与盘点

- 停止给 M6.2 增加功能、修补功能对齐或新增产品依赖。
- 列出 UI、桌面主进程、preload、客户端、协议、Host、CLI、存储、测试和文档中的全部消费者。
- 区分专属代码、共享安全边界和历史兼容代码，记录删除依赖顺序。
- 检查是否存在本机加密草稿、待确认操作或设备材料，并确定可验证的保留策略。

### 2. 关闭新增并保护已有数据

- 先阻止创建新的加密会话、草稿和原操作，再移除入口。
- 为已有记录提供必要的只读说明或明确的人工处置窗口；不自动发送或重试。
- 验证升级和重新启动不会删除、执行或改绑已有记录。

### 3. 移除产品接线

- 按界面、控制器、桌面桥接、传输、Host、CLI 的顺序移除可达路径。
- 每一层删除后运行定向检查，确认普通工作区没有隐式依赖。
- 移除最后一个消费者后再删除能力常量、schema、存储和底层实现。

### 4. 清理测试、依赖和文档

- 删除失活夹具、脚本、依赖、构建入口和包导出。
- 使用 `knip` 和代码检索确认没有未引用模块、旧入口和只剩文案的能力。
- 更新 README、架构、部署、CLI、设备安全与验收文档，区分当前能力和历史资料。

### 5. 整体验收

- 运行 `pnpm check`、`pnpm test`、`pnpm build` 和 `pnpm format:check`。
- 验证本机与普通远程工作区的登录、项目选择、会话、输入、权限、附件、文件、Git 和恢复流程。
- 验证发布包不包含加密工作区页面、入口、secure CLI 或 v4 运行时资源。
- 记录真实设备未验证范围，不把合成测试当作正式安全结论。

每个阶段单独提交，使用 Conventional Commit 主题；不得把退场清理与无关功能改版混在同一提交中。

## 退场完成条件

- 正式界面、设置和构建产物中不存在“加密工作区”入口。
- 应用启动和普通工作区不加载 `SecureApp`、加密客户端或 v4 运行时。
- Host、Relay 和 CLI 不暴露已退场的 v4／secure 产品入口。
- 不存在仅服务于退场功能的能力标记、存储写入、后台连接和未引用依赖。
- 已有数据没有被自动删除、重放、改投或误报为已确认。
- 普通工作区继续满足范围绑定、幂等、主机确认和离线不执行约束。
- 四项仓库门禁通过，文档只声明当前实际能力。

## 后期重新立项的启动条件

只有同时满足以下条件，才重新评估端到端加密：

1. 统一工作区的核心流程和数据模型已经稳定，并完成目标真机验收。
2. 产品明确需要防止中转运营者或中转数据库读取正文，而不只是需要 TLS 或自托管。
3. 有资源一次性交付设备生命周期、恢复、功能对齐、可诊断性和真实多设备验收。
4. 已形成独立威胁模型、安全评审计划、版本迁移方案和故障恢复规范。
5. 新设计不重新引入第二套工作区界面。

后期设计应把端到端加密作为连接的安全属性：普通和加密连接共用工作区、会话与功能组件；远程连接可默认尝试端到端加密，任何明文回退必须清晰展示并由用户明确决定，禁止静默降级。设备配对、撤销和恢复归入“设备与安全”设置，而不是工作区导航。
