# Git 与会话工作目录

Moor 可以读取当前执行电脑上项目的 Git 状态，并在新会话首次发送前创建独立 worktree。会话仍属于原来的项目副本，Agent、当前文件浏览与回合快照使用这份独立目录。创建目录本身不会执行 Agent。

## 创建与使用

1. 新建会话，确认执行电脑和项目，打开“Git 与工作目录”。
2. 选择主机列出的本地基线分支及提交，填写一个尚不存在的新分支名称，手动创建。
3. 主机确认“独立工作目录 · 可用”后再发送指令。刷新页面或切换项目后返回，仍使用该草稿的原会话编号和目录。

独立目录从明确的提交创建，不复制原目录的未提交文件，也不切换原目录分支。项目登记为仓库子目录时，新 worktree 包含完整仓库，Agent 的工作位置仍是对应子目录。已有会话保持原执行目录；需要从已有上下文创建独立会话时使用[原生 Fork](session-fork.md)。

工作目录默认位于主机 SQLite 数据库同级的 `worktrees` 目录，具体位置由主机生成，访问端不能提交任意路径。主机数据目录应在项目仓库之外；若 CLI 把数据库放在项目内部，创建嵌套 worktree 会被拒绝。不要为绕过拒绝移动或修改已有会话的执行记录。

## 状态与清理

面板显示本地分支、提交和文件状态。路径只返回登记项目范围内的相对路径；同一仓库的项目范围外改动单独提示。未跟踪和被忽略文件也会使目录视为有改动。状态读取有数量、字节和时间限制，部分读取不能当作干净目录。

清理需要手动勾选确认，并由主机再次核对目录归属、Git 状态版本及会话是否空闲。活动回合、尚未处理的用户输入、未保存结果、未提交文件、被忽略文件和无法确认的状态都会阻止清理。操作只移除此会话的 Moor 管理 worktree，不删除分支或提交。主机不会强制清理或递归删除未知目录。

清理后，会话历史、附件和已经冻结的 diff 仍可读取和搜索；实时文件不可再读取，该会话也不能继续发送指令。需要继续编码时另建会话。保存了提交不等于完成远程备份；推送需另行进入[代码发布](github-writes.md#推送与-pr-操作的范围)流程明确确认。

原目录 Fork 可以让多个会话共用一份 Moor worktree。面板显示引用数量；有其他会话引用时，仅可脱离当前空闲会话，不移除目录。最后一个引用才可清理物理目录。未确认的 Fork 预留也计入引用保护；脱离的会话保留历史，但不能继续执行。

## 拒绝、确认丢失与恢复

每个操作绑定账号、设备、执行工作区、项目和会话。访问端先保存原请求，主机先保存固定操作计划，再执行 Git。写入前发现分支冲突或状态变化会明确拒绝，保留原执行绑定；修改参数后必须再次手动操作。

Git 已开始执行后发生超时、断线或持久化失败，结果保持待确认。重启、刷新和重连不会发送待确认操作。“重试确认”沿用原操作编号：主机已经保存计划时，只检查原定目录和 Git 登记，不再次执行 Git；原请求从未到达主机时，这次手动操作才会首次提交。无法证明已有操作的结果时继续保持未知，并阻止在该会话发送新指令。其他会话仍可使用。

主机会核对目录身份及 `.git`、`commondir`、`gitdir` 指针，并在发送前检查仍处于绑定分支，拒绝目录替换或仓库改向。同一分支的提交可以前进；外部切换分支或进入 detached HEAD 后须先恢复绑定分支。Git 本地及 include 配置也绑定创建时的文件身份与摘要，修改或替换配置会使旧绑定保守失效，本版本不自动重绑定。

当前版本对执行型 hooks、filters、子模块、稀疏检出、隐藏索引状态等布局采用保守限制；状态、worktree 管理与本地提交不启用网络访问，也不调用仓库配置的外部程序。明确推送时使用固定 GitHub smart HTTPS，不读取 remote 配置来选择目的地。启动 ACP 时清除继承的 `GIT_*` 环境变量，使新建与恢复会话的 Git 使用主机选择的目录。界面会说明不支持或读取不完整的状态。

## 提交与发布

“审查、评论与代码发布”可以在当前会话目录提交明确选择的文件。本地提交不需要 GitHub 账号；用户先检查文件内容、作者与说明，主机固定父提交、选中字节和首次计划时间，保留未选择的暂存与工作目录改动。外部编辑使已选择版本改变时，必须重新审查。

提交中的原索引锁、文件系统身份与分支更新受到校验；同一仓库目录的活动回合、未确认提交、Fork 或目录清理不能与之交叉执行。回执丢失后仅核查原计划，不生成另一个提交。本地提交的分支与暂存区结果无法同时证实时，需在执行电脑检查实际状态，不能仅关闭待确认记录、删除锁或重发来绕过保护。

推送是独立的最终确认动作，需先验证本机 GitHub 仓库并明确开启项目外部写入。它只推送已选择的 HEAD 到同名分支，并核对预期远端提交；没有强制推送。完整步骤与未知结果处理见[审阅与代码发布](github-writes.md)。

## 备份与验收范围

主机数据库保存目录绑定和操作凭据；M4.4 本地提交计划还保存该次选中的代码字节和索引前后内容，但不构成工作目录的完整副本。停机备份还需由操作者保存项目仓库、共享 Git 元数据和各 worktree 的未提交文件；单独复制数据库不构成代码备份。目录绑定包含原路径和文件系统身份，复制或迁移目录后不能直接恢复为可执行绑定，也不会自动修复 Git 登记。历史仍按原项目范围授权读取。

自动测试使用临时 Git 仓库和合成 Agent，覆盖隔离、首条指令路由、脏目录保护、指针变化、操作去重、重启核查及清理后历史保留。Mac 安装包、真实 Agent、iPhone/Safari/PWA 与跨设备交互仍需按[设备验收](validation.md)人工检查。
