# 工作区界面

界面以黑、白和中性灰呈现。设置中的 Dark mode、Light mode、Auto 分别固定深色、固定浅色和跟随系统；默认为 Auto。浏览器保存本机外观偏好，桌面通过可信 IPC 保存到用户数据目录并同步已打开窗口，不写入项目或会话。

## 导航与输入

侧栏依次显示工作区切换、新对话与新项目、置顶、项目、Chat 和底部账号/设置。Chat 是当前工作区的最近会话，所有会话仍保留原账号、设备、项目和执行身份。跨项目列表只读获取，不改变正在编辑的草稿。项目默认收起，侧栏可以调整宽度或折叠，窄窗口改为抽屉。

macOS 关闭、最小化和全屏按钮位于侧栏顶部的原生区域，不再增加独立标题行和大号标志。Windows/Linux 保留原生窗口装饰。

输入框上方显示项目、执行电脑和 Git 工作目录；切换执行上下文不会把已保存的草稿带到另一个身份。附件与 Skills 位于「+」菜单，空输入框按 `$` 可打开 Skills；Cmd/Ctrl+Enter 提交当前指令。审批选项在输入框下方左侧，模型和推理强度在右侧。选项仍来自当前 Agent 的实际能力。

输入与本机恢复数据分为三层。UI State 保存当前文字和控件交互，每次输入只更新组件内存，不发布全局工作区状态。Draft State 按账号、设备、工作区、项目和会话单独保存未发送文字与运行选项；连续输入合并后保存，切换会话、发送或页面退出前主动落盘。Ledger 只保存必须可靠确认的原操作、附件和功能状态，使用严格事务与版本校验；普通草稿保存不会复制、校验或重写 Ledger。

发送是三层之间的明确边界：先保存最新 Draft State，再把当时的文字、运行选项和附件版本固化为不可变原操作写入 Ledger，最后才请求执行主机。回执确认后按草稿版本清空已发送文字；若发送期间又有新输入，版本不同，新内容不会被清除。恢复草稿或重新联网只读取数据，绝不自动执行。

执行电脑连接状态与会话加载状态分别建模。选择会话时先读取本机缓存，再显示“正在同步”；只有主机读取实际失败才标记执行电脑不可达。同步期间只暂停依赖主机最新确认的发送和变更，不锁住侧栏或其他会话导航；快速连续选择由会话 generation 丢弃旧响应。

有历史内容后，右上角显示环境信息面板，集中提供文件、diff、Git/worktree 和 GitHub 入口。新会话隐藏该面板；工作目录仍可从输入框上方选择。会话元数据、Fork 和信息位于省略号菜单。

## 移除功能与已有数据

移除网页预览、角色预设、协作任务和本回合额外 MCP 的客户端组件、工作流和预览登记面板。新的指令不附带这些功能的旧草稿选择；主机版本化协议、存储校验与原操作确认逻辑保留兼容性，本机 Agent 和 MCP 配置继续可用。

已有会话与原请求不删除、不在重连时重放。会话待确认请求保留原编号核查；旧协作请求只有存在遗留记录时才显示核查与原请求重试入口，不提供新建计划或授权。差异与错误可使用语义颜色，主题表面与主操作保持黑白。

这些已移除功能的客户端控制器及其专属交互测试也已清理。旧数据格式、图片与请求摘要校验、原账号和执行目标绑定继续由工作区存储和原操作账本维护；任务与 MCP 的原指令摘要共用同一实现。兼容回归见[旧工作区记录](../tests/integration/workspace-feature-compatibility.test.ts)、[旧预览与标注](../tests/integration/project-preview-compatibility.test.ts)和[原加密请求账本](../tests/integration/secure-store.test.ts)。本机设置、主机协议和合成主机测试继续保留。

## 验证范围

自动测试使用合成账号、会话、主机和确定性信号。`pnpm exec electron scripts/validation/check-workspace-layout.cjs` 检查实际 Chromium 中的深色/浅色/Auto、重载持久化、环境面板显隐、侧栏宽度持久化与 390px 抽屉布局，并将截图写入临时目录。原生标题栏配置另有平台测试。

这些检查不等同于已签名安装包、真实 Agent 账号或真实多设备端到端验收。
