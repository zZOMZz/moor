# 正文搜索

正文搜索覆盖会话消息、工具输出和已经保存的文件变更；侧栏搜索继续用于会话标题、项目与电脑名称。M2.4 的主机索引、离线缓存查询与页面定位已实现，四项仓库检查和合成验证通过；真实设备验收仍待完成，当前进度见[功能完善计划](roadmap.md)。

## 搜索范围与查询

“当前会话”限定所选会话；“当前电脑的项目”覆盖同一执行电脑、执行工作区和本地项目内的可访问会话。同一逻辑项目在另一台电脑上的副本需要单独选择，不会因为名称相同而合并搜索。即使查询整个项目，请求也必须绑定一个已有且可访问的会话作为上下文。

查询按字面子串匹配，不把引号、星号、括号或 `OR` 当作搜索表达式。空白分隔的多个词使用 AND 关系，必须同时出现在同一条消息、工具内容或 diff 条目中；不会把分散在不同回合中的词拼成命中。支持中文子串和统一的 Unicode 小写处理，未做拼音、模糊纠错或语义检索。

每次查询最多 500 个字符，默认返回 30 条，最多 100 条。结果显示来源、所属会话、内容类型、可用路径与原文摘要；有更多匹配时需要缩小查询范围。消息和工具结果以原回合及条目为定位依据，历史 diff 使用保存时的版本；打开搜索结果保留原输入草稿。

## 主机索引

索引保存在原执行主机自己的 SQLite 数据库中。搜索请求使用 `session-search-v1` 能力和 `searchVersion: 1`，通过当前工作区与项目副本的 `session-search` 接口发送。账号来自登录身份，设备与路由来自当前副本映射；主机校验执行工作区、用户、机器、本地项目及会话范围。中转只临时转发请求与结果，不保存会话正文或搜索索引。

会话持久化时标记索引源版本变化，用户手动搜索时再刷新受限数量的脏索引。旧会话可按需建立索引，已保存且源版本一致的索引可以跨主机重启使用。源内容已经更新、保存失败或范围已失效时，旧片段不能作为当前搜索结果返回；重建失败应显示内容覆盖不完整，而不是确认旧内容仍然有效。

查询先按已授权会话从 SQLite 取出受数量与字节限制的候选，再使用与离线查询一致的字面匹配。单次文本检查最多 5,000 条、16 MiB；达到限制时明确报告不完整。索引保存的是可搜索的内容投影，这一实现不承诺每次搜索都遍历整个项目的全部历史。

投影只包含消息和思考文本、工具标题与可见文本输出、工具返回的 diff，以及主机保存的冻结文件变更。原始工具参数、原始输出对象、私有 metadata、Agent 配置和附件字节不进入正文索引。附件内文检索尚未包含在本阶段中。

冻结 diff 必须匹配原会话中的回合、diff ID 和版本，再从主机自己的历史记录读取。当前项目文件不会为搜索重新扫描，也不会用当前文件补造旧 diff。新增、删除、修改和重命名可提供路径与实际保存的前后文本；二进制、超限或不可用内容不生成猜测文本。搜索、索引刷新与重建都不启动 Agent。

## 离线覆盖范围

主机离线时，查询只读取当前浏览器中已经保存且属于当前执行身份的会话和历史文件缓存。用户可以输入新的查询词；离线流程不会请求主机、写入远程数据或等待重连自动执行。在线搜索失败则直接显示错误，不自动切换为旧缓存结果。

消息来自已持久化的本机会话缓存。历史 diff 需要原回合的引用、已读取的对应版本摘要，以及曾读取过的历史文件内容；仅缓存摘要时，只能搜索可用路径，未缓存的前后文本不算覆盖。主机尚未保存的临时输出不作为持久历史参与离线搜索。

结果明确标为“本机缓存”，并显示本次读取的缓存会话数、已知会话数和历史文件缓存数。已知会话列表也来自访问端掌握的范围，不代表离线时已获知主机全部最新会话。缓存可能过期、缺失或超限，因此没有匹配不证明主机上不存在该内容；浏览器缓存也不构成备份。

## 限制与不完整结果

主机刷新、单会话投影、结果候选和离线读取分别受数量与字节预算约束。单会话投影最多 2,000 条，每条最多 120,000 个字符，总文本最多 16 MiB；截断文本和遍历范围会标记不完整。离线单次最多处理 100 个已知会话，历史 diff 摘要与文件缓存读取合计最多 64 次。主机还限制单次刷新的会话数、内容字节和候选量；具体覆盖情况以本次结果中的不完整提示为准。

达到预算、部分会话尚未索引、历史基线不完整、缓存损坏或缺失时，结果会提示部分内容未覆盖。`more` 表示已经发现还有匹配但超过返回条数，`partial` 表示本次没有完整检查所有可用内容，两者含义不同。缩小到具体会话或更精确的查询有助于定位；手动重新搜索可以刷新尚未完成的索引，但不能让未保存的历史或未缓存文件凭空出现。

## 验证范围

本批 `pnpm check`、337 项自动测试、`pnpm build` 和 `pnpm format:check` 通过。搜索合成测试覆盖 SQLite 字面查询、范围隔离、源版本与索引替换、冻结 diff 投影、私有字段排除、离线缓存、刷新与晚到响应等行为。实际 Moor 主机和合成 ACP 的浏览器检查验证中文消息命中后定位原消息、保留输入草稿，以及搜索 `answer.txt` 的已保存内文后打开对应冻结 diff；390×844 视口未发现横向溢出或页面错误。

Mac/iPhone 的输入、结果定位、大列表反馈以及真实网络下的离线恢复，仍须按照[设备验收](validation.md#后续阶段的专项验收)核对。合成数据和桌面窄视口不能替代真实设备验收。
