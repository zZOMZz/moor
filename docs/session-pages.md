# 会话目录分页

执行主机通过 `session-page-v1` 能力提供项目范围的会话元数据分页。每页默认最多 30 项，调用方可选择 1—100 项；响应上限为 1 MiB。分页不读取会话正文、不启动 Agent、不产生执行操作，也不把会话索引保存在中转。旧 `sessions` 接口仍保留，兼容未使用分页的客户端。

## 请求与结果

Host 命令为 `sessions-page`。HTTP 入口是 `POST /api/workspaces/:workspaceId/replicas/:replicaId/sessions-page`，其中路径使用组织目录的工作区与副本；正文中的 `workspaceId`、`localProjectId` 使用该副本确认的执行主机身份，不能用展示名称或路径代替。

请求字段如下：

| 字段                            | 规则                                                                                    |
| ------------------------------- | --------------------------------------------------------------------------------------- |
| `pageVersion`                   | 固定为 `1`                                                                              |
| `workspaceId`、`localProjectId` | 必填，与已授权的执行工作区和项目一致                                                    |
| `limit`                         | 默认 `30`，最小 `1`、最大 `100`                                                         |
| `archived`                      | `active`（默认）、`archived` 或 `all`                                                   |
| `pinned`                        | `all`（默认）、`pinned` 或 `unpinned`                                                   |
| `query`                         | 默认空字符串；去除首尾空白后最多 200 字符，匹配标题或会话编号，不区分大小写；不搜索正文 |
| `cursor`                        | 首次省略；后续原样使用前一页的 `nextCursor`，最长 2,048 字符                            |

结果包含 `pageVersion`、执行范围、`confirmed: true`、规范化后的四个筛选/数量字段、`revision`、`items` 和 `nextCursor`。`items` 仅包含 Moor 会话元数据，按置顶优先、最近活动时间降序、会话编号字典序排列。没有下一页时 `nextCursor` 为 `null`；结果不提供全局总数，客户端应区分“已加载”与“完整目录”。

## 游标、范围与列表变化

游标绑定当前执行工作区、账号、机器、项目、筛选条件、页大小和整个项目元数据的版本。标题、置顶、归档、增删或其他元数据变化后，旧游标返回 `409`，调用方需要从第一页重新读取，不能将不同版本的页面拼接。其他项目的变化不会使当前项目的游标失效。

游标是分页位置，不是授权凭据。即使调用方提供了格式正确的游标，每次读取仍要核对项目归属和当前连接；返回结果仍检查范围、筛选条件、排序、重复编号和 Host 元数据身份。中转在读取前后检查原执行范围，响应丢失不会触发任何执行或自动改变会话。

## 当前成本与验证

Web 与桌面共用分页消费。导航为每个可见项目读取最多 30 个置顶摘要和 30 个最近摘要，再合并显示；摘要读取以四个 worker 调度。展开项目、标题或编号筛选、查看归档和加载更多都使用同一个分页接口。查询或项目改变时，迟到页不能覆盖新视图；加载更多收到 409 时提示重新读取，不自动改用完整列表。

重复读取相同目录不会重新拉取所有项目。客户端比较连接身份、项目目标、在线状态以及该项目的运行身份与能力；只有相关项目失效。用户手动刷新某个项目也只使该项目的列表失效。旧主机未报告分页能力时才使用旧 `sessions` 完整目录，界面明确显示兼容模式；不能将旧主机的完整读取算作分页收益。

离线仅展示已确认读取并保存过的具体页，按账号、来源、设备、项目、筛选条件和原游标隔离。界面显示已加载数量、缓存范围及是否还有更多。未缓存的下一页不能用已知条目补造；鉴权、映射或游标错误不触发缓存回退。某个项目的读取失败不会把其他项目标为离线，分页读取也不修改草稿或未确认操作。

每个执行范围的可丢弃页缓存最多保留 64 页，序列化页正文与引用头合计最多 8 MiB。页面使用独立记录，轻量引用头只保存受限请求、版本和字节数；新版本第一页会淘汰该筛选的旧游标页，超限时淘汰较早的缓存。缓存头、写入和物理删除在一个 IndexedDB 比较交换事务中完成，不写 `null` 占位。待删键由已验证的执行范围与请求派生，缓存头不能指定任意数据库键；草稿、原操作、其他范围和旧接口缓存不参与清理。缓存写入失败不会阻止使用已经确认的在线结果。

当前改造限制网络传输、客户端解析和渲染所需的数据量。Host 内部仍从项目会话列表获取完整元数据，并计算版本和筛选排序；尚未改成 SQL 索引分页，不能将网络页大小等同于 Host 只扫描 30 条记录。后续优化内部索引时应保留稳定排序、版本冲突、项目权限和旧游标失效规则。

合成测试覆盖 85 项的完整逐页读取、默认与最大页大小、归档/置顶/标题和编号筛选、跨身份和跨项目游标、陈旧元数据、异常游标、返回排序与范围验证，以及全部 43 个 Host 命令的接线。没有使用真实 Agent、真实用户历史或真实设备网络性能测试。

客户端验证还覆盖真实 React 导航的摘要请求量、原游标续读、搜索未加载的会话、归档、查询切换后的迟到响应、离线部分结果、无关项目不重刷，以及缓存容量、恶意引用头、物理删除失败的原子回滚和草稿/未知操作保留。真实 Relay 与生产分页 helper 的联测确认转发范围、返回身份和撤权/重连期间的迟到响应保护。
