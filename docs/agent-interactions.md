# Agent 交互

Moor 根据当前会话实际报告的能力提供问题回答、命令、计划、上下文与用量，以及受限的回合内追加。M3 实现与合成验证已完成，真实 Agent 和设备验收仍待完成。能力缺失或未验证时显示原因，不根据 Agent 名称猜测其支持范围。

## 问题与权限审批

Agent 的表单问题支持文本、单选、多选、数值/整数和布尔字段。用户可提交回答、拒绝回答或取消此问题；关闭弹窗只关闭界面，停止整个执行回合仍使用会话的停止按钮。必填、选项、长度和数值范围由客户端和主机分别验证，`0` 与 `false` 是有效回答，不等同于未填写。

**回答问题不等于批准工具权限。** 两者采用独立请求，均只对提问时的活动助手回合有效。问答请求绑定账号、设备、执行工作区、本地项目、会话、回合与请求编号；主机停止、原请求结束或会话目标变化后，旧页面不能把回答送给新回合。无法按当前能力安全表达的问题会明确拒绝或取消，不转为任意 URL 访问。

提交前，浏览器保存完整原请求和操作编号。主机在同一事务中保存回答状态与去重凭据，再交给对应等待中的 Agent 请求；该确认不代表 Agent 后续执行已经成功完成。响应丢失或确认不匹配时保留原请求，由用户手动确认；刷新、重连和重新打开弹窗不自动提交。已确认的同一操作返回原确认，不向 Agent 再交付一次回答。

## 命令与计划

“命令、计划与用量”显示当前会话最近回合实际收到的运行时信息。命令名称、说明和参数提示来自 Agent；点击命令只把内容填入输入框，用户检查并点击发送后才执行。命令不会绕过正常指令确认、审批或执行目标校验。

命令保留 Agent 上报的 `$` 或 `/` 前缀；普通名称才补 `/`，例如 Codex 的 `$review-skill` 与普通 `/review`。项目文件的发现和冻结正文引用另见 [Skills](skills.md)，不能用文件存在代替原生能力报告。

计划可以是条目列表或 Markdown，并保留 Agent 报告的优先级和进度。Agent 删除计划后，页面显示当前状态；没有报告计划与已报告空计划分别表示。文件形式的计划只显示引用，Moor 不自动访问 URL 或读取引用中的本机路径。

## 上下文与用量

页面分别展示 Agent 通过 ACP 报告的上下文已用量/容量、Token 字段和费用。缺失字段显示“未提供”，真实的零值仍显示为零；不从模型名称推算上下文大小、价格或额度。

Token 的时间范围由 Agent 报告，Moor 不把含义不明确的计数推断为本回合增量，也不跨回合相加。费用保留上报金额与币种，不换算、不推测账号余额。离线展示的是已读取的历史报告，不能当作实时账号用量。

内置 Claude ACP 0.76.0 的实际初始化名称与版本匹配时，额外显示适配器结构化上报的账号额度：窗口、允许/接近限制/受限状态、已用比例、UTC 重置时间，以及可选额外用量状态。利用率按上报的 0–1 比例显示；未知版本、自定义 Agent、Codex 或无报告时明确显示未提供，不从模型级 token 配额推断账号余额。

各额度窗口分别保留最近报告，历史保存与重新读取不会因普通上下文更新而丢失其他窗口。新报告缺少比例时显示未提供，不继承旧比例；到达重置时间后也不自行判断已恢复。付款信息、账号标识及原始扩展元数据不进入共享记录。

## 回合内追加

“回合内追加”向仍在运行的原回合补充文本说明，操作绑定精确的活动回合，独立于普通指令草稿。它不更换模型、不自动提交附件，也不会在目标回合结束后自动创建新回合。

当前只对 **Moor 内置 Claude ACP 0.76.0** 且实际初始化报告兼容 steering 能力的会话启用。名称或能力字符串本身不足以启用：自定义启动配置、未知版本和未知适配器保持禁用。当前锁定的 Codex ACP 1.11.0 不启用追加；不以可能启动新回合的回退行为冒充注入原回合。适配器升级需要重新验证并锁定版本。

主机先持久保存原操作的执行阶段，再调用原生追加；只有收到明确的 `injected` 结果才标记已送达活动回合。若 Agent 报告没有运行中的回合，则显示“未进入活动回合”。若连接中断、进程退出或响应含义不确定，则保留“结果未知”，不把未知状态改报成功。

原操作一旦进入主机追加阶段，**手动重试只查询原结果，不再次调用原生追加**。原生接口没有可供 Moor 保证去重的操作编号，因此不会因确认丢失而再注入一次。待确认记录保留原文本、编号和执行身份，刷新与重连不执行；用户仍可停止当前回合。

已明确未注入的记录可关闭；结果未知的记录须等原回合结束后才能关闭。关闭仅整理本地待确认状态，原请求和结果标记仍保留，不自动转成普通指令。是否重新发送内容，应在查看原回合后由用户另行决定。

## 验证范围

本批 `pnpm check`、337 项自动测试、`pnpm build` 和 `pnpm format:check` 通过。合成协议、stdio、主机和真实 app 集成测试覆盖能力约束、回答校验、精确活动请求、原操作去重、确认丢失、离线/刷新与停止竞争。

实际 Moor 主机与合成 ACP 的浏览器检查验证文本、单选、整数 `0` 和布尔 `false` 回答；命令只填入 `/review` 草稿，没有自动发送。计划进度、上下文 `25/100`、费用 `0 USD`、输入/输出/总 Token `25/5/30` 均按上报内容显示，缺失字段保持未提供。390×844 视口中的问答弹窗无横向溢出，页面没有报告错误。

浏览器使用自定义合成 Agent，按能力边界没有执行追加；固定 Claude 适配器的注入路径由合成 stdio 与主机测试验证。真实 Claude/Codex 登录和模型调用、浏览器追加、Mac 安装包、iPhone/Safari/PWA 仍须完成[第二轮设备验收](validation.md#后续阶段的专项验收)。本阶段不延长 Agent 生命周期，也不增加后台驻留、自动唤醒或离线执行队列。
