# 项目文件与历史变更

项目文件和回合变更都由原执行主机提供。读取请求绑定当前账号、设备、执行工作区、本地项目和会话；文件正文不保存在中转数据库。附件是单独保存的输入或生成文件，项目文件则来自已登记的工作目录。

## 当前项目文件

已有会话中的“项目文件”入口显示该项目的只读文件列表。Git 项目使用已跟踪文件和未被 Git 忽略的未跟踪文件；普通目录使用受限的目录扫描，并明确提示未应用 Git 忽略规则。扫描不会执行项目脚本、Git 钩子或远程命令。

文件列表最多包含 5,000 个文件与目录，目录深度最多 64 层，分页读取时固定同一列表版本。列表变化后需要从第一页刷新，不能把两个版本的分页拼接为当前完整列表。文件名、大小和路径来自扫描结果，文件正文以实际读取时的内容版本为准。

文本和 Markdown 的读取上限为每份 1 MiB，按实际 UTF-8 字节校验。二进制和超限文件明确说明其状态；不会把无效字节替换成文本。符号链接、非普通文件及项目外路径不可读取。

## 回合与会话变更

主机在打开 Agent 前保存起始文件基线，在 Agent 结束并关闭后保存结束基线。两份基线的比较可以显示新增、删除、修改和内容完全相同的重命名；同时修改内容的重命名可能显示为新增与删除。二进制文件保留内容摘要和大小，无法展示文本差异。

历史变更读取保存时的前后版本。之后继续同一会话、编辑文件或删除当前文件，都不会使旧回合的变更重新计算。会话变更按回合展示这些记录，已有的旧回合没有基线时显示“未记录”，不使用今天的文件补造历史。

**变更描述工作目录在两次扫描之间的差别。** 外部编辑器或共享该目录的其他会话也可能修改文件；扫描本身不是原子的文件系统快照，因此不能将所有变化归因于当前 Agent。独立 worktree 的隔离能力属于 M4。

每份基线最多读取 16 MiB，单份文件最多 1 MiB，一次比较最多返回 500 项变化。超限文件只记录可用的大小与状态，不将其视为不存在，也不声称未读取的内容没有变化。普通文件在采集期间变化、读取失败、项目范围变化或基线不完整时，结果明确标为部分可用或不可用。

## 过滤范围与限制

自动列表和基线排除版本库内部目录、常见依赖目录、构建产物和缓存，包括 `.git`、`node_modules`、`vendor`、`dist`、`build`、`coverage`、虚拟环境及类似目录。`.data` 和 `.moor` 也不进入自动扫描，避免收集 Moor 配对配置和运行数据。常见凭据文件和目录也排除，例如 `.env`、`.env.*`、`.npmrc`、`.pypirc`、`.netrc`、`.ssh` 和云凭据目录；`.env.example`、`.env.sample`、`.env.template` 可作为示例文件进入列表。

这些是明确的扫描过滤规则，不能识别所有项目内的敏感信息。项目内部另有凭据时，应使用 Git 忽略规则和自己的文件管理约定。只读文件接口仍以用户明确选择的项目内路径为准；自动采集的过滤范围不会授权任意路径读取。

过滤或限额会保留具体说明。部分结果中没有某个文件，不足以证明它被删除；起始或结束枚举不完整时，不会用缺失条目推断新增或删除。

## 取消、中断与离线

取消先停止当前执行，再完成可用的结束基线采集。采集失败不把已完成的 Agent 操作改报为执行失败；执行状态和变更可用性分别显示。

主机退出或崩溃后，如果没有完整的结束基线，记录保持“中断”或“不可用”。重启不会调用 Agent，也不会现场读取文件填补缺失的旧基线。用户可以手动开始新回合。

在线读取会重新检查主机和项目归属。离线只能阅读这个浏览器已保存的具体列表、文件或历史变更版本，并标为缓存；未缓存的内容不可用。在线读取被拒绝时，不用旧缓存冒充当前主机结果。浏览器缓存不构成备份，主机数据的停机备份方法见[开发与验证](development.md)。

当前文件访问使用 Node 的普通文件检查、禁止跟随符号链接的打开方式和读取前后身份复核。它能拒绝可观察的路径替换，但不等同于针对恶意本机进程的操作系统沙箱。网络文件系统和真实设备上的行为还需单独验收。

## 验证范围

合成验证覆盖文件变化、范围隔离、分页版本、历史不可变、取消与中断、事务失败以及离线缓存。真实 Mac、iPhone/Safari、网络文件系统和真实 Agent 尚需按[设备验收](validation.md)完成第二轮检查；浏览器窄视口检查不代替手机验收。
