# Agent 配置与角色预设

Moor 将本机 Agent 启动配置和项目角色分开管理：执行电脑登记实际运行的程序，角色保存要使用的 Agent 版本、模型、effort、审批模式和默认说明。角色应用先进入可编辑草稿，用户检查后手动发送。

## 在执行电脑登记 Agent

打开 **Moor → 连接设置 → 本机 Agent 配置**。展开面板或刷新设置只读取本机记录，不启动 Agent。

1. 选择“添加 Codex”“添加 Claude”，或登记自定义 ACP 程序。自定义程序需要可执行普通文件的绝对路径；参数填写 JSON 字符串数组，每个元素是一个独立参数，不经过 shell 展开。
2. 保存配置。新登记默认不用于新会话；自定义配置可明确勾选“用于新会话”。内置适配器的启动配置由 Moor 管理，面板不编辑其程序路径和参数。
3. 需要检查时，点击“检查已保存的连接”。它会启动一次所选版本，在独立临时目录读取实际能力后关闭，不发送指令，也不创建 Moor 任务历史。检查只针对已保存的配置；修改表单后需先保存新版本。
4. 核对结果，再明确选择“用于新会话”。检查成功不会自动启用。模型和审批模式来自 Agent 实际报告，具体项目中的选项可能不同。

打开自定义 ACP 的会话、Agent 列表或角色列表不会自动检查能力。角色面板中的“读取此 Agent 的模型选项（会启动 Agent）”是另一项明确操作，用于所选执行项目；已有会话只检查其固定版本。内置 Agent 仍保留原有的缺少能力时读取流程。

名称或启动参数变化会生成新的版本编号。新会话使用当前启用版本；已有会话及原生 Fork 沿用其固定配置，不被后续编辑、停用或“从新会话列表移除”切换到另一个 Agent。移除也不会删除原会话、原生映射或已确认操作记录。固定的是启动配置，不能据此宣称磁盘上的程序文件、模型服务或第三方账户状态被一并冻结。

启动程序路径、参数和配置快照只保存于执行主机的私有数据中。远端会话和目录只返回允许公开的编号、名称、Agent 类型与能力，不接收任意启动命令。不要把凭据填入角色说明或消息：这些普通正文会按草稿和会话规则保存。

## 本机 CLI

先退出持有原主机数据库的 Moor 实例，再指定同一份配置和数据路径：

```sh
node dist/bridge.mjs \
  --config /absolute/private-moor/bridge-v3.json \
  --runtime-data /absolute/private-moor/runtime-v1.sqlite \
  --agent-config-stdin <<'JSON'
{"action":"read"}
JSON
```

返回 `revision` 与 `presets`。预设的 `id` 标识可编辑登记，`versionId` 标识当前不可变启动版本；角色固定的是后者。CLI 读取结果可能包含本机程序路径与参数，属于本机配置输出。

每次修改使用刚读取的 `expectedRevision`。以下是新建自定义 ACP 的输入示例；路径和参数须替换为实际支持 ACP 的程序，版本值须替换为当前读取值：

```json
{
  "action": "save",
  "expectedRevision": 0,
  "name": "我的 ACP Agent",
  "command": "/absolute/path/to/acp-agent",
  "args": [],
  "enabled": false
}
```

| 动作      | 额外字段                                                     | 结果                                             |
| --------- | ------------------------------------------------------------ | ------------------------------------------------ |
| `builtin` | `agentType: "codex"` 或 `"claude"`                           | 登记内置适配器，默认不用于新会话                 |
| `save`    | `name`、`command`、`args`，修改时加预设 `id`，可选 `enabled` | 保存自定义配置；省略 `enabled` 按 `false` 处理   |
| `check`   | 预设 `id` 与刚读取的 `versionId`                             | 明确启动并检查该版本，不发送指令，不改变启用状态 |
| `enabled` | 预设 `id`、`enabled`                                         | 设置是否供新会话选择                             |
| `remove`  | 预设 `id`                                                    | 从新会话列表移除，保留已有会话的版本             |

这些动作都需要 `expectedRevision`；`read` 不需要。一次 stdin 输入一个 JSON，最多 64 KiB。退出码 `0` 表示命令已处理，`1` 表示输入或配置失败，`3` 表示主机锁不可用；连接检查还需查看所选预设的 `checked.ok`，不能仅用退出码判断 Agent 已连通。不能同时使用桌面、配对或其他配置 stdin 入口。版本冲突或响应丢失后先手动读取实际状态，不自动重试本机配置命令。

## 创建和应用项目角色

新会话或已有会话的输入栏均有 **角色预设** 入口。同一执行主机、同一本地项目的会话共享角色目录；工作区归组不会把其他电脑的同名项目角色自动合并。角色保存在执行主机，中转不存角色正文。

“新建角色”填写名称、固定 Agent 版本、运行选项和默认说明，再点击“保存角色”。已有角色可编辑、复制或明确删除。每次保存或删除都由主机确认，并核对整个项目角色目录的版本；其他设备已修改时需重新读取。复制产生独立角色，删除不改变已经应用的草稿或历史。

保存角色需要当前可供新会话选择的 Agent 版本。旧版本角色不会随 Agent 更新而自动改绑：它仍可在固定同一版本的已有会话中使用；需要迁移预设时，编辑并明确选择当前版本。

应用流程如下：

1. 选择角色，查看“应用到草稿前确认”中的完整说明、Agent 版本及运行选项。
2. 模型、effort 或审批模式留空表示**保持当前选择**，不代表恢复默认或降低权限。不支持的选项会显示原因并保留现有配置；需要时手动读取该 Agent 的模型选项，再重新确认。
3. 已有会话只能应用同一 Agent 版本。不同版本使用“在新会话应用此角色”，进入来源项目的新会话草稿后再次确认；不切换原会话 Agent，也不自动发送。
4. 点击“确认应用到草稿”。Moor 重新读取原角色版本，将说明追加到最新输入，并一次性保存草稿、运行选项和已应用版本记录；新会话的 Agent 选择也在同一事务保存。输入、其他页面的设置或执行目标发生竞争时，不把变更保存成半套。
5. 在普通输入框检查、编辑最终文本，再手动发送。角色说明是普通用户指令，不提升为系统提示，不写入旧历史，也不每次重连自动注入。发送后的审批仍对应实际活动回合和请求。

同一草稿中已应用的同一角色版本不会因刷新重复追加。修改角色产生新版本，也不追溯改写旧草稿。角色列表只在面板内存，关闭或离线会清除列表。尚未点击保存的角色表单只保留在仍打开的面板中，关闭后不恢复；已经提交的待确认请求则独立持久化，已应用的普通输入草稿也会保留。目录更新通知要求手动重新读取，不覆盖当前未保存的角色编辑，也不把自身已确认保存误报为未知。

## 角色操作结果未知

角色创建、编辑和删除在发送前，先把完整执行范围、操作编号与原请求保存到本地待确认记录。刷新、离线恢复和重连只恢复记录，不执行它。可以继续查看其他会话；当前角色目录的新写入需先处理原操作。

| 手动操作         | 行为与含义                                                                             |
| ---------------- | -------------------------------------------------------------------------------------- |
| 核查原角色操作   | 只查询原回执，不执行保存或删除。暂时未找到回执不代表原操作已取消。                     |
| 重试原角色操作   | 使用原编号和原参数；尚未到达主机时可能首次执行，已有持久结果则只返回原结果。           |
| 结束原角色操作   | 请求主机封存尚未执行的原请求；若此前已完成，返回实际成功回执，不宣称撤销已有角色修改。 |
| 重试结束角色操作 | 结束请求响应丢失后，继续确认同一封存请求，不切回保存或删除。                           |

主机先持久保存的结果决定后续回复：成功回执表示原操作已完成；封存回执表示原请求未执行且今后不再执行。迟到的原保存、删除和查询都遵循该结果。页面只有在收到范围、编号与版本匹配的主机回执后才清除待确认记录，错误或不匹配响应不会丢弃原请求。

应用角色后发送的指令则走普通会话 outbox。若指令送达结果未知，手动确认始终使用第一次构造的完整正文和运行选项，不再次附加角色说明；详见[同步、送达与重试](sync.md)。

## 范围、上限与验证

- 本机最多保留 100 个未移除 Agent 预设，含移除记录的预设总数最多 200。名称最多 100 字符，程序路径最多 4096 字符；参数最多 128 项，每项最多 4096 字符，且整体仍受 64 KiB 输入限制。
- 每个项目最多 50 个角色。名称最多 100 字符，每份默认说明最多 16 KiB UTF-8，角色目录合计最多 1 MiB。一次草稿最多记录 50 个已应用角色版本，追加后的普通指令最多 100000 字符。
- Agent 配置只提供本机受限 IPC/CLI；角色远端接口绑定账号、设备、执行工作区、本地项目和会话。角色接口不接收 Agent 启动配置、原始 shell 或任意网络代理；默认说明按普通文本处理。
- 合成测试覆盖私有 CLI/IPC、默认停用与显式检查、固定版本和旧会话恢复、角色目录版本竞争、未知操作封存，以及真实 React/app 的草稿事务、晚响应、原编号重试和项目隔离。测试不使用真实 Agent 账户或模型。
- 本批不据此宣称完成真实 Codex/Claude、第三方 ACP 程序、双 Mac、iPhone/Safari/PWA 或最终安装包验收。完整真机安排仍见[设备验收](validation.md)，不能用合成测试替代。
