# 设备验收

第一轮完整真机验收安排在 **M0 回归基线与 M1 会话管理实现完成、四项仓库检查通过之后，进入 M2 前**。此时发送、审批、停止、恢复和会话整理已经形成完整日常流程，适合一次验证双 Mac 与 iPhone。无需等待附件、Git 或全部 roadmap 完成。

第二轮在 M2/M3 各自的可交付流程完成后进行，重点检查图片附件、文件预览、后台通知及真实 Agent 的问答、命令和追加指令。两者独立交付时分别验收，避免一项等待另一项。修改休眠/唤醒、退出、签名、PWA 后台或系统权限等平台行为后，提前做对应的专项人工检查；这类问题不应积累到里程碑末尾。

## 验证层次

| 层次           | 执行环境                                                     | 能证明什么                                  | 不能替代什么                    |
| -------------- | ------------------------------------------------------------ | ------------------------------------------- | ------------------------------- |
| 仓库检查       | `pnpm check`、`pnpm test`、`pnpm build`、`pnpm format:check` | 类型、覆盖到的合成行为、构建与格式          | 真机交互、真实 Agent 与公网环境 |
| 合成跨设备验收 | 两台 Mac、iPhone、独立测试中转和合成 Agent                   | 实际浏览器/PWA、执行路由、持久化与恢复      | 真实 Agent 能力及账号登录兼容性 |
| 操作者人工验收 | 相同专用项目，操作者自行登录的 Codex/Claude                  | 真实 Agent 启动、审批、停止及原生上下文恢复 | 未测 Agent 版本、设备和网络环境 |
| 发布验收       | 目标架构安装包、目标域名与网关                               | 首次安装、升级、证书信任及发布配置          | 其他架构与其他部署环境          |

自动化测试只使用合成数据、合成 Agent、确定性信号或注入计时器，不读取真实 Agent/GitHub 账号、不调用真实模型或 GitHub API。涉及真实登录与模型的检查由操作者在设备上人工完成，不把凭据或会话内容交给测试脚本。

## 第一轮准备

1. 两台 Mac 分别命名为测试电脑 A/B，准备各自的专用临时项目。项目只放虚构文本和可丢弃的示例文件，不使用日常项目；在同一逻辑项目下登记两个独立副本。
2. 安装相同版本的 Moor 与锁定 ACP 适配器。使用隔离的 Moor 数据目录，记录数据库、配对配置与项目位置；不要连接日常测试之外的 Agent 会话。
3. 使用操作者可管理的独立中转账号与 HTTPS 地址；Mac、iPhone 都须信任证书，不关闭证书校验。中转 `/healthz` 成功后仍需确认两台执行主机在线。
4. iPhone 在 Safari 登录并添加到主屏幕，同时保留桌面本机工作区和另一台 Mac 的远程访问页面，以核对同一操作的结果。
5. 先用合成 Agent 验证路由和恢复；真实 Agent 兼容性阶段由操作者自行完成登录。设备测试记录只保留版本、环境、通过/失败及脱敏现象，不提交账号、日志、会话或数据库。

| 旧主机兼容性   | 合成主机省略会话管理能力报告，使用新页面访问                                                | 整理入口不可用并提示更新主机，历史阅读与原有功能不因新入口误报成功               |
| 导航与长列表   | 使用合成长列表，切换工作区、项目、活动/归档列表，搜索、置顶并在手机开关抽屉                 | 选中的执行副本准确；搜索范围明确；空列表与离线状态可理解，滚动和交互无明显阻塞   |
| 中转重启       | 重启独立测试中转，再打开 PWA                                                                | 登录、主机在线和历史恢复；草稿和待确认操作保留，恢复不执行草稿                   |
| 主机恢复       | 对合成测试数据按[停机备份步骤](runtime.md#主机停机备份与恢复)恢复到新目录，只启动一个副本   | 身份、历史、会话整理状态、原生 ID 映射与去重记录保留；中断回合不自动执行         |
| 休眠与网络切换 | 让执行 Mac 休眠再唤醒；iPhone 在 Wi-Fi/蜂窝网络间切换                                       | 离线/重连状态准确；唤醒不重放旧请求；历史可重新补齐                              |

可控的响应丢失、版本竞争与去重应先由确定性合成测试证明，再在设备上核对交互。不要通过反复点击或任意等待猜测是否形成故障。存在未解决的重复执行、审批越界、历史损坏或错误主机路由时，不通过第一轮验收。

### M2.2 附件专项步骤

1. 在专用项目中新建会话，用 iPhone 的文件/相册选择器和剪贴板分别添加合成文本、图片和二进制文件；核对名称、大小、预览和本机草稿提示。每个文件 8 MiB、每条指令 8 个、会话 64 MiB 的边界由合成测试先覆盖，设备上再核对超限提示与原草稿保留。
2. 离线添加附件并刷新，恢复连接后确认没有自动上传或执行。手动上传时核对主机确认；在合成故障信号下丢弃响应，刷新后点“重试确认”，核对原操作编号、字节和执行目标不变。
3. 分别发送带文本和仅有附件的指令，确认主机收到全部附件后才运行 Agent。上传期间切到另一电脑，原指令不应在另一电脑执行；切回后附件状态可恢复。指令确认后输入区清空附件，历史附件仍能读取。
4. 对操作者已登录的每个 Agent 分别核对图片、音频和普通文件能力。不支持或未报告的输入应显示原因；能力刷新和启动时变化不能使指令静默丢失附件。归档会话先恢复再上传，已有待确认操作仍使用原请求确认。
5. 用合成 Agent 返回 PNG/JPEG/GIF/WebP、纯文本、Markdown 和普通二进制嵌入文件，在 Mac、Safari 和已安装 PWA 中逐一打开；SVG/HTML 不作为可执行页面嵌入。预览长文本应标记截断，下载后由操作者核对完整字节和文件名。仅返回资源 URL 时应显示不可读取，不抓取 URL 或主机路径。
6. 刷新后重新打开历史卡片，离线时已读取版本明确标为缓存、未缓存附件明确不可用；尝试移除未发送附件和已被历史引用的附件，核对后者受到保护。测试期间取消文件选择、旋转屏幕、打开键盘和切换后台，核对草稿、焦点及待确认状态。
7. 在 Mac 安装包中点击历史附件下载，系统保存对话框应让用户选择位置；取消、切换会话和切换执行电脑不得继续保存待处理的旧附件或污染新页面提示。正常保存后核对磁盘字节与原摘要，不能只以按钮点击或模拟对话框结果判断通过。

### M2.3 文件与历史变更专项步骤

1. 在独立 Git 项目放入合成 Markdown、普通文本、二进制和被忽略文件。分别从 Mac 和 iPhone 打开“项目文件”，核对文本预览、大小、分页与版本，过滤文件及符号链接不进入自动列表。使用普通目录时应看到未应用 Git 忽略规则的说明。
2. 让合成 Agent 明确执行新增、删除、修改、内容不变的重命名和二进制变化。在回合及会话变更视图中逐项核对路径和前后版本，确认旧回合无基线时显示未记录。
3. 记录已保存 diff 的版本，再完成下一回合修改同一文件。当前文件应显示新内容，原回合 diff 的版本与前后文本保持不变；删除当前文件也不能使旧基线消失。
4. 使用确定性合成信号验证取消、主机中断、采集失败和数据库保存失败。核对执行状态与文件变更可用性分别表达；重启不会执行 Agent 或补采旧基线，未保存的输出不得当作持久历史继续发送。
5. 读取部分文件和历史 diff 后离线，核对已缓存的具体版本可读、未缓存版本不可用，在线读取被拒绝时不自动展示旧缓存。检查 iPhone 旋转、键盘、前后版本切换、长路径和滚动，不能用桌面窄视口替代这些检查。

### M2.4 正文搜索专项步骤

实现与合成检查已完成；设备验收使用两个主机各自的专用合成项目，继续核对实际输入、定位与网络状态。

1. 在消息、工具输出和已保存 diff 中放入不同的合成标记，分别搜索当前会话和当前电脑的项目；侧栏标题搜索的结果范围应与正文搜索区分。结果不能包含其他账号、主机、执行工作区或项目副本的内容。
2. 检查中文子串、Unicode 大小写及含引号和符号的字面查询，多个空白分隔词应同时匹配同一结果。点击消息/工具结果定位原回合，点击冻结 diff 结果读取对应历史版本。
3. 仅缓存一部分会话和 diff 后离线，用新的查询词搜索；核对缓存覆盖数量、部分内容提示，以及未缓存内容不会触发主机请求。回到在线状态后，读取被拒绝或主机断开应报告错误，不自动伪装为在线搜索成功。
4. 合成环境中验证索引过期、范围撤销、索引写入失败和预算上限；旧索引片段不得绕过当前授权或源版本检查。设备上再核对大列表反馈和滚动，记录未覆盖内容。

### M2.5 通知专项步骤

本批涉及操作系统权限和 PWA 后台，完成实现与合成检查后即可安排专项真机验收，无需等 M4。用专用项目与合成 Agent 产生事件；设备权限与推送服务由操作者在自己的测试环境配置。

1. Mac 打开连接设置，确认通知默认关闭、打开页面不请求权限。主动开启并测试系统通知，分别验证完成、失败和权限请求；改变提醒类型后核对实际效果。拒绝权限时应显示原因，任务执行不受影响。
2. 关闭 Mac 窗口但保留应用运行，核对系统通知出现且点击只打开对应会话；明确退出应用后不再执行或接收本机通知。恢复执行组件时，旧组件回调不能覆盖新连接或产生重复通知。
3. 用 HTTPS 中转配置稳定 VAPID 密钥，在真实 iPhone/Safari 添加到主屏幕并打开 PWA，点击开启。分别测试页面前台、后台和关闭后收到通知，再测试专注模式、断网、休眠以及恢复网络。记录实际端点供应商与系统版本，不提交订阅 URL 或密钥。
4. 在另一端回答权限请求或结束回合，再点击旧通知；只显示最新状态，旧请求不能批准。合成重复事件与断线恢复应去重；供应商接受、设备实际显示和用户点击分别记录，不能混为“已送达”。
5. 分别关闭提醒类型、关闭本浏览器通知和退出登录。服务器不可用时保留手动关闭入口，刷新后“停用待确认”不丢失；切换账号不得打开旧账号会话。先前已发出的推送可能显示无目标信息的通用提醒，不能携带旧会话标识。
6. 用合成信号覆盖执行连接替换、设备撤销、项目重新归组、订阅失效和推送结果不确定。真实环境核对重连不重新执行任务、旧审批不会恢复、其他登录端的订阅不被误关。更换 VAPID 密钥后手动关闭并重新开启订阅，确认恢复方式明确。

### M4.1 Git 与工作目录专项步骤

1. 在专用 Git 项目中保留一份原目录未提交修改，从 Mac 或 iPhone 新建两个会话，分别从明确的本地提交创建不同分支的独立 worktree。创建后先刷新或切换项目再返回，确认仍使用原草稿与目录，没有自动运行 Agent。
2. 让合成 Agent 分别修改两个目录，核对彼此和原目录隔离；浏览当前文件和冻结 diff，确认执行电脑与项目副本准确。原目录的未提交修改不应进入新 worktree，原分支不应切换。
3. 验证已有分支冲突、基线分支前进和不支持的 Git 布局有明确提示。对待确认操作通过合成信号丢弃回执，重启后手动重试；只核查原操作，不重复创建或清理。
4. 在独立目录中分别留下修改、未跟踪和被忽略文件，核对清理被拒绝；活动回合及尚未处理输入也不能清理。将合成改动提交后手动勾选清理，确认目录移除、分支和提交保留、历史与冻结 diff 仍可读取，该会话不能再发送指令。
5. 操作者检查真实 Agent 的 Git 行为、Mac 休眠和恢复、手机键盘与长路径布局。外部切换工作目录分支、替换目录或更改 Git 路由后，发送前应拒绝已失效的绑定。文件系统迁移与 Git 特殊配置须单独记录兼容范围；不要用复制数据库代替代码备份。

### M4.2 原生 Fork 专项步骤

M4.1/M4.2 实现与合成验证完成后安排一轮真机测试，优先确认真实 Agent 上下文与文件目录的对应关系，再推进依赖它们的并行工作流验收。

1. 操作者在专用项目中分别验证锁定 Codex 与 Claude 适配器，完成两个含不同合成标记的回合。从第一个已完成回合 Fork，再明确询问子会话可见的标记，确认截止范围；另测“Agent 当前保存的上下文”。没有原生锚点的旧回合应禁用，不能当作精确截止可用。
2. 分别创建原目录和独立 worktree Fork。核对来源不变、子会话显示来源和截止点；原目录共享未提交文件，独立目录仅包含选择的提交。让子会话修改专用文件，再核对来源目录和子目录的实际内容。
3. 关闭并重新打开子会话，验证原生恢复仍使用子会话与目标目录。Claude 尤其检查来源目录创建的原生子会话能在独立目录恢复。原生编号与消息锚点不应出现在网页或中转数据库中。

### M4.4 Git 与 GitHub 写操作专项步骤

本批自动测试使用合成 HTTP、临时 Git 项目和 bare 接收仓库，不访问真实 GitHub 账号。真实权限与分支保护规则、Mac 安装包和 iPhone/Safari/PWA 均待操作者按以下步骤验收。使用明确授权的专用测试仓库，并在每次最终确认前核对仓库、分支、PR 和实际内容。

1. 在执行电脑验证项目 GitHub 仓库。默认关闭外部写入时，仍能读取上下文和审查本地提交；启用后，手机可打开写操作面板。关闭再开启开关后，旧审查版本失效，必须重新读取。
2. 浏览 PR 文件和补丁，分别选择新增、删除或上下文中的实际行。核对 head/base SHA、路径和 LEFT/RIGHT 行号；二进制、缺失或截断补丁不能猜测行号。提交顶层行评论后，手动同步评论并回复顶层线程，核对 GitHub 网页中的位置与正文。
3. 在 Issue/PR 会话评论中填写草稿，审查后最终确认。离线、刷新和重新连接不会自动发布；确认丢失时保留原编号，手动核查同一请求。结束远端未知操作的核查不表示已撤销它，也不能重新发送旧编号。
4. 本地修改至少两个文件，预先暂存其中一个。只选择另一个文件，核对前后预览、作者和说明，再确认提交。检查提交内容、时间、分支及保留的未选暂存内容。活动 Agent 或相同目录的未确认提交应阻止新的冲突操作，停止入口仍可使用。
5. 推送前核对本地分支、固定 head SHA、登记仓库和刚读取的远端 SHA。普通快进成功后核对远端结果；远端竞争、受保护分支或权限不足不能触发强制推送或自动重试。仓库身份或凭据变化后重新读取。
6. 创建 PR 时核对同一登记仓库的 head/base 分支和提交；分别测试编辑标题/正文、关闭/重开与 merge/squash/rebase。GitHub 创建与编辑接口没有原子版本条件，应检查可能的并发变化；创建后实际 head 变化会明确提示。合并使用核对后的 head SHA，分支规则仍由 GitHub 决定。
7. 对未知提交，在执行电脑核对分支与暂存区，然后手动读取原结果。读取不修改 Git，也不能把一次“尚未看到变化”当作原操作永远不会完成。只有主机已记录原写入进程与子进程收尾、当前完整范围不变、无活动会话或 Git 锁且分支与索引符合原基线，才可明确结束核查来解除目录保护。崩溃缺少证据或部分完成时继续保持保护，不能仅清除提示绕过。
8. 双 Mac 和 iPhone 分别核对最终确认页、长路径与正文、页面刷新、会话切换、退出登录和授权撤销。记录真实 API 权限、限流与设备生命周期结果；确定性的响应丢失、锁竞争和内容变化由合成测试覆盖，不通过任意等待猜测故障是否发生。

### M4.3 GitHub 只读集成专项步骤

本批实现与合成测试不含真实 GitHub 账号或 API。下面是操作者在专用项目和仓库中执行的后续验收步骤；当前没有据此声明通过。评论、推送、创建或合并 PR 等 M4.4 写操作不在本批验收范围。

1. 在执行电脑的本机连接设置添加、替换、检查和删除凭据，明确选择已登记项目的 `owner/repo`。核对 token 保存后不回显，项目验证前不能远端读取；仓库数字 ID 和连接状态准确。配置目录必须在所有项目之外，不把测试凭据、配置或备份提交到仓库。
2. 在两个执行副本上分别配置专用仓库，手机切换电脑或项目，核对读取始终来自当前主机的明确绑定。当前请求期间撤销 Moor 访问权限或替换主机配置，晚到响应不能显示旧内容。
3. 阅读 Issue、PR 及会话评论，检查正文转义、截断和手动分页。存在下一页、过滤了 PR 的 Issue 页或已达上限时不能显示全量完成；空的当前页不能被解释为整个仓库没有内容。
4. 阅读来自 fork 的 PR，分别核对 head/base 仓库、分支和 SHA。CI 仅对应明确的 head SHA，缺失或部分结果不显示全部通过；用合成信号验证 PR 在读取中更新时拒绝旧结果，真实环境中再核对新提交需重新读取。
5. 阅读和关联不改变源文件、不启动 Agent，也不填入或发送草稿；明确加入草稿才复制内容，手动发送后进入会话历史。撤销 GitHub 授权会清除在线 GitHub 内容，但不能删除操作者已复制的普通草稿或历史。
6. 用确定性响应丢失检查关联恢复：原操作已保存时，手动重试返回脱敏确认，不调用 API 返回旧正文；随后撤权仍可解除本地关联。尚未送达的操作可手动撤销，主机保存放弃记录后同编号迟到请求不能执行；撤销不自动解除已保存关联。
7. 将本机项目从仓库 A 改为 B，确认页面只展示 B 的有效上下文；旧 A 关联可以明确解除或重新绑定，不回显 A 正文。刷新、断网重连及账号切换不会自动绑定、读取旧缓存或重放撤销前的请求。
8. 真实 token 的过期、组织授权、GitHub 限流及移动端体验由操作者另行记录。浏览器或 HTTP 合成测试不能替代实际 Mac 设置窗口、双 Mac/iPhone 和真实 GitHub 验收。
