# 设备验收

第一轮完整真机验收安排在 **M0 回归基线与 M1 会话管理实现完成、四项仓库检查通过之后，进入 M2 前**。此时发送、审批、停止、恢复和会话整理已经形成完整日常流程，适合一次验证双 Mac 与 iPhone。无需等待附件、Git 或全部 roadmap 完成。

第二轮在 M2/M3 各自的可交付流程完成后进行，重点检查图片附件、文件预览、后台通知及真实 Agent 的问答、命令和追加指令。两者独立交付时分别验收，避免一项等待另一项。修改休眠/唤醒、退出、签名、PWA 后台或系统权限等平台行为后，提前做对应的专项人工检查；这类问题不应积累到里程碑末尾。

## 验证层次

| 层次           | 执行环境                                                     | 能证明什么                                  | 不能替代什么                    |
| -------------- | ------------------------------------------------------------ | ------------------------------------------- | ------------------------------- |
| 仓库检查       | `pnpm check`、`pnpm test`、`pnpm build`、`pnpm format:check` | 类型、覆盖到的合成行为、构建与格式          | 真机交互、真实 Agent 与公网环境 |
| 合成跨设备验收 | 两台 Mac、iPhone、独立测试中转和合成 Agent                   | 实际浏览器/PWA、执行路由、持久化与恢复      | 真实 Agent 能力及账号登录兼容性 |
| 操作者人工验收 | 相同专用项目，操作者自行登录的 Codex/Claude                  | 真实 Agent 启动、审批、停止及原生上下文恢复 | 未测 Agent 版本、设备和网络环境 |
| 发布验收       | 目标架构安装包、目标域名与网关                               | 首次安装、升级、证书信任及发布配置          | 其他架构与其他部署环境          |

自动化测试只使用合成数据、合成 Agent、确定性信号或注入计时器，不读取真实 Agent 账号、不调用真实模型。涉及真实登录与模型的检查由操作者在设备上人工完成，不把凭据或会话内容交给测试脚本。

## 第一轮准备

1. 两台 Mac 分别命名为测试电脑 A/B，准备各自的专用临时项目。项目只放虚构文本和可丢弃的示例文件，不使用日常项目；在同一逻辑项目下登记两个独立副本。
2. 安装相同版本的 Moor 与锁定 ACP 适配器。使用隔离的 Moor 数据目录，记录数据库、配对配置与项目位置；不要连接日常测试之外的 Agent 会话。
3. 使用操作者可管理的独立中转账号与 HTTPS 地址；Mac、iPhone 都须信任证书，不关闭证书校验。中转 `/healthz` 成功后仍需确认两台执行主机在线。
4. iPhone 在 Safari 登录并添加到主屏幕，同时保留桌面本机工作区和另一台 Mac 的远程访问页面，以核对同一操作的结果。
5. 先用合成 Agent 验证路由和恢复；真实 Agent 兼容性阶段由操作者自行完成登录。设备测试记录只保留版本、环境、通过/失败及脱敏现象，不提交账号、日志、会话或数据库。

## 第一轮操作矩阵

| 场景           | 操作者动作                                                                                  | 通过条件                                                                         |
| -------------- | ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 安装与本机启动 | 在 A/B 打开 Moor；先不配对，添加测试项目并打开本机工作区                                    | 本机流程可用；未配对、未就绪与就绪提示准确                                       |
| 配对与项目路由 | 两台 Mac 加入同一工作区；手机选择 A 的副本创建会话，再选择 B 创建另一会话                   | 名称和目录准确；文件改动只出现在所选执行电脑                                     |
| 发送与继续     | 手机发送，另一台 Mac 阅读并手动继续同一会话                                                 | 输出补齐，原主机执行，新回合只出现一次                                           |
| Agent 兼容性   | 操作者分别用已登录的 Codex、Claude 完成文本、工具与第二轮对话；检查可报告的模型/effort/模式 | 选项以主机能力为准；执行失败可理解，输入与目标保留；原生会话可继续或准确报告失败 |
| 审批与停止     | 使用会请求审批的合成场景；一端处理审批，另一端尝试旧请求；停止后开启新回合                  | 只有精确活动请求被接受，旧审批/旧停止不影响新回合                                |
| 关闭窗口与退出 | 任务运行时关手机页面或 Mac 窗口，再打开；另一次明确退出执行电脑上的 Moor                    | 关页面/窗口不停止任务；明确退出停止自身执行组件；重开后不自动重放指令            |
| 离线与草稿     | 在已经读过历史的访问端断开网络，输入草稿，再恢复连接                                        | 已缓存历史可读；未缓存内容明确不可用；草稿保留且不自动发送                       |
| 确认丢失       | 在合成场景中由测试信号丢弃一次已接受操作的响应，手动点原请求重试                            | 结果待确认有提示；operationId、目标与配置不变；无重复回合                        |
| 重命名和置顶   | 手机上整理 A 的空闲会话，观察另一台 Mac，再刷新页面                                         | 主机确认后两端一致；置顶排序稳定，标题搜索匹配新标题                             |
| 归档与恢复     | 在有草稿的会话中归档，查看归档历史，尝试继续，再恢复                                        | 历史和草稿保留；归档会话不能发送；恢复本身不启动 Agent，随后可手动继续           |
| 活动会话和冲突 | 运行或等待审批时尝试归档；两端修改同一会话；离线时尝试整理                                  | 归档活动会话被拒绝；过期版本返回冲突；离线整理不误报成功，重连不自动执行         |
| 旧主机兼容性   | 合成主机省略会话管理能力报告，使用新页面访问                                                | 整理入口不可用并提示更新主机，历史阅读与原有功能不因新入口误报成功               |
| 导航与长列表   | 使用合成长列表，切换工作区、项目、活动/归档列表，搜索、置顶并在手机开关抽屉                 | 选中的执行副本准确；搜索范围明确；空列表与离线状态可理解，滚动和交互无明显阻塞   |
| 中转重启       | 重启独立测试中转，再打开 PWA                                                                | 登录、主机在线和历史恢复；草稿和待确认操作保留，恢复不执行草稿                   |
| 主机恢复       | 对合成测试数据按[停机备份步骤](runtime.md#主机停机备份与恢复)恢复到新目录，只启动一个副本   | 身份、历史、会话整理状态、原生 ID 映射与去重记录保留；中断回合不自动执行         |
| 休眠与网络切换 | 让执行 Mac 休眠再唤醒；iPhone 在 Wi-Fi/蜂窝网络间切换                                       | 离线/重连状态准确；唤醒不重放旧请求；历史可重新补齐                              |

可控的响应丢失、版本竞争与去重应先由确定性合成测试证明，再在设备上核对交互。不要通过反复点击或任意等待猜测是否形成故障。存在未解决的重复执行、审批越界、历史损坏或错误主机路由时，不通过第一轮验收。

## 结果与通过口径

每轮记录被测提交或构建标识、macOS/iOS 与硬件架构、Moor/Agent/适配器版本、Safari/PWA 形态、中转部署和网络类型，以及每个场景的通过、失败或未测。失败项记录脱敏复现步骤与是否阻断发布；真实会话、密钥和运行数据不进入仓库。

本轮四项仓库检查通过，73 项自动测试全部通过。已使用独立数据目录中的实际 Moor 主机与合成 ACP，在桌面和 390px 浏览器视口中检查重命名、置顶、归档、恢复、草稿保留、刷新恢复和活动会话禁止归档；合成测试还覆盖 2,000 条会话的分批渲染、并发标题冲突、旧响应覆盖保护，以及数据库复制到新目录后的身份、元数据、去重凭据和原生会话 ID 保留。

这些检查尚不覆盖真实 Mac 安装包、iPhone/Safari/PWA、真实 Agent 登录与模型调用，**真实双 Mac + iPhone 和正式签名公证仍待操作者完成**。第一轮真机通过后可以进入附件与 Agent 交互扩展；正式分发还需完成对应发布验收。
