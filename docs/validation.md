# 设备验收

验收针对当前版本的用户流程。自动化入口是 `pnpm test:e2e`，完整提交检查是 `pnpm check`、`pnpm test`、`pnpm build` 和 `pnpm format:check`。历史测试数量、旧安装包和已删除脚本的通过记录不沿用到新版本。

## 自动化覆盖与缺口

| 流程                   | 自动化入口                                                                                                                                                                                       | 证明范围                                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| 本机与远程会话闭环     | [CLI/Host E2E](../tests/e2e/cli-host.test.ts)                                                                                                                                                    | 构建后的 CLI/Host、真实本机 HTTP 或生产 Relay HTTP/WS、合成 ACP、SQLite、去重、停止、整理、重启恢复 |
| 浏览器草稿与登录恢复   | [浏览器 E2E](../tests/e2e/browser-workspace.cjs)                                                                                                                                                 | 构建后的 Web、真实 Chromium/IndexedDB、合成 API；离线保留草稿，401 返回登录，不自动发送             |
| 项目导航与窄屏         | [布局场景](../tests/e2e/workspace-layout.cjs)                                                                                                                                                    | 当前 React/CSS、真实 Chromium、内存控制器；分页、筛选、选择、主题、390px 抽屉                       |
| 审批、丢回执和身份变化 | [主机](../tests/integration/host.test.ts)、[客户端](../tests/integration/cli-client.test.ts)、[恢复](../tests/integration/workspace-operation-recovery-relay.test.ts)                            | 确定性故障注入与跨模块行为，不等于完整浏览器到 Host 流程                                            |
| 旧数据与退场入口       | [旧 CLI/Relay](../tests/integration/retired-e2ee.test.ts)、[旧客户端数据](../tests/integration/retired-client-data.test.ts)、[旧运行能力](../tests/integration/retired-session-features.test.ts) | 只读保留、原操作核查、拒绝新增执行；不恢复已删除的功能                                              |

运行要求和详细边界见 [E2E 说明](../tests/e2e/README.md)。测试仅使用临时合成项目与账号，按 Host 消息、DOM 和数据库事务信号等待；不读取真实 Agent 账号或其他应用数据库。图形环境缺失应失败并修复环境，不标记跳过后宣称通过。

浏览器到真实 Host 的发送/审批闭环、附件与 Git 等功能还没有统一 E2E 场景，仍依赖定向集成回归。后续优先补齐这些用户流程，不以单元测试数量衡量完成度。

## 本轮重构的待验收清单

真实设备检查由发布操作者在专用测试项目中完成。准备两台独立 Mac、一个自托管测试 Relay 和 iPhone/Safari/PWA；分别记录源码提交、安装包摘要、系统版本、Agent/适配器版本和执行者。任何真实账号操作只在操作者明确授权的范围内进行。

| 场景               | 操作                                                            | 必须观察到的结果                                                 |
| ------------------ | --------------------------------------------------------------- | ---------------------------------------------------------------- |
| 本机首次使用       | 不登录远端，添加项目、配置本机 Agent、创建空会话                | 项目与执行电脑明确；空会话不启动指令                             |
| 发送与继续         | 选择有效模型/effort/权限，发送，另一访问端读取并继续            | 选项来自原 Host；一条发送只出现一次，始终在原项目执行            |
| 审批与停止         | 两端查看同一审批，一端处理后另一端提交旧请求；停止后开启新回合  | 仅当前回合和精确请求有效，旧审批/停止不影响新回合                |
| 同名项目与会话     | 配对两台 Mac，在手机选择具体电脑及同名项目                      | 实际执行副本准确，归组与筛选不迁移会话                           |
| 账号切换与撤销     | 切换账号或撤销设备后使用旧页面                                  | 旧页面不能读取正文、退出新账号或提交旧权限                       |
| 整理与长列表       | 重命名、置顶、归档、恢复，切换最近/归档和后续页                 | 主机确认后同步；活动回合不能归档；恢复不启动 Agent；分页不混版本 |
| 离线草稿           | 保存草稿、断网、重开页面、恢复连接                              | 草稿和已缓存内容保留，未缓存范围明确，不自动上传或执行           |
| 未知结果           | 由合成信号丢弃已接受操作的响应，重开后手动核查原操作            | 原编号和冻结输入不变，无重复回合，新草稿不被旧确认清空           |
| 归组保护           | A 会话保留草稿/未知请求，切到 B 后移动电脑或重新归组            | 操作被阻止，A 的原记录仍可找到                                   |
| 明确提交的队列任务 | 审阅输入和授权后明确提交，断线再重连                            | 仅已提交任务可同步入队；普通草稿和旧父子任务不转成新任务         |
| 关闭、退出和恢复   | 关页面/窗口再打开；另一次退出所拥有的 Host；休眠唤醒            | 关页面不取消；退出后的中断状态明确；恢复不重放普通请求           |
| 网络变化           | iPhone 切换 Wi-Fi/蜂窝，重启测试 Relay                          | 离线与恢复状态准确，主机身份及原操作保持不变                     |
| 旧数据升级         | 使用合成旧草稿、待确认请求和已退场记录升级                      | 支持的迁移核验完整身份；其余只读保留，不删除、改投或封存         |
| 主机备份恢复       | 按[停机恢复步骤](runtime.md#主机停机备份与恢复)恢复到新私有目录 | 只启动一个副本；身份、历史、原生会话映射与去重记录保留           |

出现重复执行、审批越界、错误副本、数据损坏或草稿丢失时，该项保持失败，先补合成复现再重验。当前没有本轮最终包的双 Mac、iPhone 或正式签名通过结论。

## 功能专项

### 附件、文件与搜索

在专用项目中从 iPhone 选择/粘贴附件并下载 Agent 生成文件；验证大小限制、上传中断与手动恢复，主机未确认附件前不能执行指令。检查当前文件和历史 diff 的版本区别、后续修改不改写旧 diff、二进制/过滤/超限的部分可用提示。正文搜索分别检查当前会话、当前主机项目与离线缓存范围，点击结果准确定位，不跨副本混入内容。

### 通知

Mac 和已安装的 PWA 分别从默认关闭开始，验收系统允许、拒绝和撤销权限；在前台/后台触发完成、失败和待审批通知。确认去重、关闭、退出登录以及点击后重读原会话。通知不包含正文，旧通知不能批准新请求。页面内提示、模拟推送及窄视口均不能证明系统后台送达。

### Git、Fork 与 GitHub

在专用仓库创建独立 worktree，确认执行位置、脏目录保护与清理边界。原生 Fork 核对上下文截止点和代码基线；Agent 不支持时明确拒绝。GitHub 读取核对真实仓库授权、fork PR 两侧和精确 SHA 的 CI，撤权后清空不可访问内容。

外部写入由操作者在专用仓库明确开启，并审阅最终评论、补丁、提交文件与目标分支后执行；未知结果只核查原操作，不自动重发。测试推送、评论和 PR 行为需要具体授权，自动化合成 HTTP 响应不代表真实 GitHub 验收通过。

### CLI

使用最终安装包中的 CLI，在本机和普通远程连接完成登录、目标选择、创建、发送/等待、停止、整理和原操作核查；另一访问端读取同一历史。确认正文和登录资料经 stdin/文件输入，凭据不回显。超时或 Ctrl-C 不隐式停止任务；重启保留原请求，不自动重试。v4/secure 命令只验收明确拒绝及离线只读归档，不执行已删除的加密步骤。

### Agent 选项、Skills 与共享队列

使用实际支持的 Agent 版本核对模型、推理强度、权限、能力刷新和旧会话恢复；未报告的能力不能用推测值填充。Skills 加入草稿后仍需明确发送，已冻结文本不随原文件变化。共享任务的输入/授权、认领、撤销与重连行为单独验收；旧角色、旧父子任务、网页预览和逐回合额外 MCP 只检查历史保留与新增请求拒绝。

### PWA 更新与发布

iPhone 验证添加主屏幕、前后台、键盘、选择/下载文件、离线 shell 与版本更新交接。旧页面关闭前不混用新旧资源，身份接口不被 shell 缓存替代。窄屏 Chromium 不代替 Safari。

最终 Mac 包验证干净设备首次打开、升级数据保留、第三方许可、Developer ID、签名、公证和证书信任，见[macOS 发布](mac-release.md)。ad-hoc 签名只证明测试包完整性。Relay 发布按[部署说明](../deploy/README.md)核对固定输入、程序白名单、数据卷保留与失败恢复。

## 结果记录

每项记录“通过 / 失败 / 未执行”、版本与环境、执行入口、可复现的脱敏现象和剩余限制。新代码或新包需要重新验证相关流程，不继承旧阶段的数量或结论。日志、截图、私有数据库、会话正文、凭据与内部任务记录不提交到仓库；文档保留操作步骤和可复用结论即可。
