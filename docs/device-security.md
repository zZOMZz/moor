# 旧设备安全材料

旧设备建根、配对、换钥、撤销、恢复和公开信任分发命令已经退场。当前包不提供 `security.mjs`；历史命令不能用于管理当前普通连接，也不能证明启用了端到端加密。当前范围见[加密退场](end-to-end-encryption-deferral.md)。

## 保留与归档

已有端点文件、恢复码、恢复包、信任版本和 Host journal 保持原内容。升级、启动和普通登录不重新签名、不删除、不重放原操作，也不自动把旧连接转换到 v3。需要归档时完整备份私有目录；不要将材料放进项目、共享会话或分发包。

旧 CLI 原记录仍保存在原状态目录的 `secure_outbox` 与 `secure_catalog_outbox`；使用[CLI 离线归档](cli.md#退场数据的离线归档)读取原编号和已存状态。浏览器旧记录使用[只读检查与导出](browser-client.md)。导出不是主机送达确认，结果未知的请求仍然未知。

## 当前设备管理

普通连接通过账号配对和授权连接访问执行电脑，使用[个人登录与账号恢复](google-login.md)的现行流程。登录身份、设备授权、传输 TLS 与端到端加密是不同边界；不要使用旧加密材料推断当前账号或主机权限。

合成验证见[入口拒绝与数据保留](../tests/integration/retired-e2ee.test.ts)；最终版本的升级及设备行为仍按[设备验收](validation.md)核对。
