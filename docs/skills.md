# Skills 发现与引用

会话输入栏的 **Skills** 按钮可以发现并查看当前执行目录中的 Skill 文件，以及执行电脑上明确登记的全局目录。选择“将说明加入本次指令”后，完整说明、来源、相对路径和内容版本进入可编辑草稿；仍需用户手动发送。

打开列表、查看正文和保存引用不会创建 Agent 会话、执行脚本或安装 Skill。Moor 的文件发现与 Agent 原生启用状态分别处理：当前 ACP 没有统一的 Skills 启用接口，读取了文件不能证明 Agent 已加载相同版本。

## 项目与全局来源

项目内检查以下三个容器，分别展示，不按同名覆盖：

| 相对当前执行目录 | 含义                                               |
| ---------------- | -------------------------------------------------- |
| `.agents/skills` | 通用项目 Skills 约定                               |
| `.claude/skills` | Claude 项目目录约定                                |
| `.codex/skills`  | Moor 保留的兼容发现入口，不据此声明 Codex 原生支持 |

例如 `.agents/skills/review/SKILL.md`。读取以当前会话实际执行目录为边界；worktree 使用自己的目录，不沿父目录、原项目目录或其他电脑补查。不存在的容器会显示“目录不存在”。来源根目录本身的 `SKILL.md` 不作为一项 Skill，文件应放在子目录中。

全局目录不会从用户主目录自动猜测或扫描。先在执行电脑打开 **Moor → 连接设置 → Skills 全局目录**，选择明确的 Skills 容器目录，填写名称并勾选允许读取，再保存。默认未启用，包括修改已有登记时。可登记例如操作者实际使用的 `~/.agents/skills` 或 `~/.claude/skills` 的绝对目录；目录是否被某个 Agent 原生识别，仍由其配置和版本决定。

全局授权适用于当前主机身份可访问的项目会话，最多 20 个根目录。登记名称、编号和内容版本可以出现在远端，绝对路径仅在本机配置中。停用、删除或替换目录会使旧列表和详情失效；重新启用会产生新版本，不恢复旧请求授权。

## 阅读和加入指令

1. 在新会话或已有会话打开 Skills，按名称、说明或相对路径搜索。
2. 核对项目/全局来源。同名条目会明确标记并分别保留。
3. 选择条目查看完整 `SKILL.md`。常见简单 YAML 名称和说明用于列表展示；不支持的元数据格式以目录名显示，原文仍可查看。
4. 点击“将说明加入本次指令”。Moor 重新核对来源、执行目录和原正文版本，再把冻结说明追加到最新输入末尾。原草稿保留，用户可继续编辑；其他页面同时修改时会报告冲突。
5. 检查最终指令，手动发送。之后遵循普通会话送达规则：待确认请求保留原编号和原正文，刷新与重连不自动执行。

引用兼容 Agent 的普通文本输入。附带的 `scripts/`、`references/`、图片或其他资源不会自动读取、上传或执行，也不承诺相对资源可用；需要时由用户在既有文件/附件流程中明确提供。Skill 正文中的 shell 插值、HTML 和远程图片作为文本展示，Moor 不评估其中的代码，也不自动打开链接。

Agent 实际报告的命令仍在“命令、计划与用量”面板中。Codex 上报的 `$skill` 保留 `$`；已有 `/` 前缀原样保留，普通命令如 `review` 填入 `/review`。它们只填入草稿，不绕过手动发送，也不能证明某个磁盘文件的版本已被原生 Agent 使用。

## 本机 CLI 配置

先明确退出持有该主机数据库的 Moor 实例，再用原数据路径执行：

```sh
node dist/bridge.mjs \
  --config /absolute/private-moor/bridge-v3.json \
  --runtime-data /absolute/private-moor/runtime-v1.sqlite \
  --skills-config-stdin <<'JSON'
{"action":"read"}
JSON
```

读取返回 `revision` 和 `sources`。每条本机登记包含 `id`、`label`、`rootPath`、`enabled` 和目录身份是否仍有效的 `current`。提交下列动作时使用刚读取的版本：

```json
{
  "action": "source-save",
  "expectedRevision": 0,
  "label": "个人 Skills",
  "rootPath": "/absolute/my-skills",
  "enabled": true
}
```

修改时加原 `id`；省略 `enabled` 会停用。`source-enabled` 接收 `expectedRevision`、`id`、`enabled`，`source-remove` 接收 `expectedRevision`、`id`。响应丢失或版本冲突后先读取，不自动重试。stdin 一次一个 JSON，最多 16 KiB；退出码 `0` 成功、`1` 输入或配置失败、`3` 主机锁不可用。不能与桌面、配对或其他配置命令同时运行。

## 读取与保存边界

- 只读取注册容器下最多 4 层子目录中的普通 `SKILL.md`，不跟随符号链接，不读取 FIFO、设备文件或外部引用。每次发现合计最多 2,000 个目录项、200 个 Skill，每份正文最多 64 KiB，必须是有效 UTF-8 且不含 NUL。最多显示 100 条读取问题，超限和不完整目录明确标记；主机同时最多处理 2 次 Skills 读取，繁忙时需稍后手动重试。
- 主机在读取前后核对归属、执行目录、来源授权及可观察的目录/文件身份变化。便携 Node 文件接口没有原子的 `openat2` 边界，不能防御恶意本机进程在检查间反复替换再还原祖先目录；这不等于系统文件沙箱。
- 本机 `skills-v1.json` 在主机数据库旁以 `0600` 原子保存，配置目录必须位于项目和 worktree 外。全局来源不能包含 Moor 私有数据目录，也不能位于其中；自动项目文件、快照和手动读取保留该配置文件名及 `.tmp-*` 变体，大小写不敏感。
- 主机和中转不持久保存发现到的正文，远端接口不接收目录路径、启动命令或配置写入。中转只转发类型化读取；HTTPS/WSS 尚无额外端到端加密，转发进程可看到返回正文。
- 列表和详情只在页面内存，关闭面板、切换目标或离线会清除。明确加入指令后，冻结说明进入普通本地草稿；手动发送并确认后进入主机会话历史。后续修改文件或撤销目录授权不会删除用户已保存的草稿和历史。

安装、编辑、同步 Skills 与原生激活属于后续独立范围。本批只用合成目录和 Agent 验证；真实 Agent、双 Mac、iPhone/Safari/PWA 与最终安装包仍需[专项验收](validation.md)。
