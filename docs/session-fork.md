# 原生会话 Fork

Fork 在同一执行电脑和项目中创建独立的 Agent 原生会话。Moor 会话记录来源和截止范围，新会话正文从空历史开始；来源历史通过链接查看，旧审批、问题和工具调用不会成为新会话中的待执行操作。

## 选择上下文与目录

从会话入口或已完成回合打开 Fork 面板，读取执行电脑确认的能力，再选择上下文和目录，手动创建。

| 选择                   | 含义                                                                         |
| ---------------------- | ---------------------------------------------------------------------------- |
| Agent 当前保存的上下文 | 使用原生 Agent 保存的当前状态，不承诺等于某个旧 Moor 回合                    |
| 指定已完成回合         | 只开放主机保存了原生完成锚点的回合；旧历史没有锚点时不可选择，不根据文本推断 |
| 原目录                 | 子会话与来源使用同一目录，看到相同未提交文件；修改会互相可见                 |
| 独立 worktree          | 从面板中明确选择的本地分支及提交创建新分支和目录，不复制来源未提交文件       |

上下文截止点与代码基线分别选择。旧回合的 Agent 上下文不代表 Git 自动回到当时的文件状态；创建前应核对两者是否适合本次工作。原生 Fork 不发送新 prompt，也不切换或改写来源会话的执行目录。

来源必须空闲、结果已经保存，并保有可验证的原生会话及执行绑定。主机在原生调用前重新检查来源版本与目标目录，期间变化会阻止创建。清理或脱离目录后的来源仍可读历史，但不能继续执行或 Fork。

## Agent 支持范围

能力来自实际 ACP 协商，并与锁定适配器匹配。当前支持 Codex ACP `1.11.0` 和 Claude Agent ACP `0.76.0`；自定义 ACP、版本不符或未报告原生 Fork/加载能力的 Agent 不开放创建。

Codex 使用原生 Fork 的目标目录和回合截止参数。Claude 先在来源目录创建原生子会话，再加载返回的子会话到目标目录。指定回合的原生消息编号只保存在执行主机，通过适配器实际支持的截止扩展传递；浏览器与中转不接收原生会话编号或消息编号。

Moor 不读取其他应用数据库，不复制 Moor 历史文本作为新 prompt，也不跨电脑迁移 Agent 上下文。Agent 自己持有的原生内容与登录状态仍由该 Agent 管理。

## 确认、失败与手动恢复

访问端先持久保存来源、子会话编号、截止范围、目录计划和 operationId。主机再持久保存操作阶段；只有原生子会话与执行绑定均已确认并保存后，页面才打开子会话。关闭面板、刷新或重连不会自动 Fork。

手动重试沿用原操作编号和原参数。原请求尚未到达主机时，重试可能首次提交；主机已进入原生 Fork 后不再次调用创建。若原生返回丢失且没有保存子会话编号，结果保持待确认，不能猜测编号或重新创建。若编号已经持久保存，恢复只针对该子会话完成加载和本地确认。

独立目录已创建但原生 Fork 被明确拒绝时，面板保留该子会话的目录入口，可手动清理。尚不能确定原生结果时，目录继续保留，禁止继续发送或清理。客户端保留最多 20 份尚需处理的失败目录记录；达到上限时先整理目录，再发起新的 Fork。清理目录不会删除分支或提交。

## 共享 worktree 的清理

来源已经使用 Moor 管理的 worktree 时，原目录 Fork 会让多个会话引用同一目录。面板显示引用数量；还有其他引用时，只能手动脱离当前会话，目录和其他会话继续保留。最后一个引用才可在目录干净、会话空闲和状态匹配时移除物理目录。待确认的 Fork 预留也计入引用，不能绕过保护删除目录。

脱离后的会话保留历史、附件和冻结 diff，不能继续发送。需要文件隔离时，应选择独立 worktree Fork。

## 验收与备份

自动验证使用临时仓库、隔离的合成原生记录和合成 ACP，不调用真实账号或模型。实际 Agent 的上下文截止、子会话恢复、文件访问和跨设备交互仍须按[设备验收](validation.md)验证；390px 浏览器视口不代表 iPhone/PWA 验收。

Fork 操作阶段、原生锚点、子会话映射和共享目录引用属于 Moor 主机数据库备份。原生 Agent 内容和代码目录需要操作者分别备份；单独复制 Moor 数据库不能恢复它们。详见[运行与恢复](runtime.md)和[Git 与会话工作目录](git-workspaces.md)。
