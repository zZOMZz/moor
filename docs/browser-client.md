# 浏览器与桌面的统一工作区

Web 和桌面使用同一个 `WorkspaceApp`、`WorkspaceController` 与按记录保存的 `WorkspaceStore`。桌面通过有限原生 IPC 访问执行主机；浏览器使用同源 HTTP。两者共用 `WorkspaceTransportClient` 的目录投影、固定路由、执行范围核对和响应校验，不向页面提供任意 URL、Cookie、shell 或 socket 代理。

原 Web 总控 `app.ts` 和独立加密页面已经退出。账号状态、Google 登录与退出由独立账号组件负责。桌面主窗口不再要求 `moorSecure`，不创建加密连接；`moorWorkspace` 只公开普通工作区、账号、选择本机项目和用户明确触发的历史导出入口。只有一个工作区时直接显示名称；多个工作区仍可筛选，身份字段保持不变。

逻辑项目分组严格限定在同一来源、服务、账号和工作区中，以 `catalogProjectId` 关联副本；名称和目录不参与判断。项目筛选只改变列表范围，多个副本分别显示电脑和目录；最近与置顶条目也显示执行电脑。项目名或电脑名匹配时请求该副本的最近和置顶摘要，每页仍最多 30 项；其他副本继续使用服务器会话标题/编号搜索。查询和加载更多仍使用各自副本的游标与缓存，不读取正文，不改写原目标、草稿或原操作。

原总控使用的 `show*` 插槽包装、Shell、旧导航、附件和会话创建控件一并移除。现用文件面板、问题表单、模型与权限选择直接作为 React 组件测试。附件预览在两端保持相同的正文转义；桌面继续通过原生保存对话框，浏览器显式点击后再次核对已读取内容的摘要，再下载对应 Blob，不会重新执行或上传附件。

普通发送和审批现在冻结 `send-turn` / `respond-permission` 语义请求，由主机生成文档变化；页面不再为新请求构造 Loro 增量或元数据。主机缺少 `session-intents-v1` 时明确要求升级，保留草稿，不回退旧接口。审批保留完整已审阅工具项，刷新不能把旧选择应用到改变后的请求。原操作落盘、附件消费与完成状态仍使用原有事务；确认只清理已发送版本，不清除后来编辑的草稿。旧 Mutation 记录保留原正文和编号，只通过明确操作核查或重试，不转写为新格式。详见[会话语义命令](session-intents.md)和[同步与恢复](sync.md)。

## 电脑连接与分组

“账号与连接”保留添加电脑、读取已连接电脑和撤销授权。点击添加电脑先读取当前账号的远端工作区：一个工作区时直接生成绑定该工作区的配对码，多个工作区时需选择并确认生成；没有工作区时使用默认配对入口。同账号、同服务下已选择的远端工作区可以预选，本机或其他账号的工作区不能用于预选。账号或页面在读取期间改变时停止后续派发。撤销授权需要明确确认。所有管理请求携带当前核验的账号，服务器在读取请求体后再次核对账号，避免页面停留期间切换登录状态而写入另一账号。

“高级分组管理”保留创建和重命名工作区、电脑归属、创建项目分组和本地副本归组。项目可记录 Git 来源地址；这是描述元数据，不会克隆仓库或连接 Git 服务。移动电脑和调整副本归组前，客户端只读检查所有受影响的本机范围，包含当前没有打开的会话。未发送正文、附件、待确认原操作、GitHub/待办草稿和协作未完成记录会阻止调整。正在查看的范围也必须先结束查看；检查期间关闭管理页面会取消尚未发出的更改。读取失败、数据身份不符或超过 100,000 个键 / 16 MiB 的检查预算均保留原状态并停止调整。

已成功更改的目录只触发只读刷新。管理写入结果不明时不自动重试，用户应重新读取目录或电脑列表核对。检查不会清空草稿、封存原操作或把旧请求改写到新归组。

## 本机数据与离线启动

现有 Electron partition 名称 `persist:moor-secure-client-v1` 是历史存储标识，仍沿用。它同时保存普通工作区数据，不能因代码重命名而更换或清理。普通账本、草稿与缓存的数据库名和键保持原样；canonical JSON 的规范化算法已原样移至协议包。

浏览器保存最后使用的账号、已验证目录和选择位置。缓存目录可以先于网络响应显示，但所有目标都标记离线，缓存不授予执行权限。收到新的身份结果后，账号变化会关闭旧工作区；确认退出会清除本机账号选择标记，不删除会话或原操作。

退出请求绑定用户已核验的账号；等待草稿保存或账号检查期间切换登录，旧页面不能退出新账号。Relay 只撤销该请求携带的登录令牌，不在退出响应中无条件发送删除 Cookie 的指令，避免晚到响应清除另一页面刚建立的登录。浏览器保留的失效 Cookie 不再代表身份，`/api/me` 会返回匿名；浏览器再次确认匿名后才清除本机账号提示。桌面继续保留 Google 写入屏障，在主进程核对账号与原 Cookie 后删除；CLI 使用固定私有令牌，不读取浏览器环境 Cookie。

只有网络中断或 Host 不可达时才恢复同账号、同 origin 的目录及会话列表。401、403、身份变化、范围不匹配或不可验证响应不会回退为成功。已确认的会话快照和草稿可离线阅读；读取缓存不会伪造主机确认、检查或重试原操作。WebSocket 只提供变更提示，连接恢复仍是只读补读。

## 旧网页记录

旧 Web 的 `moor-runtime-v1/cache` 保留不变。已知目录和会话快照可作为离线历史读取。普通草稿和待确认 Mutation 的复制要求：当前账号已认证、目录唯一映射到原执行范围、原 Host 重新确认同一会话及 Agent 绑定。原操作编号和完整增量保持不变，复制不会发送、检查、重试或封存请求。

会话整理请求另外校验原账号、设备、工作区与副本。新账本已有编辑时不覆盖草稿；复制标记只在所需写入成功后保存，失败可按原编号重复复制。旧记录不会被删除。缺少完整身份或已退场功能的特殊请求不猜测转换，保留原记录并提示从账号面板读取和导出。

## 已退场的加密记录

“账号与连接 → 历史本机数据”提供明确触发的只读检查及 JSON 导出。检查只读取当前应用原有 IndexedDB，不创建不存在的加密库，不加载加密控制器，也不会连接 Host。导出保持原键与值，结果待确认的记录仍保留原状态；导出不是执行结果证明。

单次检查最多 10,000 条、96 MiB；超过预算时保留数据并报告无法完成。桌面导出必须经过原生保存对话框，写入用户选定的文件，页面不能指定路径。设备端点、密钥材料及 Host journal 不会因为此入口而删除或改写；CLI 的旧记录处理见对应 CLI 文档。

## 验证范围

合成测试覆盖 Node/Browser 共用固定路由、身份替换拒绝、缓存不授权、401 不回退、旧请求在 Host 确认后保持原编号复制、无法转换的记录保留、浏览器离线重开，以及普通工作区的输入、审批、Git、文件和 GitHub 交互。账号面板测试覆盖配对、撤销确认、名称和 Git 来源管理、归组取消、未知结果不重试及异步检查后的页面状态重验；存储测试验证其他会话的草稿、原操作、附件和待办不会被跨范围调整绕过。JSON 准入、原生账号 Cookie 屏障和 IndexedDB 锁测试继续独立保留。

构建 Web 后，可运行 `pnpm test:e2e`。该脚本使用实际 Chromium、IndexedDB 和临时配置，对本机合成 API 验证在线打开会话、草稿事务落盘、结束查看后原草稿仍阻止副本归组、离线重开保持草稿且发送禁用、401 返回登录，以及全程没有发送执行请求或归组写入。测试等待 DOM 和数据库事务信号，不使用睡眠猜测完成时间。

这些结果不等于真实账号、多设备、手机 PWA 或正式签名安装包验收。

`pnpm test:e2e` 独立构建临时夹具，验证单工作区入口、现代分页摘要、跨电脑项目归组、筛选不改变当前会话、点击保留精确副本、电脑名搜索及桌面/窄屏布局。React 回归同时验证同名项目跨来源/账号/服务/工作区不合并，以及本机工作区不参与远端配对。
