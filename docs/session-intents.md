# 会话业务意图与原操作兼容

新的普通指令和权限决定使用有限业务命令：`send-turn` 与 `respond-permission`。客户端不再为这些新请求创建 CRDT 增量；执行主机验证输入后生成 Moor 会话操作。会话格式仍为 v1，桥接协议仍为 v3，历史与下行增量同步保持兼容。

## 请求边界

两种请求都携带 `intentVersion: 1`、原 `operationId`、执行工作区、用户、机器、本地项目和会话。这里的 `workspaceId` 保持既有协议中执行工作区的含义。账号、设备和产品目录映射由受认证的有限传输边界另外绑定，不接受正文自行声明访问权限。

| 命令                 | 允许表达的输入                                                                              | Host 另外验证的条件                                                              |
| -------------------- | ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `send-turn`          | 预期上一用户回合、固定 Agent 版本、新用户回合编号、文本、模型/推理/权限选择、已上传附件引用 | 主机已确认会话、原执行范围、空闲状态、有效选项、附件归属与输入能力、未结算原操作 |
| `respond-permission` | 原用户回合、请求编号、已审阅助手回合及完整工具项、选择或取消                                | 唯一且仍活动的原请求、工具项未变化、选项属于原请求、实时审批回调仍有效           |

新命令不接受 `update`、`metaBundle`、历史列表、执行状态、客户端时间戳、任意启动配置或退场的 MCP/子任务扩展。Host 自己填写时间戳、用户回合状态与助手回合。新用户回合不能复用历史回合编号；审批不能顺带修改工具内容或其他会话字段。

请求只走现有受授权副本下面的两个固定 POST 路由，受 1 MiB 请求和 64 KiB 回执上限约束。审批工具项另受 256 KiB UTF-8 和结构预算限制。只有报告 `session-intents-v1` 的 Host 才能接收；缺少能力时提示升级，不自动退回 Mutation。元数据整理继续使用已有的窄 `session-action` 命令。

## 共用接受与回执

旧 Mutation 先经过完整增量差分校验，新业务命令由 Host 按允许的字段生成候选文档；之后都进入同一个会话串行接受路径：

1. 核对当前连接、执行范围、原编号及冻结请求；已有终态原操作直接返回原回执。
2. 核对 Agent、执行目录、附件、活动回合和业务条件，准备候选文档。
3. 同一 SQLite 事务保存原操作凭据、会话、元数据索引、Agent 绑定和附件引用；审批同时结算对应通知与待办。
4. 提交后才交给 Agent 或回应原审批回调。提交失败不能先产生执行效果。

业务命令不新增独立 journal 或第二份确认权威，仍使用原 `operation` 表。新 DTO 的指纹按版本化 canonical JSON 计算，绑定完整原输入与适用的授权上下文；字段键序变化不改变语义。同编号不同内容、跨会话或跨命令碰撞会被拒绝。指纹不依赖 Host 临时生成的 CRDT 操作、时间戳或助手编号。

快照与检查点仍比较原读取的持久版本。候选分支上更大的 CRDT 计数不能覆盖已提交的输出，详见[流式持久化](runtime.md#流式输出的持久化)。接受回执表示主机已经保存并接受输入，不代表 Agent 已完成任务。

## 升级与未知结果

客户端为新的两种请求增加显式原操作类型，仍在派发前保存原请求，并使用已有 `session-operations` 进行手动检查或放弃。恢复也需要新能力；不能把新请求改成旧增量或换一台电脑重试。放弃尚未接受的原请求会保留原编号，迟到请求不能再执行；已接受的决定不会因放弃而撤回。

旧 Mutation 的原 body、operation ID、目标、指纹算法和保存状态保持不变。升级、启动和重连不转换或重放它们；用户手动重试仍发送原字节。CLI 已保存的路径和请求摘要也不迁写。Host 已接受的旧原编号继续返回历史回执。

Host 无法区分“升级前只保存在客户端、从未到达主机的 pending Mutation”和“新构造的同形 Mutation”。因此本轮保留严格的兼容入口，不能声称关闭了全部原始增量上行。将来若完全关闭该入口，必须另行决定未到达旧请求的处置方式，不能在代码整理时暗中改变恢复政策。

草稿只保存在访问端，不因恢复连接自动执行。新共享 TaskDoc 的明确提交仍遵循自己的冻结授权、重连同步与队列政策；其 Host 内部兼容命令复用同一接受路径，不把普通未知命令自动升级成排队任务。旧父子任务执行已经退场，不再新增一套接受基础设施。

## 验证与限制

[协议与客户端回归](../packages/protocol/tests/session-intent.test.ts)检查未知字段、冻结输入和完整审阅；[实际 Host 回归](../tests/integration/session-intents.test.ts)覆盖原编号并发、跨请求碰撞、响应丢失、重启、事务失败、附件范围、精确审批与迟到请求。[固定路由回归](../tests/integration/host-command-routes.test.ts)使用真实 Relay，检查当前能力、响应身份和撤权后的结果。

测试使用合成数据、确定性故障信号和合成 Agent；结果不代表真实账号、双 Mac、iPhone 或正式签名验收。整合检查及待验收事项见[改造与验收依据](design-improvements.md)。
