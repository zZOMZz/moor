# 端到端加密：M6.2 实现进展

当前已提供设备信任、配对与恢复、公开签名版本分发，以及显式启用的 **v4 加密主机、`secure` 会话 CLI 和桌面“加密工作区”**。这条链路把目录、命令及主机响应在两个端点之间加密，中转只转发密文。新桌面入口支持设备配对、核心会话、精确权限审批、项目文件与历史 diff、附件草稿和预览保存、Skills 阅读引用、逐回合额外 MCP、GitHub 读取与审阅写入、网页预览和标注，以及 Git/worktree 与原生 Fork；“我的所有电脑”、Web/PWA 和普通会话 CLI 仍使用明文桥接 v3。组织修改、完整设备管理、可信 PWA、加密 watch 和通知等仍需继续迁移，M6.2 尚未完成。Google 登录、TLS 和中转不保存会话正文，都不能替代端到端加密。

## 已实现的边界

设备使用 P-256 加密密钥。消息采用固定的 HPKE Auth P-256／HKDF-SHA256／AES-256-GCM，每条消息建立独立上下文。实现锁定 `@hpke/core 1.9.0`，使用 WebCrypto；协议依据为 [RFC 9180](https://www.rfc-editor.org/rfc/rfc9180.html)，实现与支持范围见 [hpke-js](https://github.com/dajiaji/hpke-js)。该库未经过正式安全审计；当前选择不承诺长期设备私钥泄露后的前向保密。

账号信任根用独立 ES256 密钥签署设备清单，绑定账号、中转 origin、根指纹、设备编号、公钥及客户端/执行主机角色。根公钥必须来自用户明确核对的配对或恢复步骤，不能根据 Google 登录或中转返回的公钥自动替换。清单只含公开身份，不含密钥私有部分、设备名称、项目路径或会话内容。

清单带有递增 epoch 和前一版本摘要。普通信任更新拒绝其他根、其他账号、其他 origin、回滚、跳过版本和同版本不同内容；重读同一版本保持幂等。离线设备需要依次核对缺失的签名版本。显式配对可用根签名将新设备加入非初始版本；恢复另需用户选择公开基准。根管理和公开版本分发已接通明确的 CLI 动作；桌面配对已接通，建根、批准、撤销、换钥、同步与恢复管理仍使用 CLI。

Node 端点提供独立的信任锚存储：目录须仅当前用户可访问，数据库及锁文件为私有普通文件；禁止符号链接、硬链接、意外数据库类型和路径替换。它保存公开签名状态与本机防回滚检查点，不保存设备或根私钥。更新先验证、再持久化、最后替换内存状态；并发更新不能覆盖已安装的新版本。没有自动清空或重新配对入口。此保护以端点存储可信为前提，不能检测整个本机数据目录被离线还原到旧备份。

每个加密通道绑定账号、中转、双端设备与密钥、信任版本摘要、主机连接挑战和客户端挑战。每条消息另外绑定方向、类型、请求编号、序号、工作区、项目和会话；产品工作区/副本编号同时提供或同时为空。目录读取单独使用账号与设备范围，不能借空项目范围执行普通主机命令。`resource.projectId` 指执行主机的 `localProjectId`。

通道在解密前预留序号，认证成功后才更新有限重放窗口，最多同时处理 64 条记录。并发副本、过期序号、篡改和旧连接挑战被拒绝；消息乱序不要求自动重发。关闭原连接或安装另一信任版本后，尚在加解密的结果也不能继续投递。v4 主机在异步建钥前保留唯一通道位置，最多 64 个活动通道、每条底层连接 256 个累计挑战组合；已关闭组合留下记录，不能重建接收器清空防重放状态。主机重启必须产生新挑战。

原 38 类主机操作已归入共同的严格校验与分发入口。加密适配器在解密后再次匹配工作区、项目、会话和恢复请求范围，保留原 operationId、主机 journal、精确回合审批、MCP 和有限任务约束。MCP/任务授权中的账号、执行设备、客户端密钥和通道来自验证后的绑定，不接受正文注入。成功结果和错误都进入密文响应；适配器不会因为加密成功而生成“主机已确认”回执。同一主机的通道必须复用共同分发器；其 64 个名额一直保留到主机处理和响应加密结束，超限直接拒绝，不建立等待队列。

已经进入主机处理的操作可能在撤销后完成，结果不再投递给旧通道。撤销不是对文件或外部服务动作的回滚；未知结果仍须手动查询或重试原编号。加密模块不保存执行队列，不在重连后自动发送。

48 MiB 明文连同认证标签最多编码为 67,108,886 个 base64url 字符。记录上限为 67,141,654 字节，v4 WebSocket 外层另外预留 2,048 字节。中转同时最多 256 个连接，每账号最多 64 个主机和 64 个客户端，全局最多 64 个未完成请求；请求名额、待处理字节和发送队列均有限制。消息、心跳与 ping/pong 回复共同最多保留每连接 128 个、全局 1,024 个未完成写回调的帧，完成或关闭后释放，避免空控制帧堆积大量小写请求。

入站另有所有账号、主机和客户端共同使用的 134,287,404 字节预算。接收器在 WebSocket 组装之前检查帧头，按声明的完整载荷加每帧 256 字节开销预留；预算不足时立即关闭该连接，不等待正文或排队。握手消息最多 16 KiB，每条消息最多 1,024 个数据分片，从首字节起最多 30 秒；控制帧或持续少量发送不会延长未完成消息的期限。配额保留到整条消息处理结束，关闭、错误或超时会释放。

TCP 载荷以最多 64 KiB 的独立块交给 WebSocket 接收器，避免逐字节送达造成大量小 Buffer，也避免小分片长期引用无关的大缓冲区。此预算限制保留的入站消息及分片，不能等同于进程内存上限：网络流、完整消息拼接、JSON/字符串与发送队列仍有额外内存。协议不接受压缩帧，也没有扩大单条消息上限。

## 显式加密主机与 CLI

`/bridge/v4/host` 和 `/bridge/v4/client` 使用个人账号 Cookie 与精确 Origin；不接收查询字符串凭据或本机连接。握手只含公开设备、根、检查点和挑战。中转列出的主机只是未认证在线提示，客户端必须用本机已安装的根和设备清单验证对端，成功解密目录后才允许执行命令。项目名称、路径、Agent 配置、会话结果和错误都在密文内；中转仍能看见路由编号、消息大小与时序。

当前主机提供版本 2 加密目录，在自身数据库保存产品工作区、逻辑项目及本地副本关系，绑定 origin、账号、信任根和签名主机身份。可以按运行工作区/本地项目或 `--space/--replica` 选择目标；两种方式都必须解析到主机确认的同一副本。中转旧目录、相同名称或相同路径不会自动成为可信映射，跨主机目录也不会按名称合并。

新业务请求在密文中固定逻辑项目、副本和映射版本，并与 AAD 中的运行工作区、本地项目、会话及产品范围一起核对。主机处理至响应加密结束期间持有映射租约，组织调整不能跨过正在执行的命令；运行项目被移除、路径或执行身份改变后，迟到成功和错误均不再返回。客户端拒绝连接内目录版本回退、产品版本回滚，以及目录刷新后的旧请求结果。

`secure-turn-authority-v1` 将一次 RPC 的映射租约与整个回合的执行授权分开。回执发出后释放 RPC 租约，仍有效的 MCP 和任务授权继续核对原客户端通道、产品映射与运行身份；不能因为一次请求结束而误判回合已失去授权，也不能借释放租约忽略后续映射变化。单个客户端断开、信任变化、目录调整或运行实例变化会触发相应授权重新核查，失效回合请求取消并关闭 Agent；其他客户端仍有效的回合保留。已经发生的文件或外部服务动作不会因此回滚。

`secure organize` 支持创建/重命名工作区、创建逻辑项目、分配副本及移动主机的组织归属。动作携带明确的预期版本，先保存到独立私有 outbox，再由主机事务保存目录与原回执；丢回执后只能手动核查、重试或封存原动作。这些动作不搬运文件、不转交执行所有权，也不构成跨主机迁移。

主机另存业务原操作的范围凭据，不能将它当作送达回执。组织调整后的恢复优先核对已保存的精确原请求凭据，且原运行实例、路径、用户和电脑没有改变。仅引用任务编号的核查/封存仍要求当前映射及原任务授权。旧目录版本 1 保留兼容；新版主机只为旧无映射会话操作提供显式核查/封存入口，不会给它补造产品归属。

主机还持久保存自己已发布的完整映射历史。严格 `session-operations` 包装中携带的原会话控制、指令/审批、元数据或附件请求尚未到达主机、随后映射变化时，只有主机留有原映射证据，且运行实例、路径、用户、电脑及运行代次均未改变，才可核查或封存原请求。它不执行原正文，也不允许旧请求借历史映射重新执行；会话归属、原操作和审批审阅的校验仍保留。已有范围凭据必须精确匹配，不能被历史记录替换。升级前未保存的映射不能从客户端正文补造；缺少证据的旧请求继续保持待确认。仅带任务编号的恢复不适用此例外。

客户端为全部 40 类解密响应分别校验 schema、范围、固定 Agent 版本、原操作、分页、文件/附件/历史哈希及预览内容，再允许返回或保存。可信主机明确拒绝与中转断开、超时、不可解密响应分别处理；未知结果不能成为送达或拒绝回执。

`secure` CLI 支持目录与组织调整、会话创建/读取/发送/停止、MCP 读取、会话整理及原操作查询/重试/封存。原请求及产品映射先写入独立私有操作表，与旧 HTTP 操作分开；换账号、换设备不能继续投递，同一运行会话的待确认操作也不能通过改变产品映射绕过。离线不发送，不自动连接后重放；丢失回执后手动重试使用原编号、正文和目标，主机 journal 保证已接受操作不再执行。用法见[加密 CLI](cli.md#显式加密连接)。

新的普通文字与 MCP 指令记录都保存 `userTurnId`，与原正文、目标和可选 MCP 审阅一起纳入摘要。带网页标注的指令还保存完整 `previewReview`，绑定原标注版本与选择编号，不能在恢复时改用当前标注。升级前没有此精确回合绑定的旧待确认 `turn`，包括普通文字指令，只能手动核查或封存，不能重发或从最新历史猜测回合。已接受的旧记录仍可读取原回执，不会重新执行；旧摘要格式继续可读。

每次 CLI 命令建立独立连接。选中额外 MCP 的 `secure send` 会先持久保存接受回执，再保留原授权连接，前台只读等待原操作明确绑定的用户回合及其助手回合结束；有完整绑定的待确认 MCP 原操作经手动重试接受后，也按同样规则等待。默认持续等待，只有明确提供 `--timeout MS` 才限时，支持 Ctrl-C 退出。等待期间不再发送原指令，超时、退出或断线保留已接受的记录并请求撤销该连接的回合授权；成功回执与执行结果分别报告。其他命令结束即关闭连接，常规 watch 和通知仍待接入。主机连接断开后需操作者重新启动，不自动降级或重连。主机运行期间独占设备与连接文件，配对、同步、换钥或撤销需先停主机、执行明确的设备安全命令，再启动新连接。执行 Host 在线设置的单一端点持有者仍待接入。

## 本机设备管理与恢复

[设备安全命令](device-security.md)共 15 个动作。原有建根、配对、续期、换钥、撤销、单版本安装及恢复等 12 个动作保持离线；新增 `read-publications` 也只读本机。`publish-trust` 和 `sync-trust` 明确访问固定中转公开信任接口，不连接执行主机或启动 Agent，不改变当前远程会话的加密状态。

设备私钥保存在当前用户的私有普通文件中，目录须为 `0700`、文件为 `0600`，禁止符号链接、硬链接与路径替换；这不是 Keychain 或磁盘加密。文件更新使用进程独占锁、本机 revision 条件和临时文件写入、同步、原子替换。写入结果不明时要求重新读取，不能声称失败即未写入。设备私钥不进入公开状态输出或签名清单。

本机文件读取、快照、Skills、附件以及 Agent 内容入口拒绝完整带 `moor-private-endpoint-v1` 标识的私有文档；任意改名或复制仍受此检查，`.moor-security` 目录及其内部项目根也被排除。这能防止 Moor 私有文件误入普通共享路径，不能识别拆分片段、人为去掉标识或任意凭据文本，也不会追溯清除已有历史。

根私钥只以加密恢复包保存在端点文件，管理动作每次用单独保存的随机 256 位恢复码解锁。恢复包采用固定 JWE `dir`／`A256GCM`，校验根私钥与公钥一致、根指纹、账号、origin 和精确签名检查点。恢复码不保存在端点文件；导出只写入新的私有文件，不在终端输出包或恢复码。恢复包不包含旧设备私钥、会话历史、Agent 凭据或登录 cookie。

新配对请求有效期为 10 分钟，包含随机编号、完整根 pin、设备公钥和角色。批准需要在另一可信设备核对完整指纹、解锁根密钥，并明确提供原设备 keyId 或确认是新设备。签名清单、批准回执和更新的恢复包一次持久化后才返回；同一未过期请求的手动重试返回原回执，不另发授权。过期请求只能手动续期，生成新编号后重新核对。换钥时先保留当前私钥，接受精确批准才替换；已撤销端点不能发起换钥。

恢复要求新的端点文件、独立恢复码、加密恢复包、事先核对的根 pin、明确的公开信任基准和逐个指定的撤销设备/keyId。新设备生成新的加密私钥与 ID，拒绝复用当前基准或备份中已知的设备 ID。恢复生成基准的下一签名版本，再由其他端点明确安装。基准不能低于备份，也不能与备份同版本分叉；这不能证明用户选择了所有设备中的最新版本。旧基准产生的分叉会被已安装新状态的端点拒绝，不能通过重置端点绕过。

设备撤销不等于撤销根管理能力：同时持有有效恢复包和恢复码的人仍可管理信任根。当前不提供根密钥轮换，也不承诺恢复码泄露后的根失陷修复。恢复材料应与日常端点及项目分开保管；本机恶意进程和拥有文件权限的 Agent 不在此文件边界的保护范围内。

## 公开信任版本分发

首台设备把 genesis 与初始化状态同次持久化；批准、撤销将原签名清单、恢复包、批准回执和待发布版本一并提交。恢复端点只保存本次新签署的版本。每个本机端点最多积累 16 个待发布版本，满额时新增信任变更整体拒绝，要求用户先明确发布。读取、重启或重连不会自动联网，也不重签待发布内容。

`publish-trust` 只在中转回执与原待发布检查点严格匹配时确认队列前缀。确认更新本机 revision 和记账，不替换已验证的信任对象；丢失或不可验证的回执保留原版本供用户核查后手动重发。旧端点没有队列字段时只保留其实际保存的当前版本，读取不迁移文件，也不补造中间历史。

中转提供 `POST /api/security/trust/publish` 与 `POST /api/security/trust/read`，由个人账号 Cookie 和准确 Origin 授权，禁止本机服务调用及 Bearer 绕过。公开内容仅含账号/origin/根 pin、根公钥、检查点和签名设备清单；没有私钥、恢复码、登录凭据、项目目录或会话正文。每个账号固定一个根，从 genesis 连续保存，最多 4,096 个版本、128 MiB 公开条目；请求和分页响应上限为 1 MiB，每页最多 16 项。登录失效、服务关闭或 origin 变更不能在处理中的异步验证后继续写入。

端点先用私有连接文件核对 `/api/me` 的账号与既有 pin，再从本机检查点读取一页。整个页面逐版本校验后只做一次本机 CAS；错误末项不能部分安装前面版本，远端版本不加入本机待发布队列。`complete:false` 需要用户以更新后的本机 revision 手动取下一页；没有自动翻页或重试。未验证到的 `relayHead` 只是中转提示，即使完整验证到该 head，也不能证明中转没有隐瞒更新。

私有连接由已登录的[会话 CLI](cli.md)通过 `auth export-trust --output` 导出到新文件。Google 登录只提供账号会话，不能授权更换根 pin；使用者仍需独立核对配对指纹和恢复基准。缺失历史必须从保存原材料的可信端点取得，不能用最新清单或重新建根跳过。

## 可信客户端与剩余接线

执行端和客户端必须运行可信代码。如果解密页面仍由可替换内容的中转服务提供，设备密钥与解密正文仍可能被页面代码读走。WebCrypto 也不能弥补应用自身的脚本信任问题，见 [Web Cryptography 安全考虑](https://www.w3.org/TR/webcrypto/#security-considerations)。

菜单及连接设置中的“加密工作区”打开固定 `moor-client://app/remote/`：只快照安装包内的构建资源，无网络回退、任意文件读取、源码映射或 Service Worker；保留 Chromium sandbox、隔离上下文及 CSP。独立浏览器分区不采用旧远程页面的 Cookie、缓存或待确认记录。页面自身不能发 HTTP/WS 请求，业务流量通过主进程的有限 IPC。Google 接续严格区分可信文档与账号服务地址。

业务 IPC 只允许主进程明确登记的可信客户端主 frame，旧 HTTP 页面、子框架和旧文档均无权使用。Cookie 来自主进程持有的 Electron session，身份只从固定 `/api/me` 验证，私钥留在独占端点中；renderer 不能指定网络 URL、请求头、Cookie、文件路径或 socket。页面导航、窗口关闭、服务变更和相关 Cookie 变化会释放旧通道，所有迟到成功及错误都需重新通过原页面代次检查。并发请求有数量和字节配额，不建立待执行队列。

通道仅按明确动作建立，不自动重连或降级。业务调用必须提供已确认且固定的产品映射；中转在线主机列表仍是未认证提示。状态不返回私钥、恢复材料、Cookie 或端点文件路径。界面先在独立 IndexedDB 中持久保存原操作编号、正文、请求摘要与完整执行目标，再发送；刷新、断线和重新连接都不重放。待确认操作阻断同一运行会话的新指令，即使目录映射版本已经改变。发送和封存共用按身份及原编号隔离的 Web Lock，封存先取得锁后，旧页面不能再依据旧快照发送。手动核查、重试和封存保留原映射，不能借刷新目录改绑目标。

首次使用先在独立窗口完成 Google 登录，核对已有可信设备的账号根指纹并生成配对请求；在管理端用[设备安全命令](device-security.md)批准后，把公开批准、根公钥与签名清单填回窗口。续期、取消、接受都使用本机精确版本。首次取消清除待配对密钥并保留递增版本，重开窗口后仍可重新配对，旧批准不能复活。取消不能撤回另一设备已经签发的授权。

配对完成后手动连接，选择主机并核对其加密目录，再选择项目副本。当前支持会话创建、读取、文本及附件发送、精确权限审批、停止、重命名、置顶、归档和原操作恢复；需要手动刷新结果。已读会话断线后可保存本机草稿，发送仍需显式连接。停止先冻结用户看见的活动回合，重新读取后若已被其他回合替换则拒绝。退出先关闭可见会话与通道，等待已开始的 Google Cookie 写入完成后撤销原登录；新的本机 Google 写入在整个退出期间被阻止。

权限审批保存用户实际审阅的完整工具项快照，包括工具输入和原始选项，绑定原用户回合、助手回合及请求编号。发送前重新读取核对；`permissionReview` 将版本、助手回合和最多 256 KiB UTF-8 的完整工具项带到执行主机，主机在接收时再次比较当前内容，拒绝审阅后发生的变化。新审批及其核查、重试和封存都要求原工作区在已认证目录中报告 `permission-review-v1`；旧主机缺少能力时不发送，不省略审阅绑定，也不改用明文接口。原操作账本保存 `permission` 类型、原编号、正文、审阅绑定及产品映射；回执丢失后仍保留待确认，刷新与重连不自动重发。

“取消审批”向原权限请求提交 `cancelled` 结果，仍需主机确认；它不等于停止整个回合。Agent 提供的拒绝选项按该请求的原始选项处理。“封存原操作”则让主机核查并阻止尚未接受的原操作继续执行；如果审批已经接受，核查或重试只返回原回执，不重复决定，也不能撤销已接受的审批。封存结果未知时保留原记录，不能通过重新审阅或更换操作编号绕过。

“项目文件”读取当前项目的文件树与文件，“会话变更”显示主机保存的回合前后基线。历史 diff 不会随当前文件变化而改写；未记录、过滤和超限均保留明确状态。只读请求经过有限加密 IPC，独立缓存绑定账号、根、客户端设备、执行主机、完整产品映射和会话，并校验范围、版本、哈希与分页。离线可手动打开已缓存内容，不发送 IPC；目标或连接变化会关闭原面板，不自动读取。

附件支持本机选择、粘贴、移除草稿，以及历史和工具输出中的完整附件引用。每个附件最多 8 MiB、每条指令最多 8 个；本机选择不上传。“检查附件输入能力”只读取当前会话固定 Agent 的能力，不发送指令。发送在保存文本草稿前固定用户已看到的目标与附件列表，再逐项上传；任何上传结果未知都停止后续上传和指令发送。重新连接不重放，手动恢复原上传也不会接着自动发送指令。

上传、移除及其原操作核查、重试和封存都要求主机同时报告 `attachments-v1` 与 `attachment-operations-v1`。待确认或封存未确认的记录继续阻断同一运行会话的新指令，不能靠切换映射、更换编号或删除草稿绕过。PNG/JPEG/GIF/WebP、纯文本、Markdown 和允许的音频类型支持安全预览；音频不自动播放，HTML、SVG 及其他格式不嵌入页面。保存需用户通过原生对话框选择文件；切换目标、关闭预览或退出会取消未完成保存并丢弃迟到结果。

Skills 通过有限 `skills-read` 方法发现项目和已授权的全局来源，完整说明只在面板内存中显示。加入指令前重新核对来源、正文版本和用户实际审阅的内容，再通过条件写入追加到原会话最新草稿。关闭、断线、切换目标及离开后返回同一目标会让旧读取和待保存操作失效；已经明确加入的文字仍保留在普通草稿中，不自动发送。详细边界见[Skills](skills.md#桌面加密工作区)。

“额外 MCP”只读取安全目录并保存 0–8 个不可变版本；打开面板和保存草稿不启动服务。草稿按完整执行身份隔离，审阅编号与原指令一起持久保存并纳入摘要。发送固定用户看到的目标、附件和 MCP 快照，上传前及最终暂存指令时重新核对目录；过期版本需用户重新审阅。待确认请求不自动重放，确认只消费同一审阅编号，保留后来保存的新草稿；下一回合、Fork 与子任务不自动继承。离线只保留或移除已有版本。读取要求 `session-mcp-v1`，选中服务的新加密发送还要求 `secure-turn-authority-v1`，旧主机不能通过省略检查获得授权。详见[逐回合 MCP](mcp.md#桌面加密工作区)。

GitHub 已复用完整仓库、分支、Issue/PR、评论、精确 SHA 的 CI、PR 文件与行评论读取，以及会话关联和九类审阅写入。有限加密入口要求原功能能力及 `secure-github-authority-v1`；读取正文与补丁只留在面板内存，关闭、断线或目标变化后失效。加入聊天草稿前重新核对用户审阅的正文，再条件追加到原会话最新草稿；写入仍需审查与最终确认。独立存储绑定完整设备身份、产品映射及会话，保留手工草稿、原请求与最小回执；同一运行会话的旧映射记录可以显式核查或封存，不改投当前映射，也不借恢复重新发布。详细边界见[可信 GitHub](github.md#桌面加密工作区)及[审阅写入](github-writes.md#桌面加密工作区)。

网页预览已接通服务与视口选择、连接和关闭、截图、定位、点击、输入、按键、滚动、导航和重载，以及标注保存、编辑、选择、删除与图片查看。有限入口要求 `project-preview-v1` 和 `secure-preview-authority-v1`；实时画面与交互固定原连接授权，断线后不能借新通道恢复旧实例，原操作仅手动核查或关闭。保存标注只写本机；发送前核对用户看到的完整选择，并与原回合、附件和 MCP 共同冻结。主机确认只消费原标注版本及选择编号，其他页面的新选择或编辑保留；PNG 不写入指令文本，用户需另行点击“将截图作为附件”，再按既有附件流程明确发送。见[可信网页预览](preview.md#桌面加密工作区)。

该入口没有替换现有全部界面功能：组织修改、完整设备管理、事件与通知等仍需迁移。桌面客户端与执行 Host 使用各自明确的设备身份和端点文件；Host 仍按[显式加密连接](cli.md#显式加密连接)启动。新窗口不会把默认本机 Host 自动切成 v4，也不会绕过已有端点的独占锁。草稿与原操作是本机缓存，不构成备份或磁盘加密。

当前原操作账本按账号、根和客户端设备隔离，每份最多 512 项、96 MiB，达到上限会拒绝暂存新操作并保持未发送。预览版尚未提供已完成记录的归档与容量管理界面；该项也需在日常使用验收前补齐，不能通过清除待确认记录来恢复发送。

iPhone Safari/PWA 需要独立于中转的可信静态发布来源，并接通跨来源身份接续和设备密钥存储。当前中转同源 PWA 不宣称已经满足此条件。

接下来按以下顺序完成 M6.2：

Git/worktree 与原生 Fork 已接通可信桌面入口。目录操作完整核对展示状态，支持已确认的空会话创建、脏目录保护、共享目录脱离及明确清理；Fork 支持当前或完成回合的原生截止范围、完整方案审阅、来源导航和保留目录处理。`secure-git-operations-v1`、`secure-fork-operations-v1` 将只读核查、明确重试与封存分开；跨映射恢复保留原请求身份，不借核查创建目录或加载 Agent。主机在实际外部派发前核对原连接授权，已派发但不能证明结果的操作继续保护目录。详细使用见[可信 Git](git-workspaces.md#桌面加密工作区)和[可信 Fork](session-fork.md#桌面加密工作区)。

1. 继续迁移桌面的角色、Agent 交互与搜索、任务协作和组织修改界面，补齐完整设备管理、恢复和原操作容量管理，以及可信 Web/PWA 加密接入；复用客户端解密后的完整响应 schema、范围、版本、哈希、分页和字节数校验。私钥只能由一个端点持有者管理，设置命令不能绕过文件独占锁。

## 验证范围

合成测试使用真实 WebCrypto、WebSocket 和独立 HPKE/ES256 对端，覆盖错误密钥、签名与 JSON 编码、全范围 AAD、并发重放、信任链、跨 await 参数快照、关闭与撤销竞争，以及全部主机响应校验。实际 CLI 与 Host 子进程连接生产中转应用，验证创建、读取、发送、停止、MCP、会话整理、丢回执后冷重启与原操作手动恢复；检查中转帧和 SQLite 不含项目路径、名称或会话正文，HTTP 仅做身份读取。公开版本和旧主机/CLI/MCP/通知回归继续运行。

此前原生 Electron 审批验收连接实际中转与执行主机，通过实际 `DesktopSecureBridge`、preload 和可信页面完成合成 Agent 权限审批。主机接受允许决定后，夹具按精确请求编号丢弃客户端密文回包并断开连接；真实 IndexedDB 保留待确认原操作，页面重载未自动重发，手动重连并重试原操作后取得原回执，Agent 没有重复处理决定。随后新回合的显式取消也通过。1200px 与 390px 视口无横向溢出；中转两条连接的双向帧、SQLite 表值及数据库/WAL/SHM 文件未出现合成私有内容，另以合成明文注入验证表值与 WAL 扫描能够检出泄漏。

此前文件与附件批次的源码原生 Electron 已通过实际 main、preload、执行主机、生产中转应用和 IndexedDB 验证。精确丢弃上传回执后，页面重载不重传，手动恢复原请求后再明确发送，合成 Agent 只收到一次附件指令；生成内容可预览，原生保存实际写入合成选择的目标文件。后续回合改变当前文件后，原回合 diff 保持原前后版本；离线缓存读取没有发出 IPC。390px 附件与 1200px diff 截图已目测检查。该批次四项仓库门禁及 ad-hoc 包内的同一原生流程、独立 CLI/Host 往返也已通过，具体范围见[设备验收](validation.md#m62-可信桌面文件历史变更与附件)；此包仍是开发预览。
