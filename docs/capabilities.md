# 当前产品范围与验收状态

本文是 Moor 0.2 开发预览版的当前能力说明。历史里程碑、合成检查数量和旧界面截图不代表当前发布承诺；设计动机见[设计审查](design-review-2026-09-22.md)，后续改造见[路线图](roadmap.md)。

## 当前范围

Moor 优先提供个人在多设备上访问自己的执行电脑：添加本机项目、连接已有 Codex、读取和继续会话、处理审批、停止回合、发送附件与检查代码变化。代码、Agent 登录和完整会话保存在执行电脑，Relay 只保存账号、设备和组织元数据。

现有共享执行队列保留明确提交、冻结授权、重连同步入队的语义，作为有限预览能力维护；不据此扩展团队权限平台、跨主机自动接管、通用编排引擎或额外 Agent 产品。没有明确提交的草稿始终只在当前访问端，不执行。已有 PR/Git 功能仍按当前范围提供，不在这轮可靠性改造中增加新的外部写入类型。

## 本轮发布清单与负责人

下表为本轮交付的用户场景和负责角色。项目维护者负责对应功能的实现、兼容与仓库验证；发布操作者负责将最终版本的设备及发布结果记录到[本轮验收清单](validation.md#本轮重构的待验收清单)。同一人可以承担多个角色，记录中仍须写明实际执行者和版本。

| 功能范围                          | 本轮用户场景                                                 | 负责人     |
| --------------------------------- | ------------------------------------------------------------ | ---------- |
| 本机与远程工作区                  | 在手机或另一台 Mac 继续原执行电脑上的项目与会话              | 项目维护者 |
| 模型选择、发送、审批、停止和恢复  | 根据原 Agent 能力选择配置，并在断线后核查原请求而不重复执行  | 项目维护者 |
| 附件、文件、历史变更和搜索        | 从远端提交附件、查看受限文件及已冻结的历史结果               | 项目维护者 |
| Git/worktree、原生 Fork 与 GitHub | 在选定项目和分支上审阅或明确确认受限代码操作                 | 项目维护者 |
| Skills 与通知                     | 引用执行电脑上可用的指令，并接收不含正文的状态提醒           | 项目维护者 |
| 共享持久任务意图                  | 明确提交并冻结授权后，在重连时将原任务同步入队               | 项目维护者 |
| 已退场能力的旧记录                | 查阅旧加密、预览等记录并核查原未知结果，不新增对应运行操作   | 项目维护者 |
| 安装包、PWA 更新与 Relay 部署     | 在目标设备安装、升级并恢复数据，确认发布包和实际部署输入一致 | 发布操作者 |

本轮不把独立加密工作区、旧父子任务、网页预览或逐回合额外 MCP 恢复为新功能。真实设备与发布验收完成之前，上述实现仍按开发预览范围提供。

普通远程连接使用 HTTPS/WSS，TLS 在 Relay 终止，Relay 进程能够看到转发内容。“不持久化正文”“本地优先”和“自托管”都不等于端到端加密。后期如重新引入 E2EE，必须共用业务界面并独立完成威胁模型、设备生命周期和安全评审。

## 版本与数据约定

- Moor 桥接协议 v3、会话格式 v1。内部索引、去重 blob 或客户端存储布局升级，不自动意味着对外会话格式变化。
- 旧客户端分区和加密预览数据不在升级时删除或自动执行；已由旧版本删除的数据只能依靠原备份恢复。
- SQLite 升级后不保证旧二进制能读取新内部布局。回退前核对兼容说明，并使用升级前完整停机备份，不能混合恢复单张表。
- 关闭页面或窗口不等于停止任务；明确退出所拥有的执行组件会结束其运行。主机休眠和关机期间不能执行。

## 验收门槛

近期发布先完成首次启动、添加项目、远程访问、发送、审批、停止、断网保留草稿、未知结果核查和升级保留数据的闭环，再扩展新工作流。

每次提交运行 `pnpm check`、`pnpm test`、`pnpm build`、`pnpm format:check`；CI 另检查未使用代码。`pnpm test` 先运行 E2E，再运行集成与包内回归；覆盖范围见[开发与验证](development.md)。自动化只用合成数据、合成 Agent 与确定性故障信号。设备验收由操作者在专用项目中进行，结果必须绑定安装包/源码版本、设备和 Agent 版本，不能将旧批次通过结论继承到新版本。

目前尚没有本轮最终安装包的双 Mac、iPhone、真实账号和正式签名验收结论。步骤与历史记录见[设备验收](validation.md)，这项限制在功能重构完成后也不能省略。
