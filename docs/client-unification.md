# 统一客户端与日常使用改进

本计划覆盖添加项目难以发现、模型选项与实际 Agent 不一致、消息区信息过多、侧栏空间不足、三种客户端入口割裂以及电脑改名不同步六项问题。目标是一个 Moor 客户端、一套项目与会话导航：只有本机时直接使用本机，连接其他电脑后在同一界面继续工作。

本文描述待实施的产品与工程设计，不代表功能已经交付。现有功能总览见[功能完善计划](roadmap.md)，运行身份与目录关系见[概念与身份](concepts.md)。

## 产品目标

- 首次打开即可找到“添加项目”，从选择本机文件夹到开始会话无需进入连接设置。
- 模型选择来自实际执行主机上的 Agent，并能区分当前模型、默认模型、加载失败和过期选择。
- 消息正文占据主要阅读区域；命令、计划、用量和工具详情按需查看。
- 侧栏优先容纳项目和会话，电脑、账号、筛选与设置使用紧凑入口。
- 本机、远程与加密连接使用同一个主窗口，不要求用户切换三种客户端。
- 电脑名称在本机保存后同步到其他访问端，在线、离线恢复和重启后的结果一致。

## 一、主界面添加项目

1. 侧栏常驻带文字的“添加项目”，中央首次使用空状态提供同一主按钮。
2. 默认目标是本机。选择文件夹后由执行主机确认登记，成功后自动选中项目并进入新会话；登记本身不发送指令。
3. 多电脑时显示目标电脑。远程端可以选择该电脑已经登记的项目；本机文件夹选择器不能被用来登记另一台电脑的路径。
4. 添加后立即展示项目，即使项目还没有会话。重复目录返回已有项目；取消或登记失败不会产生空项目。
5. 使用独立、有限的桌面 IPC 和主机设置操作，避免保存整页连接设置或重启活动执行组件。
6. 提供登记中、成功、目录无效、不可访问及主机不可用反馈，保留已有会话与草稿。

验收：全新合成用户无需打开设置，就能完成“添加文件夹 → 选中项目 → 发送第一条消息”。

## 二、模型发现与实际执行一致

### 程序来源与诊断

- 记录实际执行程序来源、版本、锁定 ACP 适配器版本和能力读取时间；完整启动路径仅在本机设置中显示，不进入共享会话。
- 本机设置支持选择 Codex 来源。自动发现纳入本机 CLI 安装位置，检查可执行性和适配器兼容性，避免只依赖固定路径优先级。
- 显式配置优先；升级或更换程序来源通过明确的配置更新处理。已有会话继续使用其固定 Agent 配置，不能因新配置出现而静默换程序。
- 诊断不得读取其他应用数据库、登录凭据或原始私密日志。能力探测不发送用户 prompt。

### 能力读取与缓存

- 选中项目和 Agent 后提前探测；打开模型选择器时检查缓存新鲜度，明确展示加载、可用、过期和失败状态。
- 缓存关联执行主机、Agent 配置版本、实际程序指纹以及项目/执行目录。处理程序原地升级、主机重连、项目切换和同一 Agent 在不同目录中的配置差异。
- 保留当前模型、可验证的默认模型及模型专属思考强度；区分新会话默认设置与已有会话恢复后的当前设置。
- 处理模型切换及 ACP 配置更新后的能力变化；取消过期探测，拒绝迟到结果覆盖新目标或用户选择。
- Codex 底层继续通过锁定 ACP 适配器读取实际运行程序的模型目录，不维护硬编码型号列表。官方要求在绘制模型选择器前通过 `model/list` 取得可用模型与能力，见 [Codex app-server Models](https://developers.openai.com/codex/app-server#models)。
- 保留自定义 ACP 与不提供完整模型目录的 Agent 的能力差异；缺失信息不能冒充已确认的模型或权限。

### 默认选择与失败处理

- “Agent 默认”展示已确认的具体含义；未知时明确显示未确认，不猜测型号。
- 发送前根据实际打开的 Agent 能力校验模型和思考强度，不能用另一进程的探测结果替代执行校验。
- 历史或草稿中的过期型号保留为不可用选择，提示用户重新选择；不静默降级或替换。
- 分别报告启动失败、能力读取失败、程序/适配器不兼容和账号不支持模型，提供刷新及本机诊断入口。
- 失败保留草稿与原操作状态，不自动换模型重发，不改变审批模式。

验收：首次选择能取得真实选项，升级后缓存失效，模型和思考强度匹配；注入两类 400 错误时不丢草稿、不自动重发。

## 三、消息区与右侧信息面板

- Assistant 默认展示正文，工具执行细节折叠；待处理审批、问题、失败以及需要用户行动的状态保持可见。
- 消息列表右上角增加“会话信息”入口，面板默认关闭，集中显示 Agent 命令、计划和用量。
- 面板默认显示最新上报，支持查看指定回合；计数标明来源、时间和统计范围，未知值不显示为零，不跨回合盲目相加。
- 历史事件继续保存，仅调整展示，不删除历史记录。命令仍只填入草稿，由用户发送。
- “查看回合文件变更”依据主机已保存的 diff 引用与 `changeCount` 显示。`ready` 或 `partial` 且确认有变化时显示数量入口；无变化时隐藏。
- 采集中、部分可用、采集失败和历史未记录分别表达，不能把未知当作无变化。详情面板可检查这些状态，不用今天的文件补造历史。
- “从此回合创建副本”改为消息底部的小图标，支持悬停说明、键盘焦点和无障碍名称；仍检查完成状态、原生锚点和主机能力。

文件变化代表回合前后工作目录基线差异，不能把共享目录中所有变化归因于当前 Agent。详见[项目文件与历史变更](file-changes.md)。

验收：纯文本问答没有重复快照和空 diff 按钮；真实合成文件变更有入口；审批和错误不因视觉整理而消失。

## 四、紧凑侧栏与工具布局

| 区域       | 常驻内容                               |
| ---------- | -------------------------------------- |
| 侧栏顶部   | 紧凑工作区入口、新会话、添加项目和搜索 |
| 侧栏主体   | 项目分组、置顶及最近会话，占据剩余高度 |
| 侧栏底部   | 一行账号、电脑状态及设置入口           |
| 消息区顶部 | 会话标题、执行电脑、搜索及右侧工具入口 |
| 消息区底部 | 输入框、模型和运行设置                 |

- 缩小 Logo 与上下留白，合并重复的工作区、电脑及连接状态显示。
- 活跃/归档进入列表筛选菜单；待我处理使用紧凑入口与数量标记。
- 项目分组支持折叠，项目旁可以新建会话；没有会话的项目也可选择。
- 会话行以标题为主，电脑、时间及管理按钮降低视觉权重；执行目标仍可明确查看。
- 侧栏支持折叠、宽度调整与偏好保存，窄屏使用抽屉。悬停操作也必须支持键盘和触屏。
- GitHub、预览、Skills、MCP 等进入右侧工具面板或更多菜单；能力不足时给出具体原因。
- 在固定窗口尺寸和同一组合成数据下记录改版前后的列表高度及可见会话数量，验证空间改善。

验收包含长标题、同名项目、多电脑、长列表、浅色/深色与 390px 窄屏；桌面窄视口不能替代手机真机验收。

## 五、单一客户端与兼容

### 共享界面与有限传输

- 桌面从安装包加载一个主界面，取消“本机工作区 / 我的所有电脑 / 加密工作区”三个用户入口。
- 本机自动出现在电脑列表；未登录或中转不可达时可继续使用本机项目。连接其他电脑后复用同一导航和会话界面。
- 抽离共享的导航、消息、输入框、模型选择和详情组件，使普通页面与加密页面采用一致交互。
- 本机、现有远程和加密连接通过有限、类型化的传输接口接入；传输差异留在内部，保留各自的授权与恢复语义，不提供任意 HTTP、shell 或 socket 代理。
- 在单一运行时所有权下协调主机与传输生命周期，解决目前加密主机与桌面模式互斥，避免不同进程争用运行数据库。
- 同一台电脑的本地与远程入口仅在确认身份映射后合并展示。已建立会话的执行主机、项目及 Agent 绑定不变。
- 加密连接断开不得静默降级；未知结果不能自动改走另一链路重发。连接恢复与元数据读取不能执行旧草稿。

### 旧数据与功能完整性

- 保留 Moor 旧 origin/partition 中的草稿、附件、缓存和待确认操作。通过受限的已知数据格式迁移/恢复入口处理，不清空旧存储，不读取其他应用数据。
- 原账号、设备、工作区、项目、会话和 operationId 必须保留。名称或路径相同不足以合并身份，不能把旧待确认操作改投新目标。
- 对迁移中断、重复升级、存储写入失败和无法确认身份的记录提供恢复路径；未完成迁移时保持原数据可恢复。
- 分别检查搜索、附件、审批/问答、停止、Git/worktree、Fork、Skills/MCP、GitHub、预览、角色/任务、待办及通知；主机能力差异必须可见，统一界面不能丢弃原本可用的功能。
- 旧协议兼容仅用于已有明确配置，不自动把不可信目录提升为加密身份。可信 PWA、完整加密通知等既有未完成范围继续如实记录。

验收：启动、登录、断网、连接第二台电脑和访问加密会话均留在同一个主窗口；本机可独立工作，升级后草稿与未知结果可恢复。

## 六、电脑名称同步

1. 名称作为主机持久保存、带递增版本的显示元数据，身份仍由稳定设备与机器编号决定。
2. 本机改名通过独立设置动作更新，避免重启主机和中断活动回合。
3. 当前远程链路更新后端设备元数据并通知同账号在线客户端刷新；后端确认与本机保存分别报告。
4. 重连发布主机已保存的最新元数据状态；按版本拒绝迟到消息和旧连接覆盖。此过程不重试用户执行操作，也不重放任务队列。
5. 加密链路通过经过认证的加密目录提供名称，不把名称放入公开信任清单。
6. 界面区分本机已保存、远端已同步及同步失败，不把局部成功报成全端完成。

验收矩阵：A 改名后 B 在线更新；B 离线后重连更新；A 离线改名后恢复连接同步；重启、连续改名、旧版本迟到及设备撤销不能恢复旧名称。

## 阶段与提交边界

各阶段完成后更新本文的交付状态及相关产品文档，执行全部仓库门禁，然后作一次 Conventional Commit。不得将部分实现标为阶段完成；计划文档先独立提交。提交不包含运行数据、生成产物、凭据或内部执行记录。

| 阶段                  | 交付范围                                                                | 完成标准                                                                                    | 状态   |
| --------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- | ------ |
| 1. 模型与名称基础修复 | 实际 Agent 来源诊断、能力缓存与默认选择、模型错误反馈、名称持久化与发布 | 对应模型与名称验收矩阵通过，活动回合不因改名中断，四项门禁通过                              | 待实施 |
| 2. 统一客户端基础     | 单一主窗口、共享界面契约、有限传输、主机生命周期、旧数据兼容            | 本机独立运行、远程/加密接入、旧草稿恢复及原请求身份检查通过，四项门禁通过                   | 待实施 |
| 3. 日常界面整理       | 添加项目、紧凑侧栏、共享消息列表、右上角信息面板和回合操作              | 首次使用完整路径、列表空间对比、消息与 diff/Fork 条件、响应式及无障碍检查通过，四项门禁通过 | 待实施 |

阶段 1 提供共享能力数据及名称协议，阶段 2 为统一界面建立连接与存储边界，阶段 3 使用这些基础完成产品交互，阶段 4 验证整体交付。必要的兼容修复归入对应阶段，不另起未完成的平行客户端。

## 验证与交付要求

每次提交前运行：

```sh
pnpm check
pnpm test
pnpm build
pnpm format:check
```

测试使用合成 ACP、临时 Git/普通项目、模拟双主机和确定性故障信号或注入时钟，不使用真实 Agent 账号或 sleep。重点覆盖首次启动、旧能力缓存、程序升级、模型配置变化、重复及迟到响应、名称版本收敛、未知结果、权限撤销、断线重连与迁移失败。

图形和安装包检查使用隔离数据目录及合成用户，验证实际打包资源和有限 IPC，不能仅靠组件快照证明交付。包与 Docker 上下文只含程序文件，重建保留操作者数据，依赖继续锁定并保留来源和许可声明。

真实 Codex/Claude 账号调用、双 Mac、iPhone/Safari/PWA、系统休眠与正式签名发布的结果单独记录在[设备验收](validation.md)。环境未覆盖时明确标为待验收，不把合成通过或桌面窄视口当作真机成功；阶段 4 的工程交付不宣称这些外部验证已经完成。
