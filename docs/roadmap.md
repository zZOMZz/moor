# Moor 功能完善计划

本计划面向个人多设备使用：先让现有会话可靠、易管理，再让手机也能提交材料和检查结果，最后补齐并行编码与协作能力。当前基线为 0.2 开发预览版、桥接协议 v3、会话格式 v1。下述里程碑区分实现进展与验收状态，不代表全部已完成或正式发布。

运行时独立化已经完成。后续按 Moor 的会话格式和主机边界实现功能；不重新引入 Lody 运行时、数据库读取或外部源码依赖。当前能力与限制见[项目首页](../README.md)和[开发与验证](development.md)。

## M1：管理日常会话

按以下顺序交付：

1. **重命名**：定义独立的会话元数据操作，经主机确认和去重后保存。两端同时修改时明确返回冲突，不借发送 prompt 修改标题。
2. **归档与恢复**：增加归档列表和恢复入口。首版只归档空闲会话；运行中的会话提示先停止。归档保留历史、Agent 上下文映射和项目目录，恢复不会触发执行。
3. **置顶**：明确为当前 Moor 主机会话的共享元数据，在同一账号可访问的设备间同步。置顶不改变会话归属；列表只排序当前可访问的会话。
4. **长列表与操作反馈**：提供加载、空列表、失败和离线状态；首批渲染 100 条会话，可手动显示更多，并额外保留当前选中的会话。已用 2,000 条合成数据验证初始控件数量受限；当前按完整会话列表搜索和排序，尚未引入主机分页或虚拟列表。

验收：两台合成访问端看到主机确认后的操作；离线变更不会被误报成功；恢复后可手动继续原会话；归档和置顶不影响精确审批、停止或请求去重。永久删除和自动生成标题留作后续增强。

首版通过主机能力报告开放整理入口，不增加新的桥接协议版本；访问旧主机时提示更新执行电脑。元数据请求携带预期版本并在主机事务中保存状态与去重凭据，版本竞争返回冲突。归档会话保留正文和草稿，先恢复再发送；恢复动作不调用 Agent。主机确认丢失时保留原目标、operationId 和预期版本，刷新页面后仍只能由用户手动重试，不在重连时自动提交。

主机被移到另一产品工作区时，手动重试可以使用重新验证的工作区/副本路由，但必须先确认账号、设备、执行工作区、本地项目和会话身份均未改变。原操作内容、预期版本和 operationId 保持不变；组织归属调整不能把待确认操作转交另一执行目标。合成测试覆盖待确认请求跨刷新恢复、归属隔离、版本竞争与原编号重试。

主要入口：[元数据模型](../src/model.ts)、[操作校验](../src/bridge/validate-mutation.ts)、[主机](../src/bridge/host-workspace.ts)、[HTTP](../src/relay/http.ts)、[导航](../src/web/navigation.ts)、[界面](../src/web/ui.tsx)。

## M2：提交材料、检查结果

M2 先定义文件与附件的主机接口，再分别接入图片、文件浏览和变更采集，避免每项功能各自建立一套路径访问或存储机制。

M2.1 实现 `file-content-v1` 能力及只读文件接口，限制每份文件 1 MiB，校验主机范围、规范相对路径、文件类型和内容摘要。M2.2 通过 `attachments-v1` 接通附件，限制每份 8 MiB、每条指令 8 个、每个会话 64 MiB；新会话附件使用持久保存的会话 ID，上传和发送分别确认。文件与附件缓存按完整执行身份和具体内容版本隔离，离线结果明确标为缓存。M2.3 通过 `project-tree-v1` 和 `project-diff-v1` 提供只读文件树、文本/Markdown 浏览及回合和会话变更；四项检查与合成浏览器检查通过，真实设备验收仍待完成。详见[文件与内容协议](content.md)及[项目文件与历史变更](file-changes.md)。

附件持久保存在执行主机，访问端保存自己的草稿与必要缓存，中转仅转发。主机离线时，附件可以保留为访问端草稿，重连后仍需用户手动完成发送。Web Push 的平台限制和运行依赖需要独立验证，页面内提示不算完成后台通知。

M2.5 通知默认关闭，用户分别开启本机系统通知或当前浏览器 Web Push。事件只携带标识和类型，点击后重新校验账号、原执行范围和当前会话；关闭、退出登录、去重、连接替换和过期处理已接通。网页多页订阅变更串行协调，存储超时会中止写入，失败后可手动清理残留服务器订阅。服务配置、支持范围和实际送达限制见[任务通知](notifications.md)。

M2.2 支持只发送附件的首条指令；未确认上传阻止依赖它的指令提交，响应丢失或无效确认保留原编号和完整请求。上传期间切换目标不会向新目标继续发送。图片、音频和普通文件分别核对 Agent 的实际输入能力；生成文件只接收 ACP 嵌入内容，不抓取资源 URL 或任意主机路径。主机已确认指令后清理输入区附件，历史引用及字节保留，历史附件不能通过草稿移除操作删除。真实 iPhone 选择/粘贴、下载落盘与真实 Agent 附件兼容性仍待第二轮专项验收。

回合 diff 描述文件基线之间的变化。同一目录被外部编辑器或多个会话修改时，不能声称所有变化均由当前 Agent 产生；界面需说明归属限制。M4 的独立 worktree 提供更可靠的任务隔离。

M2.4 使用执行主机自己的 SQLite 索引，在用户手动搜索时刷新有范围的已保存内容；消息、工具输出和冻结 diff 可作为结果来源。项目范围只包含当前执行电脑的同一项目，不自动扩展到其他电脑副本。离线查询只读取当前浏览器缓存，并显示缓存覆盖数量和不完整提示；在线请求失败不自动换成旧缓存。索引重建不执行 Agent，也不读取当前目录补造历史。查询语义和限制见[正文搜索](search.md)；四项检查及合成页面定位验证通过，设备专项验收仍待完成。

主要入口：[会话格式](../src/session-schema.ts)、[Agent 接口](../src/runtime/agent.ts)、[持久化](../src/runtime/store.ts)、[主机](../src/bridge/host-workspace.ts)、[内容展示](../src/web/content.ts)、[浏览器缓存](../src/web/cache.ts)。

## M3：完善 Agent 交互

先扩展带类型的能力发现和事件协议，再逐项实现。只有主机实际报告可用的功能才显示入口；适配器升级必须锁定版本并增加合成协议测试。

1. **能力与事件**：覆盖交互问答、可用命令、计划、使用量等事件；定义未知事件的兼容处理，不将其显示为已支持功能。
2. **交互问答与命令**：支持单选、多选和文本回答；问答与权限审批分开建模，但都必须匹配当前活动请求。命令列表来自运行时，明确命令对会话的影响。
3. **上下文与用量**：展示 Agent 实际提供的上下文、Token 和额度。缺失值标为不可用；不同来源和时间范围分别显示，不据模型名称推算用量。
4. **运行中追加指令**：新增独立的 steer 操作和确认状态，绑定活动回合；保留原 operationId，处理响应丢失、竞争停止和配置变化。运行时未确认前显示待确认。

以上实现与合成验证已经接通。当前表单支持文本、单选、多选、数值/整数和布尔回答，允许拒绝或取消问题；命令只填入草稿，由用户手动发送。计划、上下文、Token 和费用只展示 Agent 上报字段，缺失不当作零，也不跨回合推算合计。追加仅对内置 Claude ACP 0.76.0 且实际报告兼容能力的活动会话启用；Codex、自定义及未知适配器不启用。原追加操作一旦进入主机执行阶段，手动重试只查询原结果，不再次调用原生追加。详细边界与验证范围见[Agent 交互](agent-interactions.md)。

验收：问答回答只送达一次，过期回答被拒绝；运行时不支持的功能有清晰回退；steer 不创建重复回合、不静默更换模型，也不把离线草稿变为自动执行队列。

当前每轮结束会关闭 Agent 进程。保持后台任务、定时唤醒或 Goals 需要另行设计进程驻留与恢复语义，放入 M6；不得因增加事件展示而默认延长执行生命周期。

主要入口：[能力发现](../src/runtime/capabilities.ts)、[运行设置](../src/run-config.ts)、[Agent 接口](../src/runtime/agent.ts)、[ACP](../src/runtime/acp.ts)、[主机](../src/bridge/host-workspace.ts)。

## M4：完成编码工作流

| 顺序 | 交付内容                                         | 验收标准                                                                                                 |
| ---- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| 1    | 本地 Git 状态、分支选择、worktree 创建和清理     | 两个会话的文件隔离；脏目录、分支冲突、创建失败有明确结果；清理不会丢失未提交内容                         |
| 2    | 原目录 Fork、独立 worktree Fork                  | 只向报告原生 Fork 能力的 Agent 提供入口；明确历史截止点、Git 基线及未提交文件如何处理；原会话不改变      |
| 3    | GitHub 仓库接入、Issue/PR 上下文、PR/CI 状态读取 | 凭据留在主机私有设置；会话绑定明确仓库、分支和 PR；权限撤销后不可继续访问                                |
| 4    | 行评论、评论同步、提交推送和 PR 操作             | 评论绑定具体 revision 和行；外部写操作有明确人工动作或既有授权，失败重试不重复发布；合成测试不写真实仓库 |
| 5    | 项目网页预览、响应式视口、元素标注               | 只访问当前项目明确登记的预览服务；连接可关闭；不暴露任意 socket 代理；标注能回到正确会话                 |

先交付 PR/CI 读取，再开放外部写入。终端可作为桌面本地增强单独实现，不提供任意远程 shell。跨主机会话迁移不包含在 Fork 中，需单独解决文件、Agent 上下文与执行所有权转移。

## M5：配置与协作

- **Skills**：只读发现项目和主机全局 Skills，支持查看与引用；声明路径边界及 Agent 兼容范围。安装、编辑和同步单独评估。
- **角色与 Agent 配置**：保存模型、effort、权限和默认指令的预设；提供本机自定义 ACP 配置与能力检查。凭据和启动命令保留在主机，既有会话不被预设修改追溯影响。
- **完整 CLI**：通过同一主机接口提供会话创建、读取、发送、停止、归档和配置查看；结构化输出和错误码可用于脚本，重试沿用原操作编号。
- **多 Agent 协作**：增加受限的创建、读取、发送、等待与取消会话工具；记录父子关系、目标权限和完成条件。先支持用户明确创建的有限任务，处理超时、取消和主机离线，不隐式形成无限后台调度。

验收：CLI、Web 和 Agent 工具接受同样的归属与活动回合校验；无法访问其他账号或项目的会话；并行代码修改使用明确的工作目录策略；协调方超时不误报子任务已停止。

额外 MCP 配置从本机配置与会话授权设计开始，不允许远程输入直接注入命令或凭据。设备 CPU/内存监控可在增加驻留 Agent 或多 Agent 并发后加入，优先展示当前受 Moor 管理的进程状态。

## M6：按需求扩展

以下内容暂不安排固定顺序；进入开发前应有明确使用场景和验收环境。

| 方向                      | 启动条件与范围                                                                                             |
| ------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Windows / Linux           | 有目标设备验收条件；先验证路径、进程终止、数据锁和适配器，再完成打包                                       |
| 原生 iOS / Android        | PWA 的通知、附件或系统集成限制已影响日常使用；复用现有主机协议                                             |
| 团队与 SSO                | 明确多人使用需求；先定义成员角色、设备共享和审计，再接身份提供方                                           |
| 后台任务、定时任务、Goals | 明确授权、预算、进程驻留、取消和漏跑策略；重连不补跑未确认任务                                             |
| 旧历史导入                | 确有保留旧历史需求，且有旧版本显式导出格式；先导入可读历史，不读取其他应用数据库，不恢复旧审批和待执行操作 |
| 跨主机迁移与端到端加密    | 分别明确可迁移的 Agent 上下文范围、执行所有权转移及设备密钥恢复方案，再单独立项                            |

## 第一轮执行清单

第一轮限定为 M0 基线和 M1 最小会话管理，可拆成四个小改动批次：

1. **校准能力说明并验证基线**：澄清 diff/搜索/附件的当前范围，运行四项检查，整理人工验收步骤；只修复检查发现的问题。
2. **会话元数据操作**：实现重命名的协议、主机事务和去重，覆盖跨项目拒绝、竞争修改和响应丢失。
3. **重命名与归档界面**：接入重命名、空闲会话归档和恢复；验证双端一致、离线提示及草稿保留。
4. **置顶与里程碑验收**：完成置顶排序、长列表评估、安装升级说明；汇总合成检查和人工设备验收状态。

第一轮实现和四项检查完成后，先提供开发预览版本供操作者执行[第一轮真机矩阵](validation.md#第一轮操作矩阵)。随后从 M2.1 文件与内容协议开始，并开展 M3 的运行时能力兼容性验证。证书与设备准备可以提前进行，正式发布仍须满足 M0.4；尚未进行的人工验收继续明确标记为待完成。

## 每批交付标准

- 明确此次新增行为、失败恢复方式和兼容范围；协议或会话格式变化同时覆盖主机与浏览器数据。
- 使用合成数据、合成 Agent 和确定性信号验证受影响行为；新增测试针对权限、持久化、去重或生命周期等实质风险。
- 提交前运行 `pnpm check`、`pnpm test`、`pnpm build`、`pnpm format:check`。不提交会话记录、真实账号数据、生成包或内部执行记录。
- 更新用户文档；真实设备结果仅记录环境、结论与限制，不将真实会话内容放入仓库。
- 一个里程碑只有在用户操作流程和主机处理均接通、相关验收通过后才算完成。单独增加字段、按钮或渲染函数不计为完整功能。
