# 产品范围与重构路线图

当前目标是完成[设计审查](design-review-2026-09-22.md)中的 26 项问题。功能是否当前可用，以[当前产品范围与验收状态](capabilities.md)为准；本页只描述改造顺序和完成条件，不再把历史批次测试数量当作当前交付状态。

此前 M0–M6 的逐批记录保留在 Git 历史与[设备验收](validation.md)中。旧路线图中的“继续补齐加密工作区”、继续扩展网页预览/项目角色/旧父子任务等计划不再有效。端到端加密按[退场计划](end-to-end-encryption-deferral.md)处理，未来是否重启需要独立立项。

## 保持不变的边界

Host 是执行与会话持久化的权威；请求绑定账号、设备、工作区、项目与会话。Relay 不持久化正文，凭据不进入共享文档。未知操作保留原编号和冻结内容，审批仍匹配精确活动回合。

离线草稿不执行。已经明确授权并冻结输入的持久任务意图可以在重连后同步入队；已派发或结果未知的执行不能因此重放。客户端统一、存储迁移与功能退场都不能改变这些语义。

## 交付顺序

| 批次             | 对应审查问题                      | 交付内容                                                                                     | 完成依据                                                        |
| ---------------- | --------------------------------- | -------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 可靠性与数据保护 | D06、D07、D12、D13、D17、D19、D26 | 操作记录长期可用、按会话阻塞、定向恢复、历史内容去重、共享安全模块、准确源码解析、保留旧分区 | 容量和竞争回归、旧数据迁移故障回滚、冻结历史、无重复执行        |
| 产品退场         | D01、D03、D18                     | 移除独立加密与已退场功能的新增入口、运行接线和专属分发资源，保留必要历史处置                 | 普通工作区独立运行；无隐藏新增执行；未知请求未删、未改投        |
| 客户端与关键路径 | D02、D05、D08、D11、D14、D15      | 共用会话业务、清晰身份、细粒度状态、追加输出、分页、范围受限的目录校验                       | HTTP/IPC 同一行为；字节/扫描/请求数量下降；撤销与迟到响应仍正确 |
| 协议与维护成本   | D09、D10、D16、D21                | 窄业务意图、共同接受/回执原语、按业务处理器、真实入口死代码检查                              | 不增加新的业务状态权威；旧请求兼容；无反向包依赖                |
| 交付与产品说明   | D04、D20、D22—D25                 | 稳定近期范围、独立构建、PWA 交接、一份当前能力表、可重复发布输入                             | 发布包与文档一致；核心真机与正式分发验收如实记录                |

各批次有依赖但可以并行处理互不影响的模块。每个问题尽量形成独立、可回滚的 Conventional Commit；同一数据迁移的事务边界不能为了拆提交而打断。提交附对应行为、迁移兼容、验证与真实设备限制说明。

## 改造完成后统一设备验证

先收尾设计审查中仍有缺口的改造，并对每次修改运行仓库检查；代码和文档定稿后，双 Mac 和 iPhone 对同一最终版本统一验证本机首次使用、远程连接、真实 Agent 发送/审批/停止、休眠唤醒、移动网络切换和草稿保留。自动化继续只用合成账号与 Agent，不读取真实账号或其他应用数据库。

每次验证绑定明确包版本。代码、构建或合成测试通过只证明对应范围；未完成设备检查的能力仍标为预览。最后交付前，对最终包再做升级保留数据、PWA 更新、签名/公证和实际部署回归。条件不足时明确缺项，不把目标改为仅合成测试通过。

## 暂不扩展

不新增团队权限平台、通用工作流引擎、更多外部写入类型、跨主机自动接管或第二套工作区界面。保留现有明确提交的持久任务语义和当前可用的受限工作流，先验证可靠性和日常体验。

Windows/Linux、原生移动端、E2EE 和跨主机会话迁移均需要具体使用需求、完整恢复设计及可执行的目标设备验收，不能仅因协议预留字段就开始补齐产品。
