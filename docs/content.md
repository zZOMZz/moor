# 文件与内容协议

M2.1 提供按会话范围读取项目文件的主机接口，以及独立的内容类型与缓存客户端。M2.2 已接通图片和文件附件的选择、上传、发送，以及 Agent 回传附件的预览和下载。M2.3 已接通只读项目文件树、文本/Markdown 预览及主机保存的回合和会话变更，四项仓库检查和合成浏览器流程检查通过；真实设备验收仍待完成。引用本身不授予文件访问权限。

## 版本与兼容

内容消息使用 `contentVersion: 1`。主机通过 `file-content-v1` 能力开放项目文件读取，通过 `attachments-v1` 开放附件上传、移除和读取，通过 `project-tree-v1` 与 `project-diff-v1` 开放文件树和历史变更读取；桥接协议继续为 v3，会话格式继续为 v1。只读请求不修改会话文档或执行 Agent；附件、文件基线与历史变更分别保存在 Moor 主机数据库中，已有会话记录保留。旧主机缺少相应能力时，中转拒绝该功能并提示更新执行电脑。

项目文件和附件的内容版本为实际字节的 `sha256:` 摘要，与文件修改时间无关。描述信息包括字节数和媒体类型。当前文件读取上限为 **1 MiB**，返回规范 base64；有效 UTF-8 且不含 NUL 的内容标为 `text/plain`，其他内容保留为 `application/octet-stream`，不会用替换字符伪装成文本。历史 diff 的版本另外绑定保存时的范围、回合、前后基线与采集状态。

附件引用包含 `attachmentId`、显示名称、内容摘要、字节数与媒体类型，单份上限为 **8 MiB**，每条指令最多 **8 个附件**，每个会话保存的附件字节合计最多 **64 MiB**。显示名称不能用于生成磁盘路径。会话中的历史 diff 引用只保存回合、diff ID、版本、采集状态和变化数量，最多对应 500 项变化；前后文件内容由主机另行保存和按需提供。新增、删除和重命名分别保留对应的空基线或原路径，同一前基线来源或后基线目标不能重复。

## 主机读取

接口为 `POST /api/workspaces/:workspaceId/replicas/:replicaId/file-content`，只接受 JSON 请求，整个请求最多 16 KiB。路径参数中的工作区属于产品组织层，正文中的工作区属于执行主机，不能混用。

```json
{
  "contentVersion": 1,
  "workspaceId": "runtime-a",
  "localProjectId": "project-a",
  "sessionId": "session-a",
  "path": "src/example.ts"
}
```

账号来自登录凭据，设备来自已验证的项目副本映射，客户端不能在正文中替换它们。中转校验产品工作区、副本、执行主机和本地项目的当前归属；主机在访问文件前校验执行工作区、本地项目和会话所有者。读取结束后再次校验权限和归属，期间退出登录、移动或撤销主机的请求不能继续返回文件内容。文件请求必须关联已有会话，不接受任意本机目录或主机路径。

`path` 是未经 URL 解码的项目内相对路径。绝对路径、盘符、反斜杠、空路径段、`.`、`..` 和控制字符均被拒绝；百分号是文件名的字面字符。项目根来自主机本地登记记录，所有符号链接组件均被拒绝，包括指向项目内部的链接。只读普通文件，不读取目录、FIFO、socket 或设备文件。

主机以不跟随符号链接且不阻塞 FIFO 的标志打开文件，核对路径与文件描述符的身份，在读取前后检查目录、文件大小和修改状态。每次最多读取上限加一字节；读取时变大、路径替换或内容变化会返回错误。普通 Node 文件接口无法提供等同操作系统 `openat2` 的原子目录约束；这些检查能拒绝可观察到的替换，但不构成针对恶意本机进程精确反复换回目录的系统沙箱。

主机返回 `confirmed: true`、完整请求范围、路径与内容描述。`status: "content"` 带 base64 字节；若请求附带 `knownVersion` 且本次实际读取的摘要相同，则返回不带正文的 `status: "not-modified"`。后者也必须重新读取当前文件和验证范围，不能凭旧缓存确认。文件不存在、超限和读取期间变化分别返回 404、413 和 409；不能读取的路径或文件类型返回 403。错误不回传本机绝对路径。

文件读取没有执行副作用，不创建 operation 记录、不写入会话、不调用 Agent，也不进入待执行队列。中转仅转发内存中的响应，返回 `Cache-Control: no-store`，数据库不保存路径、摘要或文件字节。

## 项目文件缓存

缓存客户端验证响应版本、范围、路径、字节数和实际 SHA-256；内容校验失败时不保存。缓存键包含协议版本、账号、设备、执行工作区、本地项目、会话、相对路径与内容摘要。产品工作区的重新归组不改变已缓存内容的执行身份，但下一次在线读取仍须通过当前路由验证。

底层内容缓存保存不可变的具体版本。调用方保留正在显示的摘要；只有本地存在并通过校验的对应字节，才发送条件读取。若缓存丢失、损坏或不属于当前范围，在线请求改为读取完整内容。

离线读取必须指定具体版本，结果标记 `source: "cache"`、`stale: true`；缺少对应缓存时明确不可用。在线读取被拒绝或文件已删除时直接报告错误，不自动用旧缓存冒充当前文件。主机读取成功但本机缓存保存失败时，内容仍可读取，同时返回 `cacheSaved: false`。客户端不监听重连、不自动重试，也不处理附件草稿或发送操作。

文件浏览页面另外保留明确标记的“上次读取”版本指针，指向同一完整执行范围下已经保存的具体内容；分页树和历史 diff 仍按固定版本隔离。指针用于选择离线可读版本，不代表当前主机内容。页面切换目标或文件后，晚到响应不能覆盖新选择。

## 项目文件与历史 diff

已有会话可通过 `project-tree` 获取版本化文件列表，通过 `turn-diff` 获取原回合保存的变化摘要，再通过 `diff-file` 读取特定文件的前后版本。请求使用同一工作区和项目副本路由，并再次绑定执行工作区、本地项目、会话、回合及所选路径。分页和历史读取均校验预期版本；内容和列表不上传为中转索引。

主机在打开 Agent 前保存起始基线，在执行结束并关闭 Agent 后保存结束基线。读取旧 diff 使用数据库中的冻结记录，不访问今天的文件来重算历史；未采集过的旧回合显示未记录。取消、中断和采集失败分别保留真实执行状态与基线可用性，重启不执行 Agent 或补采旧基线。

默认最多列出 5,000 项、深入 64 层，每次基线读取最多 16 MiB，每份文件最多 1 MiB，一次比较最多 500 项变化。Git 项目使用跟踪文件和未忽略的未跟踪文件；依赖、构建、缓存、Moor 运行数据与常见凭据路径另有过滤。外部编辑器和同目录其他会话也可能贡献变化，不能把工作目录差异全部归因于当前 Agent。详细行为见[项目文件与历史变更](file-changes.md)。

M2.4 在这些持久化内容上增加主机正文索引和离线缓存搜索，已接通消息与冻结 diff 的结果定位，并完成仓库与合成检查。搜索不读取当前目录补齐历史、不调用 Agent，覆盖范围见[正文搜索](search.md)。

## 图片与附件

输入框上方可选择文件，也可在输入框中粘贴图片。选择首先保存为当前浏览器的草稿，可预览或移除。点击“上传”只把附件保存到执行主机；点击发送会先上传尚未确认的附件，全部收到主机确认后再提交一条指令，也支持只有附件、没有文本的指令。离线和重连均不自动上传或发送。

附件草稿按账号、设备、执行工作区、本地项目和会话隔离。新会话在发送前持久保存稳定的会话 ID，刷新后继续使用同一草稿范围；主机上传时预留该 ID 的项目归属，不启动 Agent。上传期间切换执行目标会停止原发送流程，不能把附件或指令交给另一主机。指令被主机确认后清理对应输入区的附件，历史引用和主机内容保留。

接口均使用当前工作区和项目副本路由：

| 接口                                                                       | 行为与确认                                                                                          |
| -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `POST /api/workspaces/:workspaceId/replicas/:replicaId/attachment-actions` | `upload` 携带完整范围、operationId、附件引用和 base64；`remove` 携带完整范围、operationId 和附件 ID |
| `POST /api/workspaces/:workspaceId/replicas/:replicaId/attachments/read`   | 按完整会话范围与附件 ID 读取，返回主机确认、引用和 base64                                           |

账号与设备由登录凭据和当前副本映射确定，正文不能替换它们。主机再次核对执行工作区、本地项目、会话、用户和机器身份；新会话的预留范围也参与后续指令校验。同名文件或相同会话 ID 不能跨项目授权。附件字节、归属和操作去重凭据在同一主机事务中保存，中转只转发，不保存附件正文。读取返回前再次核对登录、主机连接与工作区归属。

每次上传或移除先将原操作及完整载荷保存到浏览器，再发给主机。有效确认必须匹配操作编号、会话范围，以及上传时的附件 ID、名称、媒体类型、字节数和摘要。网络超时、响应丢失或确认不匹配时保留原请求，只能手动重试；刷新或重连不发送待确认操作。只有明确的主机拒绝才解除待确认状态，允许用户修正后重新决定。重复操作返回原确认，不重复写入或恢复已移除的字节。

未上传的草稿可在本机移除。已上传但尚未被指令引用的附件，需要主机确认移除；历史回合使用的附件不能通过草稿移除操作删除。归档会话不能上传新附件，恢复后再上传。会话达到 64 MiB 限额时明确拒绝新增内容，用户可以移除未发送附件；不会静默丢弃指令中的材料。

## Agent 输入与输出

图片、音频与普通文件分别使用 Agent 实际报告的 `image`、`audio`、`embeddedContext` 输入能力。能力未知或不支持时显示具体原因；主机验证指令时及实际打开 Agent 后都会检查，能力变化不能导致附件被静默忽略。主机读取自己的已确认字节并验证引用，再将图片/音频转换为 ACP 内容块，将普通文件转换为嵌入资源。客户端不能通过输入配置提交文件路径、原始启动命令或替代主机字节。

Agent 输出中的嵌入图片、音频、文本资源或二进制资源会保存为有范围的附件，与会话输出一起持久化。超限、损坏或不支持的输出显示明确提示。单纯的资源 URL 不会触发网络抓取或本机路径读取；文件名称仅从返回信息中提取为显示名称。会话历史保存附件引用，不把原始 base64 重复写入正文。

点击历史附件卡片后读取对应版本，验证范围、字节数和 SHA-256，再打开预览。PNG、JPEG、GIF、WebP 使用经验证字节生成的本地图片数据地址；SVG、HTML 及其他格式不嵌入执行。有效 UTF-8 的纯文本和 Markdown 可预览，文本预览最多 120,000 个字符，完整内容可下载；其他文件只提供下载。下载由用户点击触发，不自动打开文件。

附件读取缓存按完整执行身份、附件 ID 和摘要隔离。离线时只有曾在当前浏览器读取并保存的版本可用，界面标明“离线缓存”；未缓存的文件明确不可用。在线读取失败不会把旧缓存当作当前主机确认。上传草稿和读取缓存分别管理，浏览器缓存不构成主机数据备份。
