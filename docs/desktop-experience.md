# 日常 Agent 工作流的体验改进

目标是让用户从输入指令、等待执行、介入任务到审阅结果的完整过程可预期。流式性能已有[独立测量](rendering-performance.md)；本轮重点检查操作是否可发现、反馈是否准确，以及切换、失败与恢复时是否保留用户工作。

## 参考与适配原则

[Claude Code 桌面文档](https://code.claude.com/docs/en/desktop)将输入、停止、运行中补充说明和并排审阅作为常用流程。[Cursor Agent 文档](https://cursor.com/docs/agent/overview)明确区分排队与介入活动任务，并提供会话搜索与结果审阅。这里借鉴的是用户可理解的行为，不直接照搬某个平台的快捷键或权限模式。

Moor 根据当前 Agent 的实际能力开放操作。不能把“已保存草稿”说成“已发送”，不能把不支持的回合内追加伪装为自动重试或新回合。当前文件、已保存的回合变更与 Git 历史仍是不同对象。后台同步不打断阅读，首次加载、手动操作和真实错误仍须有反馈。

## 完整流程与验收要求

| 流程           | 期望行为                                                               | 验证重点                                                     |
| -------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------ |
| 开始和切换会话 | 项目、电脑、Agent 和草稿对应当前会话；切换中不会继续编辑失效的旧上下文 | 首次加载、热缓存、慢缓存、连续导航、保存失败与迟到响应       |
| 输入与上下文   | 中文输入和快捷键不误提交；文本、附件与模型选择可保留，失败能恢复       | IME、换行、粘贴、长草稿、保存中发送、跨会话隔离              |
| 执行与介入     | 明确区分停止、下一条草稿、活动回合追加和显式提交的队列任务             | 真实能力、运行/停止/完成竞争、草稿不自动执行、结果未知不重放 |
| 权限与问答     | 当前待处理事项可发现、可阅读；只响应精确活动请求                       | 折叠工具、长回复、离线缓存、请求替换与回合结束               |
| 阅读与搜索     | 流式更新不抢阅读位置；搜索、复制、展开和回到最新形成闭环               | 长历史、自动跟随、工具内容、搜索跳转、焦点恢复               |
| 文件与代码审阅 | 文件、回合和版本清楚；加载与错误不混淆，聊天输入始终可继续             | 文件切换、历史 diff、选区引用、面板收放、窄屏与键盘          |
| 断线与失败恢复 | 草稿保留；区分本机保存失败、主机离线、未确认操作和执行失败             | 确定性断线/失败、重连、原编号重试、不改变授权或执行范围      |

每个问题先以当前源码和可控场景确认，再修改和补足对应旅程。优先消除输入丢失、错误目标和无法完成的操作，再调整入口与反馈；避免增加长期占据消息空间的按钮。

## 实施与验证

审查覆盖上表所有流程。互不依赖的修复分开处理，涉及会话选择、草稿保存和执行授权的改动必须一起验证其边界。优先复用构建后的客户端与合成 Host/Agent 旅程；精确的延迟、失败和竞争条件使用受控事件验证，不使用真实账号或等待时长猜测就绪。

提交前运行 `pnpm check`、`pnpm test`、`pnpm build`、`pnpm format:check`。界面改动检查实际 Chromium 布局、键盘与焦点；新增源文件检查生产依赖和未使用代码。验收需要说明测试覆盖的路径，源码检查与合成通过不能替代真实 Agent、系统输入法和多设备安装包验收。

## 已完成的行为改进

| 发现的问题                                             | 当前行为                                                                                                                                                              |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 冷缓存切换已改变内部目标，旧输入框却仍可编辑           | 立即发布新会话范围并移除旧编辑器，仅延迟显示加载图标；保存失败留在原会话，快速连续切换拒绝迟到结果。                                                                  |
| 点击发送后等待草稿落盘，期间的新输入可能替换原指令     | 点击时固定正文、模型选择和附件集合；已在写入中的草稿也保留对应版本。后写草稿独立保存，成功清理以原版本为条件。                                                        |
| 本地附件需要先逐个手动上传，才能发送                   | 显式发送先检查主机和 Agent 能力，再按选择顺序上传并发送原内容。添加文件、重连、重试原上传均不自动发送正文；结果未知时保留原操作编号。                                 |
| 运行中主输入框只有停止入口，补充指令需要另开面板并复制 | 支持追加的主机与 Agent 显示“追加”和停止；按钮与 Cmd/Ctrl + Enter 使用同一活动回合校验。追加仅包含文字，模型与权限选择用于下一回合。不支持时保留草稿，结束后手动发送。 |
| 新旧追加入口可能重复，原独立追加草稿可能被清除         | 常规追加使用主输入框；存在独立草稿或待确认操作时保留原面板入口，先处理原草稿。有效送达回执之后的本机清理或同步失败明确标为“已追加”，不当成未发送重放。                |
| 执行电脑离线后，问答或追加弹窗不能编辑、关闭           | 本机草稿仍可编辑与保存；只有提交需要当前且已持久保存的主机状态。保存失败时，弹窗内部提供重新读取入口。                                                                |
| 隐藏的用量/能力事件把同一段 Markdown 截断              | 仅拼接被隐藏元数据分隔的文本，保留首项标识、已完成块 DOM、复制和选区；真实工具、附件与交互继续保持顺序边界。                                                          |
| 停止或失败的回合缺少明确终态                           | 主机已确认的 `canceled` / `failed` 显示“已停止”/“执行失败”；不把 `handled` 当作成功，也不根据未持久保存的视图宣告终态。                                               |
| 刷新文件面板后丢失当前文件或历史 diff 选择             | 重读目录已加载范围并重新验证原文件；历史变更保持冻结基线和所选文件。文件删除、变为目录、超限、版本不匹配或读取失败时不继续引用旧预览。                                |
| 窄窗搜索焦点被抽屉覆盖，输入法 Escape 误关闭界面       | 搜索打开后聚焦搜索框；侧栏、菜单与文件面板遵守输入法组合状态和已处理事件。                                                                                            |
| 窗口获得焦点时，额度后台查询锁住发送、停止和导航       | 查询独立进行，同一会话代次去重；切换会话可开始新查询，旧结果与清理不影响新会话。                                                                                      |

未新增自动排队、自动重发或新的执行授权方式。权限请求仍绑定当前活动回合及精确请求；搜索、历史阅读、返回最新、文件引用与面板焦点继续使用原旅程验证。左侧会话列表在输入与流式正文更新期间保持安静，首次加载、手动刷新和真实错误仍有反馈。

## 验证与边界

2026-09-26 本轮验证通过：`pnpm check`、`pnpm test`（6 条端到端旅程、1,815 项单元及集成测试）、`pnpm build`、`pnpm format:check`、`pnpm knip` 和 `pnpm production:check`。另运行 `check-markdown-memory.mjs`，3,000 段合成输出的解析器保留内存约 0.8MB。

真实 Chromium 旅程覆盖桌面与 390px 窄窗、冷缓存加载、项目添加、当前文件与非首个历史 diff 刷新、原生搜索快捷键、组合输入 Escape，以及运行中追加与停止按钮布局。主输入框旅程检查 IME 不提交、不支持追加时保留草稿、附件与独立草稿阻断、额度查询期间仍可操作，以及发送准备进度。

Host/Controller 的确定性场景使用受控写入和回执，覆盖点击后继续输入、相同正文的后写版本、跨窗口草稿、顺序附件上传、附件集合被其他窗口改变、未知结果、原编号重试、范围切换，以及有效送达后本机写入/清理/同步失败。这些边界不能只由布局截图证明。

本次没有修改增量 Markdown 解析器。元数据分隔文本的回归验证已完成块不重复解析或重建 DOM；单文本路径不增加拼接，含隐藏事件的多文本组在内容变化时仍有拼接成本。解析器的 3,000 段保留内存回归仍在既有上限内。本轮不重新宣称 FPS、CPU 或长跑内存提升，前一轮性能测量的版本和限制见[渲染性能记录](rendering-performance.md)。

验收使用合成 Agent、Host 和隔离客户端资料。真实 Agent 的追加能力、系统输入法的完整按键序列、多设备断线、Relay 长链路和正式安装包仍需实际环境验收。
