# 本机验收场景

这一原型验证“自动准备现场，让用户直接开始试用”。它使用当前构建的真实 Moor 界面，在独立窗口中打开已经准备好的交互页面。准备完成后停止自动操作，由用户接手同一个浏览器页面。

## 启动

安装仓库锁定的依赖后，在项目根目录运行：

```sh
corepack pnpm acceptance
```

命令先执行正常构建，再打开验收窗口。首次缺少 Electron 二进制时，锁定的 Electron 包会下载对应版本；受限文件系统中可先指定可写缓存目录：

```sh
electron_config_cache=/tmp/moor-electron-cache node node_modules/electron/install.js
```

当前使用开发依赖中的 Electron，原型入口不包含在 macOS 安装包或中转服务包中。

## 三个场景

| 场景     | 自动准备                                       | 可以亲手检查                               |
| -------- | ---------------------------------------------- | ------------------------------------------ |
| 窄屏弹窗 | 390 × 740 视口，选中对应会话，打开管理工作区   | 横向布局、纵向滚动、底部“完成”按钮         |
| 设置保存 | 820 × 720 视口，打开管理工作区，填入待保存名称 | 点击保存、刷新后名称保留、重置恢复初始数据 |
| 会话抽屉 | 390 × 740 视口，载入三条合成会话并展开抽屉     | 会话选择、搜索、收起后内容是否对应         |

选择场景本身不执行。点击“准备现场”才开始；准备失败会保留失败阶段和原因，需手动重新准备。就绪只表示浏览器到达指定位置，不表示功能已通过验收，侧栏清单仍需用户检查。

“重置现场”会关闭旧浏览器及服务，创建新的隔离环境，原先的名称修改、输入和会话操作不会带入新一轮。当前窗口使用启动时生成的构建；如果修改了源码，先重新运行构建，再重置，或退出后重新运行 `pnpm acceptance`。

“接受本版”记录当前运行的人工决定。“反馈问题”保存当前场景的文本反馈。两者均绑定运行编号和构建指纹；新一轮不会沿用旧决定。此阶段反馈仅保存在本机验收记录中，尚未接入真实 Agent 的修改循环。

## 执行与数据边界

- 每轮创建临时数据目录和独立浏览器分区，使用合成账号、三个已完成的合成会话及无进程、无外部连接的演示 Agent。预览中主动发送消息只会获得合成回复。
- 预览使用真实 `HostWorkspace`、主机 SQLite、账号/项目目录和现有请求校验。浏览器没有直接写入主机会话的快捷入口。
- 执行主机在准备时复制 `dist/public`，对构建文件计算 SHA-256，再只服务这份副本。构建指纹说明实际展示的界面版本，不代表完整源码或 Git 提交。
- 预览服务仅监听回环地址；浏览器只允许访问当前合成服务。预览页没有工作台的 IPC、Node、外部导航、下载或设备权限。
- 工作台只接受自身主 frame 的限定命令。场景、选择器及浏览器脚本由本地代码定义，渲染端不能传入命令、URL、端口或脚本。
- 停止、重置和退出释放本轮服务及浏览器；晚到的旧准备结果不能覆盖新现场。重新打开工作台不会自动执行任何场景。

终端会输出本次临时目录的位置。目录中的 JSON 记录只包含合成验收信息，供本机查看；原生检查还会在此生成截图。运行服务所用的数据库与构建副本在结束时清理。记录不进入 Git，也不进入发布包。浏览器配置同样位于本次临时目录，不接触日常使用的 Moor 配置。

## 验证

```sh
corepack pnpm check
corepack pnpm test
corepack pnpm build
corepack pnpm format:check
corepack pnpm acceptance:check
```

Node 测试覆盖场景状态竞争、取消与关闭、旧版本反馈拒绝、构建隔离、真实主机请求校验，以及合成工作区保存和重置。原生 Electron 检查使用实际构建页面，验证弹窗、名称保存与刷新、抽屉切换及资源清理，并在临时目录生成截图。等待依赖 DOM/IPC/主机事件，超时仅用于报告失败，不用固定睡眠推进测试。

这是桌面 Chromium 上的本机验证。真实 iPhone Safari、软键盘、触摸手势、远程网络、外部项目、真实 Agent 交付和正式分发仍属于后续里程碑。
